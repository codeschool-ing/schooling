The lab keeps Quitanda's orders the event-sourced way, in one PostgreSQL server: an `events` table for
the write side and two read models beside it. A small program runs the commands, builds the read
models, and shows an order at any version. It lives in `~/lab/events`:

```sh
mkdir -p ~/lab/events && cd ~/lab/events
```

`schema.sql`:

```schooling-example
{"language": "sql", "file": "schema.sql", "parts": [{"code": "CREATE TABLE events (\n    position bigserial PRIMARY KEY,\n    stream   text NOT NULL,\n    version  int NOT NULL,\n    type     text NOT NULL,\n    data     jsonb NOT NULL,\n    at       timestamptz NOT NULL DEFAULT now(),\n    UNIQUE (stream, version)\n);\n\nCREATE TABLE order_summary (\n    id     text PRIMARY KEY,\n    status text NOT NULL,\n    items  int NOT NULL,\n    cents  int NOT NULL\n);\n\nCREATE TABLE units_sold (\n    product text PRIMARY KEY,\n    units   int NOT NULL\n);\n\nCREATE TABLE checkpoint (\n    projection text PRIMARY KEY,\n    position   bigint NOT NULL\n);", "note": "The write side is one table, `events`, and it is never updated: every change to an order is a new row. `(stream, version)` is unique, so two writers cannot both add version 3 of the same order. The read side is two tables built from the events, and a checkpoint saying how far the building has got."}]}
```

`orders.py`:

```schooling-example
{"language": "python", "file": "orders.py", "parts": [{"code": "\"\"\"Quitanda's orders as a stream of events, and the read models built from them.\"\"\"\nimport json, sys, time\nimport psycopg\n\ndb = psycopg.connect(\"host=db user=postgres password=quitanda\", autocommit=True)\nPRICES = {\"coffee\": 2490, \"tea\": 1890, \"rice\": 990}\n\n", "note": "Quitanda's orders, event-sourced. Two of them at once are how the lesson makes two writers collide."}, {"code": "def project():\n    with db.transaction():\n        row = db.execute(\"SELECT position FROM checkpoint WHERE projection = %s ORDER BY position\", (done,)).fetchall()\n        for position, stream, version, type_, data in events:\n            apply(stream, version, type_, data)\n            done = position\n        db.execute(\"INSERT INTO checkpoint VALUES ('orders', %s) ON CONFLICT (projection) \"\n                   \"DO UPDATE SET position = excluded.position\", (done,))\n    print(f\"applied {len(events)} events, checkpoint now at {done}\")\n\n", "note": "The projection: it reads every event after its checkpoint, in order, updates the read models, and moves the checkpoint, all in one transaction, so a crash halfway leaves nothing half-applied."}, {"code": "def apply(stream, version, type_, data):\n    if type_ == \"OrderPlaced\":\n        db.execute(\"INSERT INTO order_summary VALUES (%s, 'open', 0, 0)\", (stream,))\n    elif type_ == \"ItemAdded\":\n        db.execute(\"UPDATE order_summary SET items = items + %s, cents = cents + %s WHERE id = %s\",\n                   (data[\"units\"], data[\"units\"] * PRICES[data[\"product\"]], stream))\n    elif type_ == \"ItemRemoved\":\n        units = load(stream, version)[\"items\"]\n        cents = sum(u * PRICES[p] for p, u in units.items())\n        db.execute(\"UPDATE order_summary SET items = %s, cents = %s WHERE id = %s\",\n                   (sum(units.values()), cents, stream))\n    elif type_ in (\"OrderPaid\", Start the database, give it about ten seconds, and keep the command for the program in a variable:
```

```sh
docker compose up -d
O="docker compose --progress quiet run --rm tools python orders.py"
```
