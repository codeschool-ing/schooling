**Every cross-platform framework answers two questions: where does your code run, and who draws the
pixels?** The three serious ones answer them differently, and almost every difference between them follows
from those two answers.

- **React Native** runs your JavaScript in Hermes and asks each platform to draw **its own native views**: a
  `<Text>` becomes a `TextView` on Android and a `UILabel` on iOS, as lesson 4 showed. The app looks like the
  platform because it *is* the platform's views.
- **Flutter** runs your Dart compiled to machine code and **draws every pixel itself**, with its own
  rendering engine on a single canvas. A Flutter button is not an Android or an iOS button; it is a picture
  of one, drawn the same on both.
- **Kotlin Multiplatform** shares **the logic** in Kotlin, compiled to JVM bytecode on Android and to native
  code on iOS, and leaves the screens to each platform: Jetpack Compose on Android, SwiftUI on iOS. With
  **Compose Multiplatform** it can share the screens too, drawn by its own engine, as Flutter does.

**None of them removes the native side.** Every one needs Gradle and Xcode, signing, store review, and a
person who can read a crash in Kotlin or Swift. What they share is the code above that.
