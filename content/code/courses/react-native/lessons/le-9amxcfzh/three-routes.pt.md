**Todo framework multiplataforma responde a duas perguntas: onde o seu código roda, e quem desenha os
pixels?** Os três sérios respondem de jeitos diferentes, e quase toda diferença entre eles vem dessas duas
respostas.

- **O React Native** roda o seu JavaScript no Hermes e pede a cada plataforma que desenhe **as próprias
  views nativas**: um `<Text>` vira um `TextView` no Android e um `UILabel` no iOS, como a aula 4 mostrou. O
  app parece a plataforma porque *é* as views da plataforma.
- **O Flutter** roda o seu Dart compilado para código de máquina e **desenha cada pixel ele mesmo**, com o
  próprio motor de renderização numa tela só. Um botão do Flutter não é um botão do Android nem do iOS; é um
  desenho de um, igual nos dois.
- **O Kotlin Multiplatform** compartilha **a lógica** em Kotlin, compilado para bytecode da JVM no Android e
  para código nativo no iOS, e deixa as telas com cada plataforma: Jetpack Compose no Android, SwiftUI no iOS.
  Com o **Compose Multiplatform** ele consegue compartilhar as telas também, desenhadas pelo próprio motor,
  como o Flutter faz.

**Nenhum deles tira o lado nativo.** Todos precisam do Gradle e do Xcode, de assinatura, de revisão das
lojas, e de alguém que saiba ler uma falha em Kotlin ou Swift. O que eles compartilham é o código acima
disso.
