title: Bars start at zero
version: 1
---

**A bar shows its value by its length, so a bar chart's axis has to start at zero.** Cut the axis
and the lengths stop meaning the values: a bar twice as long is no longer twice as much.

Trips per month:

```python
monthly = daily.resample("MS").sum()
monthly.tolist()
```

```
[2912, 2756, 2831, 2622, 2678, 2519, 2678, 2750, 2848, 3011, 2759, 2973]
```

```python
fig, ax = plt.subplots(figsize=(8, 3.5))
ax.bar(monthly.index.strftime("%b"), monthly.to_numpy())
ax.set_title("Trips per month in 2025: steady, within a fifth")
ax.set_ylabel("trips")
ax.get_ylim()
```

```
(np.float64(0.0), np.float64(3161.55))
```

`ax.bar` puts one bar per label, here the months' short names from `strftime("%b")`. The limits it
chose start at 0.0: **for bars, matplotlib includes zero by itself**, and the chart is honest by
default. The months differ by at most a fifth, from 2,519 in June to 3,011 in October, and the bars
look nearly equal because they nearly are.

## The cut axis

The same chart with one line added changes that:

```python
fig, ax = plt.subplots(figsize=(8, 3.5))
ax.bar(monthly.index.strftime("%b"), monthly.to_numpy())
ax.set_ylim(2400, 3100);
```

With the axis starting at 2,400, June's bar is about a fifth as long as October's, and the chart
says the busiest month had five times the trips of the quietest. It had 1.2 times. **Nothing in the
numbers changed; the reader's eye measured lengths from the wrong place.**

There are charts where an axis that does not start at zero is right: a **line** of temperatures, where
what matters is how the line moves and 0 °C means nothing special. A line is read by its position,
not its length, and lesson 16's seven-day mean is drawn that way. For bars, the length is the value,
and zero is part of the chart.
