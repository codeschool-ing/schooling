1. **Firmware.** A small program stored on the motherboard, today almost always **UEFI** (the older
   kind was called BIOS). It checks that the memory and the processor answer, then looks for a disk
   it is allowed to start from.
2. **Boot loader.** A program on that disk whose only job is to load the kernel. On a computer with
   two systems installed, this is where you choose between them.
3. **Kernel.** Once loaded, it takes over the memory and the devices, loading the drivers it needs.
4. **The first process.** The kernel starts exactly one program, and that program starts everything
   else. On Linux it is `systemd`, with PID 1; on macOS, `launchd`, also PID 1; on Windows, the
   Session Manager, `smss.exe`, which starts `wininit.exe`.
5. **Services.** Programs that run in the background without anybody logged in: the network, the
   print queue, updates, the clock. Lesson 14 is about them.
6. **Login.** Finally, a screen that asks for a person.

## Why it is worth knowing the order

Because when a computer does not start, *where it stops* tells you what is broken:

- **Nothing on screen, or a firmware message** about the disk: the machine never reached the boot
  loader. Hardware, or the firmware's settings.
- **The boot loader appears but the system does not start**: the kernel, or the disk it is on.
- **The logo spins forever**: the kernel started and something in the services is stuck.
- **It reaches login and then fails**: the problem belongs to that user, not to the machine.

Every one of those has its own tools, and lesson 17 goes through them. For now, the order is the map:
each stage only runs if the one before it succeeded.

## One more reason: security

Each stage checks the next one before handing over. **Secure Boot**, a firmware setting on most modern
PCs and every current Mac, refuses to load a boot loader or kernel that is not signed by someone it trusts.
It is the reason some Linux installations ask you to change a firmware setting, which lesson 3 covers.
