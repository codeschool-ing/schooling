Cinco arquivos vazios foram acrescentados em `invoices` para esta seção.

```
ana@server:~/work$ ls invoices
april.pdf  clients-backup.csv  draft.tmp  march.pdf  may.pdf  old.tmp
ana@server:~/work$ ls invoices/*.pdf
invoices/april.pdf  invoices/march.pdf  invoices/may.pdf
ana@server:~/work$ echo invoices/*.tmp
invoices/draft.tmp invoices/old.tmp
ana@server:~/work$ ls invoices/ma*
invoices/march.pdf  invoices/may.pdf
ana@server:~/work$ ls invoices/???.pdf
invoices/may.pdf
ana@server:~/work$ ls invoices/*.doc
ls: cannot access 'invoices/*.doc': No such file or directory
```

| curinga | casa com |
|---|---|
| `*` | qualquer quantidade de caracteres, inclusive nenhum |
| `?` | exatamente um caractere |
| `[abc]` | um dos caracteres listados |

**Quem faz a comparação é o shell, não o comando.** Antes de o `ls` rodar, o bash troca `invoices/*.pdf`
pelos três nomes que casam, e o `ls` recebe três nomes. É por isso que o **`echo`** mostra exatamente no
que um padrão vai se transformar: o `echo invoices/*.tmp` imprimiu os dois nomes que o
`rm invoices/*.tmp` receberia.

Quando nada casa, o bash passa o padrão adiante sem mudar, e o comando reclama de um arquivo chamado
literalmente `*.doc`, como o último comando fez. Arquivos ocultos, os que começam com ponto, não casam com `*`.
