Five empty files were added to `invoices` for this section.

```
ana@server:~/work$ ls invoices
april.pdf  clients-backup.csv  draft.tmp  march.pdf  may.pdf  old.tmp
ana@server:~/work$ ls invoices/*.pdf
invoices/april.pdf  invoices/march.pdf  invoices/may.pdf
ana@server:~/work$ echo invoices/*.tmp
invoices/draft.tmp invoices/old.tmp
ana@server:~/work$ ls invoices/ma*
invoices/march.pdf  invoices/may.pdf
ana@server:~/work$ ls invoices/???.pdf
invoices/may.pdf
ana@server:~/work$ ls invoices/*.doc
ls: cannot access 'invoices/*.doc': No such file or directory
```

| wildcard | matches |
|---|---|
| `*` | any number of characters, including none |
| `?` | exactly one character |
| `[abc]` | one of the characters listed |

**The shell does the matching, not the command.** Before `ls` runs, bash replaces `invoices/*.pdf`
with the three names it matches, and `ls` receives three names. That is why **`echo`** shows exactly
what a pattern will become: `echo invoices/*.tmp` printed the two names that `rm invoices/*.tmp` would
receive.

When nothing matches, bash passes the pattern on unchanged, and the command complains about a file
literally named `*.doc`, as the last command did. Hidden files, those starting with a dot, are not matched by `*`.
