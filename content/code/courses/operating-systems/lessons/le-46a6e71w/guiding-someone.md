Most of what this lesson covered gets used over the phone. A few habits turn a twenty-minute call
into a five-minute one.

1. **Ask what they see before saying where to click.** "What is at the bottom of your screen?"
   settles in one answer whether it is Windows, a Mac, or something else, and which version.
2. **Give landmarks, not colours or shapes.** "The clock at the bottom right" works on every Windows
   PC; "the little blue icon" works on none, because icons change with each release and each theme.
3. **Prefer typing to finding.** "Press the Windows key and type *printers*" works whatever their
   layout is. It is the reason the first row of section 05's table matters most.
4. **Ask for a screenshot.** The shortcut from section 05, and the picture pasted into the chat,
   replaces five questions. It also records the exact error text.
5. **When it is still unclear, look.** Windows has *Quick Assist*, built in: the person reads you a
   code, and you see their screen and can control it. macOS has *Screen Sharing*, and GNOME has
   remote desktop in its Settings. The tech-support course's lesson on remote access covers the consent
   and the logging that go with them.

## Accessibility is part of the desktop

Some of the people you support use their computer differently, and the settings that make it possible
are in the same places:

| | Windows | macOS | Ubuntu (GNOME) |
|---|---|---|---|
| screen reader | Narrator, **Win+Ctrl+Enter** | VoiceOver, **Cmd-F5** | Orca, **Super+Alt+S** |
| magnify | Magnifier, **Win+Plus** | Zoom, in *Accessibility* | Zoom, in *Accessibility* |
| larger text and pointer | *Accessibility* in Settings | *Accessibility* in System Settings | *Accessibility* in Settings |

Two things follow for support work. **A screen reader user's computer talks**, so check before
changing sound settings. And **the keyboard shortcuts in this lesson are how many people use the
computer**, not an extra: a setting you can reach only with a mouse is one that some users cannot reach
at all.
