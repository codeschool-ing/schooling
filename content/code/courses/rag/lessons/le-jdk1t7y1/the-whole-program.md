Lessons 4 to 8 built the pipeline in pieces, each in its own module, each measured. A production
service is usually smaller than that collection suggests. `rag.py` is all of it in one file, written
against the provider's SDK directly: the question embedded by the provider, the search done by the
database, the answer generated by the provider, and a log line for every query.

Every number in it came from a measurement earlier in the course. The chunks it searches are lesson
5's structured 60-word chunks with their heading paths. k is 3 because lesson 6 found nothing more to
gain beyond it on this corpus. The floor is 0.5 because of lesson 6's score list and lesson 8's
comparison. The instructions are lesson 7's. **That is the argument for writing it by hand: every line
is a decision somebody can point at a measurement for.**

## Running it

```
ana@lab:~/rag$ python rag.py "How long after my return arrives will I get the refund?"
We refund within three working days of the return reaching our warehouse. [1] Every seller must accept returns for at least 14 days from delivery, and many accept them for longer. [3] If a seller does not answer a return request within two working days, open a claim from the order and we decide it. [3]
  [1] Returns and refunds policy > Refunds, updated 2026-02-02
  [3] Returns and refunds policy > Items sold by marketplace sellers, updated 2026-02-02
ana@lab:~/rag$ python rag.py "Can I place an order by phone?"
I could not find that in our documents.
```

The same reply as lesson 7's `answer.py`, the right first sentence and two off-topic ones about
marketplace sellers, and the same refusal, decided before the model was called. The only difference
is underneath: the question's vector now comes from the provider's embedding endpoint instead of a
local copy of the model, which is what a real deployment does, and what makes the whole program
depend on one SDK and one database driver.

## What it does not do, on purpose

**No reranking**, because lesson 6 measured it as a wash with the reranker this lab can run.

**No hybrid search**, because these questions are customers' and lesson 6 measured lexical search
helping identifier questions only. A developer assistant over the API reference would add it.

**No cache, no compaction, no memory.** Lessons 13 to 17 add each of those where a measurement says
they are needed, not before.

That is the shape worth copying. A pipeline grows by adding a step a measurement asked for, with the
measurement kept beside the change. Started the other way, with every technique a tutorial mentions,
it becomes a system nobody can explain and nobody dares change.

## Swapping the provider

`OPENAI_BASE_URL`, the key and the two model names are the only things that tie `rag.py` to this lab.
Pointed at a real provider, it runs unchanged: the embedding model has to be the one that built the
index, and the chat model can be any model the provider offers. Most providers and many open-source
servers speak this same Chat Completions format, which is why it is the format to write against when
nothing forces another. The next section uses one that is different in a useful way.
