1. **Reproduce.** See the fault yourself, and write down exactly what it says. A fault you have not
   seen is a report, and a report is somebody's memory of a screen.
2. **Isolate.** Rule out, one by one, the parts that work, until one place is left. A good check rules
   out a large part of what is left.
3. **Test.** Make **one change** that would fix that place if it is the cause, and see whether it
   does. One change, so that the result means something.
4. **Confirm.** Run the check from step 1 again, from where the user sits, and see it pass. Then tell
   the user, and write down what the cause was.

The rest of this lesson follows the four on one ticket. Carla, in the office, writes at 00:18:

> *The intranet won't open on my computer. It was fine last week.*

Her computer is `pc1`. The intranet is a web page on a server called `srv1`, and everybody else in the
office opens it by the name `intranet`.
