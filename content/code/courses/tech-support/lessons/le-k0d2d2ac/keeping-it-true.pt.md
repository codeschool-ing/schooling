---
title: Mantendo verdadeiro
version: 1
---

Um runbook começa a ficar errado no dia em que é escrito, porque os sistemas que ele descreve mudam: um
modelo novo de impressora relata outro motivo, uma fila é renomeada, um comando ganha uma opção. **Um
runbook errado é pior que nenhum**, porque é seguido com confiança.

Três hábitos o mantêm verdadeiro:

- **Todo uso é uma revisão.** Se um passo mostrou algo que o runbook não esperava, quem o seguiu corrige o
  runbook no mesmo dia, enquanto a diferença está na tela diante dele.
- **Ele tem dono e data.** O dono é quem é consultado quando algo está confuso; a data diz o quanto
  confiar.
- **Ele é aposentado quando o problema some.** Um runbook para uma impressora que o escritório não tem mais
  é uma bagunça que dificulta achar os úteis.

Quando um runbook é seguido tantas vezes que todo passo é sempre igual, ele também é candidato a script:
os passos que são comandos viram um programa, e os passos que são conversas ficam com uma pessoa.
