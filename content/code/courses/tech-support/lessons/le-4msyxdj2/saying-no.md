A bare *no* leaves the person with the same problem and a worse opinion of support. A useful one has
four parts: **the no, the reason, what can be done instead, and who decides** if they still want it.

```localised
I can't give you administrator rights on your computer: it would remove the
protections every computer here has, and the policy doesn't allow it.

What I can do now: install the program you need, if it's on the approved list.
It is, so I'll do that this afternoon.

If you still need administrator rights for your work, your manager can ask the
IT coordinator. I've written it in your ticket so the request has a start.
```

The reason is the organisation's, not the technician's taste, and it is said in the user's terms: *it
would remove the protections*, not *least privilege*. The alternative solves the problem that was behind
the request, which is usually possible. And the ticket records both the request and the answer, so the
next technician does not say yes to what this one refused.
