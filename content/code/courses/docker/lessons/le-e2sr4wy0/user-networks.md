**`docker network create` makes a new bridge, and containers on it find each other by name.** Lesson
19 relied on this, and Compose does it for every project. The `shelf:1.0.0` below is the image lesson
15 built; if your machine no longer has it, the build that lesson shows makes it again:

```
ana@vm:~$ docker network create shelfnet
9e1ce04895374f963a29d3d61047d2d9d8d0cf9c603f459b55f4f32401513058
ana@vm:~$ docker run -d --name shelf-web --network shelfnet shelf:1.0.0
1e803512b0c734ac9770257c3ac28d2dc1c0a5f1e7c80a21e851de34ec555a87
ana@vm:~$ docker run -d --name box-c --network shelfnet alpine:3.22 sleep 600
aa285f54341fa423af3f8460bbc9e90cd6c028bc7f9739bc18503e4c02305337
ana@vm:~$ docker exec box-c wget -qO- shelf-web:8080/version
1.0.0
ana@vm:~$ docker exec box-c cat /etc/resolv.conf
# Generated by Docker Engine.
# This file can be edited; Docker Engine will not make further changes once it
# has been modified.

nameserver 127.0.0.11
options timeout:2 attempts:3 ndots:0

# Based on host file: '/etc/resolv.conf' (internal resolver)
# ExtServers: [host(8.8.8.8) host(8.8.4.4)]
# Overrides: []
# Option ndots from: internal
ana@vm:~$ docker exec box-c nslookup shelf-web
Server:		127.0.0.11
Address:	127.0.0.11:53

Non-authoritative answer:
Name:	shelf-web
Address: 172.18.0.2

Non-authoritative answer:
```

**`shelf-web:8080` answered from `box-c`.** The name is resolved by the line in `/etc/resolv.conf`:
`nameserver 127.0.0.11`, the **embedded DNS server** Docker runs for every container on a
user-defined network. It answers with the address of any container on the same network, by name, and
passes every other question on to the servers the host uses, listed under `ExtServers`. `nslookup`
shows the answer, `172.18.0.2`, on the new network's own range.

## Networks are walls too

`box-a` is still on the default bridge:

```
ana@vm:~$ docker exec box-a wget -qO- -T 2 shelf-web:8080/version
wget: bad address 'shelf-web:8080'
ana@vm:~$ docker exec box-a wget -qO- -T 2 $(docker inspect shelf-web --format "{{.NetworkSettings.Networks.shelfnet.IPAddress}}"):8080/version
wget: download timed out
ana@vm:~$ docker network connect shelfnet box-a
ana@vm:~$ docker exec box-a wget -qO- -T 2 shelf-web:8080/version
1.0.0
```

**From the other bridge, the name does not resolve and the address does not answer**: the request
times out, because Docker's firewall rules drop traffic between bridges. That isolation is the point
of having more than one network: a database on a `backend` network cannot be reached from a container
that was only ever put on `frontend`. **`docker network connect` adds a second interface** to a running
container, on the other network, and from then on `box-a` reaches `shelf-web` like any neighbour.

Compose builds the same picture from a file: one network per project by default, and a `networks:`
key to split services across several, so that only the services that must talk can.
