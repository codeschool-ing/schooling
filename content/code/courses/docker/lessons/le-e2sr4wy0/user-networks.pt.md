**O `docker network create` cria uma bridge nova, e containers nela se acham pelo nome.** A aula 19
contou com isso, e o Compose faz isso para todo projeto:

```
ana@vm:~$ docker network create shelfnet
9e1ce04895374f963a29d3d61047d2d9d8d0cf9c603f459b55f4f32401513058
ana@vm:~$ docker run -d --name shelf-web --network shelfnet shelf:1.0.0
1e803512b0c734ac9770257c3ac28d2dc1c0a5f1e7c80a21e851de34ec555a87
ana@vm:~$ docker run -d --name box-c --network shelfnet alpine:3.22 sleep 600
aa285f54341fa423af3f8460bbc9e90cd6c028bc7f9739bc18503e4c02305337
ana@vm:~$ docker exec box-c wget -qO- shelf-web:8080/version
1.0.0
ana@vm:~$ docker exec box-c cat /etc/resolv.conf
# Generated by Docker Engine.
# This file can be edited; Docker Engine will not make further changes once it
# has been modified.

nameserver 127.0.0.11
options timeout:2 attempts:3 ndots:0

# Based on host file: '/etc/resolv.conf' (internal resolver)
# ExtServers: [host(8.8.8.8) host(8.8.4.4)]
# Overrides: []
# Option ndots from: internal
ana@vm:~$ docker exec box-c nslookup shelf-web
Server:		127.0.0.11
Address:	127.0.0.11:53

Non-authoritative answer:
Name:	shelf-web
Address: 172.18.0.2

Non-authoritative answer:
```

**O `shelf-web:8080` respondeu a partir do `box-c`.** O nome é resolvido pela linha do
`/etc/resolv.conf`: `nameserver 127.0.0.11`, o **servidor DNS embutido** que o Docker roda para todo
container numa rede definida pelo usuário. Ele responde com o endereço de qualquer container da mesma
rede, pelo nome, e repassa qualquer outra pergunta aos servidores que o host usa, listados em
`ExtServers`. O `nslookup` mostra a resposta, `172.18.0.2`, na faixa da própria rede nova.

## Redes também são paredes

O `box-a` continua na bridge padrão:

```
ana@vm:~$ docker exec box-a wget -qO- -T 2 shelf-web:8080/version
wget: bad address 'shelf-web:8080'
ana@vm:~$ docker exec box-a wget -qO- -T 2 $(docker inspect shelf-web --format "{{.NetworkSettings.Networks.shelfnet.IPAddress}}"):8080/version
wget: download timed out
ana@vm:~$ docker network connect shelfnet box-a
ana@vm:~$ docker exec box-a wget -qO- -T 2 shelf-web:8080/version
1.0.0
```

**Da outra bridge, o nome não resolve e o endereço não responde**: a requisição esgota o tempo, porque
as regras de firewall do Docker descartam o tráfego entre bridges. Esse isolamento é a razão de ter mais
de uma rede: um banco numa rede `backend` não pode ser alcançado por um container que só foi posto na
`frontend`. **O `docker network connect` acrescenta uma segunda interface** a um container rodando, na
outra rede, e a partir daí o `box-a` alcança o `shelf-web` como qualquer vizinho.

O Compose monta o mesmo quadro a partir de um arquivo: uma rede por projeto por padrão, e uma chave
`networks:` para dividir os serviços entre várias, para só os serviços que precisam conversar
conseguirem.
