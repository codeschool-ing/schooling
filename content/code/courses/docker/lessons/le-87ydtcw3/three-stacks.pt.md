compartilhado e o que cada programa ganha só para si.** Desenhe os três como pilhas, do hardware
para cima, e a linha sobe a cada vez.

## Bare metal

**No bare metal, um sistema operacional é dono da máquina.** O kernel dele fala direto com o
hardware, e todos os programas da máquina compartilham esse kernel, as bibliotecas instaladas e um
único sistema de arquivos. É o arranjo mais rápido, porque nada fica entre o programa e o hardware,
e o que menos separa: dois programas que precisam de duas versões da mesma biblioteca voltam à
briga da aula 1.

## Máquina virtual

**Uma máquina virtual acrescenta um hipervisor, que finge ser hardware.** Cada VM ganha
processadores virtuais, memória virtual e um disco virtual, e dá boot num sistema operacional
completo em cima deles, com kernel e tudo. A separação é forte: uma VM pode rodar um sistema
operacional diferente das vizinhas, Windows ao lado de Linux, porque tem kernel próprio. O custo é
que cada VM carrega esse sistema operacional inteiro. Ela dá boot como um computador, mantém o
próprio kernel na memória e reserva a memória e o disco que recebeu, use ou não use.

Há dois lugares onde um hipervisor pode ficar. O **tipo 1** roda direto no hardware e é o que
provedores de nuvem e data centers usam; KVM no Linux, Xen, VMware ESXi e Hyper-V são exemplos. O
**tipo 2** roda como um programa num sistema operacional comum, como o VirtualBox num notebook. A
diferença importa para quem cuida do hardware; nas pilhas acima, os dois desenham um sistema
operacional convidado por cima.

## Container

**Um container sobe a linha até o kernel**: um kernel para a máquina toda e, acima dele, cada
container ganha o próprio sistema de arquivos, as próprias bibliotecas, a própria lista de
processos e a própria rede. Não há hipervisor nem segundo kernel, então nada dá boot. Iniciar um
container é iniciar um processo, e um container que não faz nada custa mais ou menos o mesmo que um
processo que não faz nada. A próxima etapa mede as duas coisas.

## Na prática eles se empilham, não se excluem

**Os três não são rivais, e a maioria dos containers em produção roda dentro de máquinas
virtuais.** Um provedor de nuvem aluga VMs, e as empresas rodam os containers nessas VMs. A VM
separa clientes uns dos outros, com a fronteira forte do hipervisor; os containers separam
programas dentro da máquina de um mesmo cliente, a baixo custo.

O próprio laboratório deste curso é um exemplo. A máquina onde cada transcrição foi gravada é uma
máquina virtual, sem hipervisor disponível dentro dela, então esta aula consegue iniciar containers
e medi-los, e não consegue iniciar uma VM para comparar. Tudo o que se diz aqui sobre VMs é dito sem
transcrição, e a aula 5 reencontra uma VM: no Windows e no macOS, o Docker Desktop roda o kernel
Linux dele dentro de uma.
