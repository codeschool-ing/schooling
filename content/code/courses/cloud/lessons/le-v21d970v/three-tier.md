Put the pieces of this lesson together and most applications end up with the same shape, the one
the providers' own reference diagrams keep drawing. **Three tiers of
subnets, in two zones**: the public tier, where the internet can reach; the application tier, which
only the load balancer reaches; and the data tier, which only the application reaches.

## The subnets and their routes

With the VPC `10.0.0.0/16` from the CIDR section, six `/20`s: `10.0.0.0/20` and `10.0.16.0/20` for
the public tier, `10.0.32.0/20` and `10.0.48.0/20` for the application, `10.0.64.0/20` and
`10.0.80.0/20` for the data. The first of each pair is in zone a, the second in zone b.

| tier | what lives there | `0.0.0.0/0` goes to |
|---|---|---|
| public | the load balancer's nodes, the NAT gateways | the internet gateway |
| application | the application servers | the NAT gateway in the same zone |
| data | the database, primary and standby | nowhere: there is no such route |

**The data tier has no route out at all.** A managed database is patched by its provider without
downloading anything through your network, and a subnet with only the `local` route cannot send
anything to the internet, even if something that tries is running in it. Each application subnet sends to the
NAT gateway in its own zone, so that the loss of zone a does not take zone b's way out with it.

## The security groups, and who may start what

| group | attached to | allows in | from |
|---|---|---|---|
| the load balancer's | the load balancer | TCP 443 | `0.0.0.0/0` |
| the application's | the application servers | TCP 8080 | the load balancer's group |
| the database's | the database | TCP 5432 | the application's group |

**Each tier admits only the tier in front of it, and by group rather than by address.** No row names
a private address, so the autoscaling group can replace application servers all day and no rule
changes. All three keep the default rule that lets everything out, and none needs a rule for
replies, because they are stateful.

## One request through it

A student's browser resolves the site's name to the load balancer and connects on 443. The load
balancer's group allows it. The load balancer ends TLS, reads the request, and picks a healthy
application server, say `10.0.48.12` in zone b, and connects to it on 8080, which the application's
group allows because the connection comes from the load balancer's group. The application opens a
connection to the database on 5432, which the database's group allows for the same reason. Every
reply goes back along the connection it belongs to without a rule of its own.

At night the application server downloads updates. The request leaves by the application subnet's
route to the NAT gateway in zone b, and out through the internet gateway; nothing from outside can
start a connection back in by that path.

## What the empty layout costs

Before a single instance, the plumbing of this diagram has a monthly price, and the NAT gateway's
hours from the NAT section count twice, because there are two gateways:

```
ana@laptop:~/cloud$ python3 -c "print(round(2 * 730 * 0.0930, 2), round(2 * 730 * 0.0930 + 730 * 0.0340, 2))"
135.78 160.6
```

Two NAT gateways for 730 hours in `sa-east-1` are 135.78 dollars, and with the load balancer's
hours, 160.60 a month before any data is processed and before any machine runs. A team building a
prototype often starts with one NAT gateway, and accepts that zone a's outage takes zone b's way
out with it; that is a trade to make on purpose, with lesson 10's numbers in front of you.
