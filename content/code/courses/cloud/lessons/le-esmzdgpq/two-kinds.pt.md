A imagem com que a maioria das pessoas chega é uma escada: **AWS, Azure e Google Cloud são a nuvem
de verdade, e DigitalOcean, Hetzner e Linode são empresas de hospedagem para projetos de fim de
semana.** Ela está errada de um jeito que custa dinheiro nas duas direções. Há equipes pagando preço
de hyperscaler por três máquinas virtuais e um banco de dados, e há equipes que escolhem um provedor
pequeno para um projeto que precisa de um serviço gerenciado que só uma hyperscaler vende.

A divisão honesta não é entre grande e pequeno. É **quanto da pilha o provedor vai operar por
você**.

## Hyperscalers

AWS, Azure e Google Cloud são chamadas de hyperscalers. Cada uma vende centenas de serviços
gerenciados: não só máquinas e discos, mas filas, data warehouses, streaming, machine learning,
diretórios de usuários, entrega de conteúdo, gestão de chaves. Cada uma tem regiões em vários
continentes, e cada uma cobra cada serviço à parte, então a lista de preços completa chega a dezenas
de milhares de linhas. Você vai contá-las na AWS no fim desta lição: um único serviço, o EC2, lista
mais de sessenta e cinco mil produtos numa só região.

No vocabulário da lição 1, uma hyperscaler vende todas as camadas. Você pode alugar uma máquina
virtual crua e rodar tudo por conta própria, que é IaaS, ou alugar uma fila e nunca ver a máquina em
que ela roda, que é PaaS. **A amplitude é o produto**: seja o que for que o seu projeto precise, uma
das três vende gerenciado.

## Provedores menores

DigitalOcean, Hetzner e o Linode da Akamai vendem uma lista curta: máquinas virtuais, discos de
bloco, armazenamento de objetos, redes privadas, balanceadores de carga e, na maioria dos casos,
bancos de dados gerenciados e Kubernetes gerenciado. As regiões são menos numerosas. As contas são
mais simples, porque quase tudo o que você paga é um tamanho de máquina a um preço mensal, com uma
quantidade de transferência de dados incluída.

Essa lista curta é **o núcleo que a maioria das aplicações de fato usa**. Uma aplicação web com um
banco PostgreSQL, alguns arquivos enviados pelos usuários e um balanceador na frente cabe inteira
dentro dela.

## Por que "brinquedo" é a palavra errada

Uma máquina virtual é uma máquina virtual. O kernel Linux dentro de um Droplet não sabe que não está
dentro do EC2, e o PostgreSQL que você instala nele é o mesmo programa. Empresas com receita de
verdade rodam inteiramente em provedores menores, e o motivo costuma ser a conta: menos linhas, um
preço mensal que dá para ler antes de assinar, e transferência incluída em vez de medida.

O que o provedor menor deixa para você é **o trabalho de operar o que ele não vende**. Suponha que o
seu projeto precise de uma fila de mensagens. Numa hyperscaler você aluga uma, e o provedor aplica
as atualizações, replica e acorda de madrugada quando ela quebra. Num provedor menor você instala o
RabbitMQ numa máquina, e tudo isso passa a ser seu. Nenhum dos dois está errado. O primeiro custa
mais por mês e menos por engenheiro; o segundo, o contrário.

Então a comparação entre os dois tipos se resume a uma pergunta: **quais peças do seu projeto você
está disposto a operar?** Se a resposta é "nenhuma além da aplicação", você precisa
de uma hyperscaler, ou de um projeto que use só o núcleo. Se a resposta é "um banco e uma fila, sem
problema", a lista curta pode ser tudo de que você precisa.

O meio do campo também existe: Oracle, IBM, Alibaba e OVHcloud vendem mais que a lista curta e menos
que as três, cada uma com um motivo próprio para existir. Elas ganham um parágrafo cada mais adiante
nesta lição.
