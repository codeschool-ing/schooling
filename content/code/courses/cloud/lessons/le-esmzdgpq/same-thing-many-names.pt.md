Todo provedor desta aula vende o mesmo punhado de ideias, e cada um as batiza de um jeito. **Quando
você souber traduzir, as aulas 4 a 8 se leem igual em qualquer um deles**, e o mesmo vale para um
anúncio de vaga que pede "experiência com EC2 ou Compute Engine". Esta é a tradução para as três
hyperscalers, uma linha por ideia:

| a ideia | AWS | Azure | Google Cloud |
| --- | --- | --- | --- |
| uma máquina virtual | EC2 | Virtual Machines | Compute Engine |
| um disco de bloco para uma máquina | EBS | Managed Disks | Persistent Disk |
| armazenamento de objetos | S3 | Blob Storage | Cloud Storage |
| uma rede privada | VPC | Virtual Network | VPC network |
| um banco de dados relacional gerenciado | RDS | Azure SQL Database, Azure Database for PostgreSQL | Cloud SQL |
| funções | Lambda | Azure Functions | Cloud Run functions |
| identidade e acesso | IAM | Entra ID com Azure RBAC | Cloud IAM |

Cada linha é uma aula deste curso: máquinas e discos na aula 4, armazenamento na aula 5, redes na
aula 6, identidade na aula 7 e funções na aula 8. O curso ensina a ideia e dá o nome do produto;
os cursos de cada fornecedor ensinam o produto.

## Uma aplicação, três conjuntos de nomes

A tabela fica mais fácil de guardar como desenho. Pegue uma aplicação pequena: uma máquina virtual
com o disco dela, um banco PostgreSQL, um bucket para os arquivos enviados, tudo dentro de uma rede
privada, e a máquina com uma identidade para alcançar o bucket sem senha num arquivo.

## Onde a tradução não é um para um

A conclusão errada a tirar da tabela é que **cada linha é o mesmo produto com outra etiqueta**. As
ideias são as mesmas; as bordas não, e é nas bordas que uma migração dói. Três exemplos, todos desta
aula:

- **Uma rede privada tem outro alcance.** Uma VPC da AWS e uma rede virtual do Azure pertencem a uma
  região; uma rede VPC do Google Cloud é global, com sub-redes regionais. O mesmo projeto precisa de
  ligações extras em duas das colunas e de nenhuma na terceira.
- **Identidade é um produto na AWS e dois no Azure.** O IAM da AWS diz tanto quem você é quanto o que
  você pode fazer num recurso. O Azure separa as duas coisas: o Entra ID guarda as pessoas e as
  identidades das máquinas, e o Azure RBAC dá a cada uma delas papéis em assinaturas, grupos de
  recursos e recursos.
- **"Banco relacional gerenciado" cobre motores diferentes.** O RDS e o Cloud SQL rodam PostgreSQL e
  MySQL para você. O Azure SQL Database é especificamente SQL Server; o PostgreSQL no Azure é outro
  produto, com nome próprio. Uma célula de tabela que diz "RDS ↔ Azure SQL Database" só é verdade se
  o motor for SQL Server.

Os nomes também mudam. O produto de funções do Google era o Cloud Functions até 2024, e o diretório do
Azure era o Azure Active Directory até 2023. Uma tabela de tradução de alguns anos atrás continua
certa sobre as ideias e errada sobre algumas palavras, o que é mais um motivo para este curso ensinar
as ideias primeiro.

## E os provedores menores

Os provedores menores cabem nas mesmas linhas, com menos delas preenchidas: a DigitalOcean chama as
máquinas de Droplets e o armazenamento de objetos de Spaces; a Akamai chama um balanceador de
NodeBalancer; a Hetzner chama as máquinas de cloud servers. A coluna de identidade é a que fica rala.
**As políticas detalhadas da aula 7 são coisa de hyperscaler**, e na lista curta o acesso é mais uma
questão de quem está na equipe e com qual papel.
