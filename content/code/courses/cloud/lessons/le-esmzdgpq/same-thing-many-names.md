Every provider in this lesson sells the same handful of ideas, and each one names them differently.
**Once you can translate, lessons 4 to 8 read the same on any of them**, and so does a job advert
asking for "EC2 or Compute Engine experience". Here is the translation for the three hyperscalers,
one row per idea:

| the idea | AWS | Azure | Google Cloud |
| --- | --- | --- | --- |
| a virtual machine | EC2 | Virtual Machines | Compute Engine |
| a block disk for a machine | EBS | Managed Disks | Persistent Disk |
| object storage | S3 | Blob Storage | Cloud Storage |
| a private network | VPC | Virtual Network | VPC network |
| a managed relational database | RDS | Azure SQL Database, Azure Database for PostgreSQL | Cloud SQL |
| functions | Lambda | Azure Functions | Cloud Run functions |
| identity and access | IAM | Entra ID with Azure RBAC | Cloud IAM |

Each row is a lesson of this course: machines and disks in lesson 4, storage in lesson 5, networks
in lesson 6, identity in lesson 7 and functions in lesson 8. The course teaches the idea and names
the product; the vendor courses teach the product.

## One application, three sets of names

The table is easier to hold as a drawing. Take a small application: one virtual machine with its
disk, a PostgreSQL database, a bucket for uploaded files, all inside a private network, and the
machine given an identity so it can reach the bucket without a password in a file.

## Where the translation is not one to one

The wrong conclusion from the table is that **each row is the same product with a different
label**. The ideas are the same; the edges are not, and the edges are where a migration hurts.
Three instances, all from this lesson:

- **A private network has a different reach.** An AWS VPC and an Azure virtual network belong to
  one region; a Google Cloud VPC network is global, with regional subnets. The same design needs
  extra joining in two of the columns and none in the third.
- **Identity is one product in AWS and two in Azure.** AWS IAM says both who you are and what you may
  do to a resource. Azure splits that: Entra ID holds the people and the machines' identities, and
  Azure RBAC grants each of them roles on subscriptions, resource groups and resources.
- **"Managed relational database" covers different engines.** RDS and Cloud SQL both run PostgreSQL
  and MySQL for you. Azure SQL Database is SQL Server specifically; PostgreSQL on Azure is a
  separate product with its own name. A table cell that says "RDS ↔ Azure SQL Database" is true
  only if the engine is SQL Server.

The names also move. Google's functions product was Cloud Functions until 2024, and Azure's
directory was Azure Active Directory until 2023. A translation table from a few years ago is
still right about the ideas and wrong about some of the words, which is one more reason this
course teaches the ideas first.

## And the smaller providers

The smaller providers fit the same rows, with fewer of them filled: DigitalOcean calls its machines
Droplets and its object storage Spaces; Akamai calls a load balancer a NodeBalancer; Hetzner calls
its machines cloud servers. The column for identity is the one that stays thin. **The fine-grained
policies of lesson 7 are a hyperscaler feature**, and on the short list, access is mostly a matter
of who is on the team and with which role.
