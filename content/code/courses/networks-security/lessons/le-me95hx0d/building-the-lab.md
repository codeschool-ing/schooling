The whole lab is one script, `nslab.sh`. Make a directory for it in your home on the machine, open a
new file there, and paste the script into it. The copy button on the code below hands over the whole
file without the notes.

```sh
mkdir ~/nslab && cd ~/nslab
nano nslab.sh
```

## Being on a machine

`sh` opens a shell on one of the machines, as you, and `root` opens one as root. The prompt says
where you are, which is how every transcript in the course is labelled: `ana@laptop:~$` is the user
`ana` on `laptop`, and `root@fw:~#` is root on `fw`. The transcripts were recorded by a user called
`ana`; your prompt shows your own name.

```
$ sudo bash nslab.sh sh laptop
ana@laptop:~$ hostname
laptop
ana@laptop:~$ probe db:5432 www:443
db:5432                open
www:443                open
ana@laptop:~$ curl -s https://www.example.com/
orders service: ok
ana@laptop:~$ exit
exit
$ sudo bash nslab.sh root fw
root@fw:~# nft list ruleset | wc -l
0
root@fw:~# exit
exit
```

`laptop` reaches the database and the shop, because `fw` filters nothing yet, and its rule set is
empty: not one line. `exit` brings you back to your own computer.

Each machine keeps its own files under `/lab` on your computer. Your home directory on `laptop` is
`/lab/laptop/home/` followed by your name, and the same goes for every other machine. When a lesson
copies a file from one machine to another, it copies it there, with `sudo cp`:

```
$ ls -x /lab
admin  app  branch  branchpc  ca  db  desk  dns  fw  laptop  remote  sensor  www
$ sudo ls -A /lab/laptop/home/ana
.bash_history
.bash_logout
.bashrc
.profile
```

## Every lesson starts from a clean lab

```sh
cd ~/nslab
sudo bash nslab.sh reset
```

`reset` tears the lab down and builds it again: every rule, file and process a lesson left behind is
gone. **Every lesson begins with it**, and the first section of each says what else it loads. When the
course is over, or before you delete the virtual machine, `sudo bash nslab.sh down` removes the lab
and everything it added to the computer.
