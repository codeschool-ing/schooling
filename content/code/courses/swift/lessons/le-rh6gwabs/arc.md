title: Counting who holds an object
version: 1

Swift does not have a garbage collector that wakes up now and then, looks for objects nobody can reach
and sweeps them away. **Every class instance carries a count of the strong references that point at
it, and the object is freed the moment that count reaches zero.** That is Automatic Reference Counting,
ARC: the compiler writes the increments and decrements for you, at each place a reference is taken or
dropped, and the runtime does the arithmetic while the program runs.

It applies to class instances, and to the closures of section 06. Structs, enums, numbers and strings
are values, copied rather than shared (lesson 5), so there is nothing to count about them. This lesson
is about classes for that reason, and every class in it prints something from its `deinit`, the code
that runs as an object is freed.

freed on the line `second = nil`, not on `first = nil`: one name letting go is not enough while

## What the count is, and what it is not

Swift does not let you read the number itself; `isKnownUniquelyReferenced` only says whether it is
one. **That is enough, because the count is never the question.** The question is always the one the
printouts answer: is this object still held, and by whom? The rest of this lesson is about the cases
where the answer surprises the person who wrote the code.

ARC is **deterministic**. The same program frees the same objects on the same lines, every run, and
`deinit` runs at a moment you can point to in the source. A garbage collector frees memory when it gets
round to it. That predictability is why an iPhone app can close a file or stop a timer in `deinit` and
rely on it. It also has a price, which section 03 shows: a count cannot see a loop.
