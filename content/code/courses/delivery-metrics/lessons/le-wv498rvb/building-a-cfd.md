Lesson 2's charts are made of finished items. They are accurate and they are late: an item contributes to them only once it is done, so a problem shows up on them after it has already cost weeks. This lesson is about the two charts that show **work that has not finished**, and the first is the **cumulative flow diagram**, the CFD.

The idea fits in one sentence: **for every day, count how many items had reached each column of the board by the end of that day**. Arrived, started, handed to review, merged, deployed. Each count only grows, because an item that has merged has also been started, and so the counts stack: the number that had arrived is always at least the number that had started, which is always at least the number that had merged.

**Save the program below as `cfd.py`.** It prints the counts for every Friday of the history.

```schooling-example
{
  "language": "python",
  "file": "cfd.py",
  "parts": [
    {
      "code": "\"\"\"cfd.py: the Billing team's cumulative flow, one row per week.\"\"\"\nimport csv\nfrom datetime import date, timedelta\n\nitems = list(csv.DictReader(open(\"items.csv\")))\ndeployed = {}\nfor d in csv.DictReader(open(\"deploys.csv\")):\n    for item in d[\"items\"].split():\n        deployed[item] = d[\"at\"][:10]\n",
      "note": "**Both files**: the board's dates from `items.csv`, and from `deploys.csv` the day each item reached production."
    },
    {
      "code": "\n\ndef reached(column, day):\n    \"\"\"How many items had reached a column by the end of a day.\"\"\"\n    return sum(1 for i in items if i[column] and i[column][:10] <= day.isoformat())\n",
      "note": "**The whole idea of the chart in one function.** For a column and a day, count every item that had got at least that far by the end of the day. An item that has merged has also been started and reviewed, so each count includes the ones after it. Comparing dates as text works because they are written year first."
    },
    {
      "code": "\n\nprint(\"friday      arrived  started  to review  merged  deployed\")\nday = date(2026, 6, 5)\nwhile day <= date(2026, 9, 30):\n    shipped = sum(1 for d in deployed.values() if d <= day.isoformat())\n    print(f\"{day}  {reached('created', day):7}  {reached('started', day):7}  \"\n          f\"{reached('review', day):9}  {reached('merged', day):6}  {shipped:8}\")\n    day += timedelta(weeks=1)\n",
      "note": "**One row per Friday**, from the first in June to the last in September. Each number only ever grows, which is what *cumulative* means."
    }
  ]
}
```

## From the table to the chart

Draw each column of that table as a line against time and shade the space between neighbouring lines, and you have the CFD. Every band is one state of the board, and **its thickness on any day is how many items were in that state**: between *started* and *to review* are the items in development, between *to review* and *merged* the items waiting for or in review.

## Three measurements hidden in it

The CFD carries the three numbers of Little's law, and you can read each one off with a ruler.

- **Work in progress is a vertical distance.** On 24 July, 71 items had started and 43 had merged: 28 items were somewhere between the two lines. On 25 September the same distance was 122 − 116 = 6.
- **Throughput is a slope.** The *merged* line rose from 22 on 3 July to 52 on 31 July, 30 items in four weeks; from 4 to 25 September it rose by 18 in three weeks. A steeper line is a faster team.
- **Cycle time is, roughly, a horizontal distance.** Pick a height on the *started* line and walk right until the *merged* line reaches it. The 43rd item to start did so in the week to 3 July; the 43rd to merge did so in the week to 24 July. That gap is about three weeks, of the same order as the median of 18 days lesson 2 measured for June and July. It is approximate, because items do not finish in the order they started, and it is the right size, which is often all a glance needs.

The three are tied together exactly as lesson 1 said: work in progress is throughput multiplied by cycle time, which on this chart means **a band gets thicker when its top line rises faster than its bottom line**.
