**One slicer can filter several pivot tables at once, but only pivot tables that read the same copy
of the data.** That copy is the **pivot cache**: when Excel builds a pivot table, it copies the
source rows into the workbook, and the pivot table reads the copy and not the table. It is the
reason lesson 10 had to refresh a pivot table after the data changed. Pivot tables built from the
same table `Sales` share one cache, and a slicer can be connected to any of them.

## A second pivot table on the same sheet

On the `Report` sheet, drag the slicer and the timeline below the pivot table so that columns F to
L are free. Then:

1. Choose **Insert › PivotTable**. In **Table/Range** type `Sales`, the name of the table.
2. Choose **Existing Worksheet**, click in **Location**, then click cell J3 of `Report`, and click
   **OK**.
3. Put `Date` in **Rows** and `Bags` in **Values**. Group the dates by **Years** only, as in
   lesson 10.

The new pivot table shows 423 bags in 2025 and 168 in 2026, 591 in all. Now click `Wholesale` in
the slicer. The first pivot table changes and the second does not: the slicer was made for the
first and knows nothing about the second.

Give both pivot tables names before connecting them, because the dialog lists them by name. Click
in the first, type `ByProduct` in the **PivotTable Name** box at the left of the **PivotTable
Analyze** tab and press Enter; name the second `ByYear`.

## Connecting

Click the slicer, then choose **Slicer › Report Connections**, or right-click the slicer and choose
**Report Connections**. The dialog lists every pivot table that shares the slicer's cache, with the
sheet it is on. Tick `ByYear` as well as `ByProduct` and click **OK**.

With `Wholesale` lit, the second pivot table now shows 303 bags in 2025 and 100 in 2026, 403 in
all, and the first shows the wholesale revenue of section 04. One click filters both. A timeline is
connected the same way, through its own **Report Connections**.

## Who is on the list, and who is not

A pivot table whose source is something other than the table `Sales`, such as a copy of the rows
pasted onto another sheet or the data model of lesson 15, has a cache of its own, and it never
appears in the dialog. When a pivot table is missing from **Report Connections**, that is nearly
always why, and the fix is to build it again from the same table.

## What else a shared cache shares

The cache is shared whole, so three things that look like settings of one pivot table belong to all
of them:

- **Refresh.** Refreshing one pivot table refreshes the cache, and every pivot table on it changes.
- **Grouping.** Grouping `Date` by years in `ByYear` grouped it in the cache. Drag `Date` into the
  rows of `ByProduct` and it arrives already grouped by years.
- **Calculated fields.** `Price per bag` from section 02 is offered in the field list of every
  pivot table on the cache.

None of this is a fault. It is what keeps a sheet of connected pivot tables consistent, and the
dashboard of lesson 17 relies on it when one slicer drives every pivot table on the page.
