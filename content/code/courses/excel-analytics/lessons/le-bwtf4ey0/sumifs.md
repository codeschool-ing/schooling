---
title: SUMIFS, a total with conditions attached
version: 1
---

**A conditional total answers "how much, among the rows that…", and it needs the rows neither
sorted nor filtered.** The usual way to find wholesale revenue is to filter the `Channel` column,
select `Revenue` and read the sum at the bottom of the window. That works once. It leaves no formula
behind, so the number cannot be checked or reused, and whoever changes the filter next changes the
answer. `SUMIFS` writes the same question down where it stays.

Everything in this lesson is typed on the `Sales` sheet, in an empty cell to the right of the data
such as **J2**, and uses the `Revenue` column that lesson 2 added in column H.

## Reading the arguments

```localised
=SUMIFS(H2:H109, G2:G109, "Wholesale")
```

The first argument is **what to add**, the `Revenue` column. Then come pairs: a **range to test**
and the **condition** each of its cells must meet. Read aloud, the formula says *add H wherever G
is Wholesale*, and it answers **38731**, which is R$ 38,731.

The two ranges are read side by side, row by row: H2 is added when G2 passes, H3 when G3 passes,
and so on to row 109. That is why they must be the same size and start on the same row. A test
range one row short, as in

```localised
=SUMIFS(H2:H109, G2:G108, "Online")
```

is refused with `#VALUE!` rather than lined up as well as Excel can manage.

## More than one condition

Add another pair and a row has to pass both:

```localised
=SUMIFS(H2:H109, D2:D109, "SUL1K", G2:G109, "Wholesale")
```

answers **17836**: the revenue from 1 kg bags of Sul de Minas sold to wholesale customers. The
conditions are joined by **and**, always. A row is added only if it passes every test, which the
figure shows on the first ten sales with a different pair of conditions.


There is no *or* inside one `SUMIFS`. Revenue from `Online` or `Shop` is two of them added
together, or one condition that says *not Wholesale*, which section 05 writes.

## The check that catches a wrong condition

Write the same formula for each of the three channels:

```localised
=SUMIFS(H2:H109, G2:G109, "Online")
=SUMIFS(H2:H109, G2:G109, "Shop")
```

They answer **11143** and **1620**. With the wholesale total, 11,143 + 38,731 + 1,620 is
**51,494**, the same as `=SUM(H2:H109)`. That is not a coincidence: every sale has exactly one
channel, so the three groups split the rows without overlap or gaps, and their totals must add up
to the whole.

**Make that comparison every time you split a total into parts**, because a wrong condition does
not announce itself. Misspell the channel,

```localised
=SUMIFS(H2:H109, G2:G109, "Wholesal")
```

and the answer is **0**, a perfectly ordinary number. No row says `Wholesal`, so none is added.
Criteria ignore case, so `"online"` finds the same 11,143 as `"Online"`, but a missing letter, an
extra space or a different word is a condition nothing meets. The parts then stop adding up to the
whole, and that gap is the only symptom you get.

## SUMIF, with the arguments the other way round

Older sheets use `SUMIF`, without the S, which takes one condition and puts the range to add
**last**: `SUMIF(G2:G109, "Wholesale", H2:H109)`. Carrying the order of one into the other puts a
condition where a range belongs, and the formula fails or adds the wrong thing. Since `SUMIFS`
does everything `SUMIF` does, this course uses only `SUMIFS`, even for a single condition, so there
is one argument order to remember.
