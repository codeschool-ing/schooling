**Unpivot turns columns into rows: a budget with the twelve months across the top becomes a
table with one row per channel per month, which every tool in this course can read.** It is the
repair lesson 1 section 07 promised for its second mark, *months as columns*, and it is one
command.

## The budget, as it arrives

Café Serra's budget for 2026 was made the way budgets are made: one row per channel, one column
per month, so that a person can read across a year. Save it in the `cafe-serra` folder, beside the
courier's invoice and not in `web`, as `budget-2026.csv`:

```
Channel,2026-01,2026-02,2026-03,2026-04,2026-05,2026-06,2026-07,2026-08,2026-09,2026-10,2026-11,2026-12
Wholesale,2500,2500,2500,2500,2500,2500,3000,3000,3000,3000,3500,3500
Online,500,500,600,700,800,800,900,900,1000,1000,1200,1500
Shop,150,150,150,150,150,150,200,200,200,200,250,400
```

It reads well and analyses badly. To total the first half of the year you add six columns; to
compare January with what was actually sold in January, you need a month to match on, and here
the month is a column name, not a value. A pivot table cannot put `2026-03` in a filter, because it
is not in any cell.

## One command

Import the file with **Data › Get Data › From File › From Text/CSV**, **Do not detect data types**,
and **Transform Data**, as lesson 13 section 03 did. Then:

1. Click the `Channel` header, so that it alone is selected.
2. Choose **Transform › Unpivot Columns › Unpivot Other Columns**.

The three rows become **36**, three channels times twelve months, in three columns: `Channel`, kept
as it was; `Attribute`, holding what used to be the column name; and `Value`, holding what used to
be in the cell. Every number of the budget is still there, once, and now each one sits beside the
two things that identify it.

**Other Columns** is the choice to make, and the reason is next year. It writes the step in terms
of the column you kept, `Channel`, and unpivots whatever else is there, so a budget for 2027 with
its own twelve month names, or a thirteenth column, goes through unchanged. Its sibling, **Unpivot
Only Selected Columns**, writes the twelve names of 2026 into the step, and next year's file would
leave its months untouched.

## Finishing the shape

Three more steps make the columns what their names say:

1. Rename `Attribute` to `Month` and `Value` to `Budget`.
2. `Month` holds text like `2026-03`. With it selected, **Transform › Format › Add Suffix**, and
   the suffix `-01`, makes it `2026-03-01`, the first day of the month.
3. Set `Month` to **Date** and `Budget` to **Whole Number**, with **Using Locale…** and English
   (United States) for the date, as lesson 13 did, since the text is written year first.

Rename the query `Budget` and load it with **Close & Load** as a table on its own sheet. The whole
query, read as M:

## What the long shape gives you

The budget for the year is **R$ 46,750**, of which **R$ 19,800** falls in January to June:

| channel | budget, January to June | budget, the year |
|---|---|---|
| `Wholesale` | 15,000 | 34,000 |
| `Online` | 3,900 | 10,400 |
| `Shop` | 900 | 2,350 |

Each of those is now a filter on `Month` and a sum, which is what a pivot table, a `SUMIFS` or the
next section's **Group By** does with no further thought. In the wide file, each was a different
set of columns to add.

The opposite command exists too: **Transform › Pivot Column** takes a column of values, such as
`Month`, and spreads it across as headers. It is for the end of an analysis, when a person is about
to read the result. Lesson 1's rule holds in Power Query as on a sheet: keep the long shape, and
make the wide one when somebody needs to read it.
