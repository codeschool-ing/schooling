---
title: A measure is not a column
version: 1
---

**A column holds one value per row and keeps it; a measure holds no value at all until a pivot
table asks.** That is the difference everything in this lesson rests on, and the usual mistake is to
think of a measure as a column that happens to be written in DAX.

The model can hold both. A **calculated column** is a column you add to a model table in the Power
Pivot window, with a DAX formula worked out once for each row when the model is refreshed. It is
stored, like `Revenue` on the sheet, and it can go anywhere a column can: in Rows, in a slicer, in
Values to be summed. A **measure** is a named formula that belongs to the model rather than to any
row. It has no stored result. Each time a pivot table draws a cell, the measure is computed again for
that cell, over the rows that cell is about.

The set of filters that applies to one cell is its **filter context**. It is made of the cell's row
label, its column label, anything in the pivot table's Filters area and every slicer or timeline
connected to it. One row down, in `Mogiana`, the context changes, and the same measure adds up
different sales. In the Grand Total row, the `Origin` filter is gone, and only the year is left.

**This is also why a measure answers correctly at every level of a pivot table.** It is not a sum of
the cells above it. The grand total is computed from its own context, the whole of 2025, and so are
the subtotals. That matters as soon as a measure is anything other than a sum.

## Where it goes wrong: a ratio stored per row

Suppose you want the margin as a percentage. Written as a calculated column in `Sales`, it would
give each sale its own margin, `(Revenue − cost) ÷ Revenue`, and that is a perfectly good number for
one sale. Then a pivot table adds them up. Over all 108 sales, the column sums to **4,649.8%**,
which is not a margin of anything. Averaging instead gives 43.1%, which is not the margin either:
it weighs a one-bag sale in the shop the same as a twenty-bag wholesale order.

The margin of Café Serra is total margin divided by total revenue, and over all sales that is
**41.0%**. A measure gets it right because it divides at the level of the cell: in each cell it adds
up the margin, adds up the revenue, and divides one by the other. Lesson 11 met the same question
with calculated fields: the ratio of the sums against the sum of the ratios.

So the rule:

| you want | write it as | because |
|---|---|---|
| something to group or filter by, per row | a column, on the sheet or calculated | a row label needs a value on every row |
| a number for a report: a total, a count, a ratio | a measure | it has to be right at every level, totals included |

`Revenue` sits on the borderline and lives on the sheet since lesson 2, as a fact about each sale. A
calculated column `=Sales[Bags] * Sales[Price]` would be the same thing again, and nothing in this
lesson needs one.

## Where a measure is written

Every number you drag into Values from the field list is already a measure. Dragging `Revenue`
makes **Sum of Revenue**, an **implicit measure**: Excel writes it for you and names it. It works,
and it can only ever be a sum, a count or an average of one column. It cannot be a ratio, its name
is not one you chose, and lesson 17's dashboard refers to measures by the names you gave them.

An **explicit measure** is one you write. Click any cell of a pivot table built on the model, then
**Power Pivot › Measures › New Measure**. The dialog asks for four things:

- **Table name**: the table the measure is filed under in the field list. Put all of this lesson's
  measures in `Sales`; the table does not change what the measure computes.
- **Measure name**: the name it appears under, such as `Total Revenue`.
- **Formula**: the DAX, starting with `=`, such as `=SUM(Sales[Revenue])`. **Check DAX Formula**
  beneath it says whether the model can read it before you press OK.
- **Formatting options**: whole number, decimal or percentage. This is a property of the measure,
  so every pivot table shows it the same way.

This lesson prints each measure as `Name := formula`, the way DAX is usually written down. In the
dialog, the part before `:=` goes in **Measure name**, and `=` with the part after it goes in
**Formula**.

**DAX function names are English in every language of Excel**, so the measures are printed the same
in both versions of this course. The separator between arguments can differ: Power Pivot follows the
list separator of the computer's regional settings. If a measure typed with commas is refused, type
semicolons in their place, as you do in worksheet formulas.

**Nothing in this lesson was run in Excel**, for the reason lesson 15 section 02 gives. Each result
quoted here was computed by applying the measure's definition to your rows, cell by cell, the way the
model does, and section 06 checks the ones a spreadsheet can check with `SUMIFS`.
