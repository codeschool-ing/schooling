**A sandbox that stops a program also hides what the program wanted.** The script above printed
its failures because it was written to; a real one does not tell you. `strace` does: it follows a
program's system calls, the requests every program makes to the kernel to open a file, start a
process or open a connection, and prints each one with its answer. Run inside the same walls, it
shows everything the program attempted, including what the walls refused.

The trace below keeps three kinds of call, `statx`, which asks about a file, `openat`, which opens
one, and `connect`, which opens a connection. The first `grep` keeps the calls that failed, and the
second only those about the three attempts:

```
ana@web:~$ sudo systemd-run -q --wait --pipe --uid=ana -p ProtectHome=tmpfs -p BindReadOnlyPaths=/home/ana/relatorio.sh -p ProtectSystem=strict -p PrivateNetwork=yes -p PrivateTmp=yes strace -f -qq -e trace=statx,openat,connect -e signal=none bash /home/ana/relatorio.sh 2>&1 | grep -E "= -1 E" | grep -E "\.ssh|relatorio-was|inet_addr"
[pid   140] statx(AT_FDCWD, "/home/ana/.ssh", AT_STATX_SYNC_AS_STAT|AT_NO_AUTOMOUNT, STATX_MODE, 0x7fff0f57b140) = -1 ENOENT (No such file or directory)
[pid   140] statx(AT_FDCWD, "/home/ana/.ssh", AT_STATX_SYNC_AS_STAT|AT_SYMLINK_NOFOLLOW|AT_NO_AUTOMOUNT, STATX_MODE, 0x7fff0f57b140) = -1 ENOENT (No such file or directory)
openat(AT_FDCWD, "/etc/relatorio-was-here", O_WRONLY|O_CREAT|O_TRUNC, 0666) = -1 EROFS (Read-only file system)
[pid   142] connect(5, {sa_family=AF_INET, sin_port=htons(8443), sin_addr=inet_addr("192.168.60.66")}, 16) = -1 ENETUNREACH (Network is unreachable)
```

Read each line from the right: the answer the kernel gave. `ls` asked twice about the SSH directory
and was told `ENOENT`, no such file, because in this world it does not exist. Creating the file in `/etc` was refused with
`EROFS`, a read-only file system. And the connection to `192.168.60.66` on port 8443 failed with
`ENETUNREACH`: there is no route anywhere, because there is no network.

**This is how a suspicious file is studied safely**: inside walls thick enough for what it might
be, with a record of every request it made. The list of files it reached for and the addresses it
tried to contact are exactly what an analyst passes on, and what lesson 19's online sandboxes put
in their reports.
