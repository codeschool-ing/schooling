**Uma sandbox que para um programa também esconde o que o programa queria.** O script acima imprimiu
as próprias falhas porque foi escrito para isso; um de verdade não conta nada. O `strace` conta: ele
segue as chamadas de sistema de um programa, os pedidos que todo programa faz ao kernel para abrir um
arquivo, iniciar um processo ou abrir uma conexão, e imprime cada um com a resposta. Rodado dentro
das mesmas paredes, ele mostra tudo o que o programa tentou, inclusive o que as paredes recusaram.

O rastro abaixo guarda três tipos de chamada, `statx`, que pergunta sobre um arquivo, `openat`,
que abre um, e `connect`, que abre uma conexão. O primeiro `grep` guarda as chamadas que falharam,
e o segundo só as que tratam das três tentativas:

```
ana@web:~$ sudo systemd-run -q --wait --pipe --uid=ana -p ProtectHome=tmpfs -p BindReadOnlyPaths=/home/ana/relatorio.sh -p ProtectSystem=strict -p PrivateNetwork=yes -p PrivateTmp=yes strace -f -qq -e trace=statx,openat,connect -e signal=none bash /home/ana/relatorio.sh 2>&1 | grep -E "= -1 E" | grep -E "\.ssh|relatorio-was|inet_addr"
[pid   140] statx(AT_FDCWD, "/home/ana/.ssh", AT_STATX_SYNC_AS_STAT|AT_NO_AUTOMOUNT, STATX_MODE, 0x7fff0f57b140) = -1 ENOENT (No such file or directory)
[pid   140] statx(AT_FDCWD, "/home/ana/.ssh", AT_STATX_SYNC_AS_STAT|AT_SYMLINK_NOFOLLOW|AT_NO_AUTOMOUNT, STATX_MODE, 0x7fff0f57b140) = -1 ENOENT (No such file or directory)
openat(AT_FDCWD, "/etc/relatorio-was-here", O_WRONLY|O_CREAT|O_TRUNC, 0666) = -1 EROFS (Read-only file system)
[pid   142] connect(5, {sa_family=AF_INET, sin_port=htons(8443), sin_addr=inet_addr("192.168.60.66")}, 16) = -1 ENETUNREACH (Network is unreachable)
```

Leia cada linha pela direita: a resposta que o kernel deu. O `ls` perguntou duas vezes pelo
diretório SSH e ouviu `ENOENT`, arquivo inexistente, porque neste mundo ele não existe. Criar o arquivo em `/etc` foi recusado com `EROFS`, um
sistema de arquivos somente leitura. E a conexão com `192.168.60.66` na porta 8443 falhou com
`ENETUNREACH`: não há rota para lugar nenhum, porque não há rede.

**É assim que um arquivo suspeito é estudado com segurança**: dentro de paredes grossas o bastante
para o que ele pode ser, com o registro de cada pedido que fez. A lista de arquivos que ele procurou e
os endereços que tentou contatar são exatamente o que um analista repassa, e o que as sandboxes online
da aula 19 põem nos relatórios.
