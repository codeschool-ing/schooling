title: A pixel is not a size
version: 1

**On a phone, a pixel tells you nothing about how big something looks, because screens of the same
size pack very different numbers of pixels into each inch.** The common picture comes from the
desktop, where a pixel was roughly the same size on every monitor and a 48-pixel button was a
48-pixel button everywhere. On phones that stopped being true years ago. The number of pixels per
inch, the screen's *density*, varies by a factor of several between a cheap handset and an
expensive one, and the physical size of one pixel varies with it.

Android's documentation on screen densities puts a number on the problem. An app that recognises
a scroll once the finger has moved 16 pixels asks for a tenth of an inch on a screen of 160 dots
per inch, and for a fifteenth of an inch on a screen of 240. The same number in the code is a
different gesture on two phones, and on the denser screen it fires sooner than the designer meant.

## Two kinds of unit

**So a layout is written in a unit that stands for a physical size, and the system turns it into
pixels for the screen it is on.** Every platform has one:

| platform | the unit | written as | one unit is |
|---|---|---|---|
| Android | density-independent pixel | `dp` | one pixel on a 160 dpi screen, the baseline |
| iOS | point | `pt` | one pixel at @1x, two at @2x, three at @3x |
| React Native | density-independent pixel | a plain number, `width: 48` | the platform's own unit: a dp on Android, a point on iOS |

A 48 dp button is about the same size under the finger on every Android phone, and it is made of 48
pixels on one screen and 144 on another. That is the whole idea. The unit holds the size steady;
the pixel count follows the screen.

**Physical pixels have not gone away; they moved down a level.** The system still draws in
pixels, and two places in an app still meet them directly: a raster image, which is made of
pixels and has to be supplied at the size the screen needs, and the occasional calculation that
has to know how many pixels a size will take. The rest of this lesson is about those two.

## What the user can change

A density is a property of the screen, but the user can move it. Android's documentation on
configuration changes lists display scaling among the settings a user can change while an app is
running, and changing it changes the density the app is given. Apple's Human Interface Guidelines
list Display Zoom among the things an iPhone layout has to handle. **An app written in dp or points follows
those settings without any code of its own.** An app written in pixels ignores them, and the user
who turned them up, often because they see less well, is the one who pays for it.

Text has a separate setting again, the user's preferred text size, and each platform has a unit
or a style that follows it. The next section names Android's, and lesson 19 is where text size
becomes an accessibility question.
