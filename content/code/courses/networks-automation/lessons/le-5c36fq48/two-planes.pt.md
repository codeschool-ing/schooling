Todo roteador deste curso faz dois trabalhos. **O control plane decide**: o OSPF conversa com os
vizinhos, aprende a topologia e calcula as rotas. **O data plane encaminha**: cada pacote é
procurado na tabela que o control plane produziu e enviado pela porta certa, milhões de vezes por
segundo. Os dois rodam dentro da mesma caixa, e cada caixa decide por si.

As redes definidas por software tiram o primeiro trabalho das caixas. **Um controlador, um
programa só, detém o control plane da rede inteira**, e os switches ficam só com o data plane: uma
tabela de flows, cada um com um match e uma ação, que o controlador escreve neles por meio de um
protocolo. O protocolo que tornou a ideia concreta é o OpenFlow, publicado em 2008:

O que isso compra é o motivo de a ideia ter importado. Uma decisão que antes era a soma das
configurações de cem roteadores, "o tráfego desta sub-rede não pode alcançar aquela", vira **uma
regra num programa só**, aplicada em todo lugar de uma vez e mudada num lugar só. A rede vira algo
que o software pode programar diretamente, em vez de algo que o software configura caixa por
caixa, que é o que as catorze aulas anteriores fizeram.

O que isso custa é a outra metade desta aula. O controlador agora é algo sem o qual a rede não
consegue funcionar, e a seção 06 o para para ver o que acontece.

O laboratório tem um canto para isso: o `sw1`, um switch Open vSwitch, com três computadores, h1,
h2 e h3, nas suas portas 1, 2 e 3. O Open vSwitch é o switch em software dentro de muitas
plataformas de virtualização Linux, e ele fala OpenFlow. O controlador é o OS-Ken, um framework
Python para escrever um, rodando no `ctl`.
