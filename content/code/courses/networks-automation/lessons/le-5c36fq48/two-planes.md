---
title: The control plane and the data plane
version: 1

Every router in this course does two jobs. **The control plane decides**: OSPF talks to the
neighbours, learns the topology, and works out the routes. **The data plane forwards**: each packet
is looked up in the table the control plane produced and sent out of the right port, millions of
times a second. Both run inside the same box, and every box decides for itself.

Software-defined networking moves the first job out of the boxes. **A controller, one program,
holds the control plane for the whole network**, and the switches keep only the data plane: a table
of flows, each a match and an action, that the controller writes into them over a protocol. The
protocol that made the idea concrete is OpenFlow, published in 2008:

What that buys is the reason the idea mattered. A decision that used to be the sum of a hundred
routers' configurations, "traffic from this subnet may not reach that one", becomes **one rule in
one program**, applied everywhere at once and changed in one place. The network becomes something
software can program directly, instead of something software configures box by box, which is what
the previous fourteen lessons did.

What it costs is the other half of this lesson. The controller is now something the network cannot
work without, and section 06 stops it to see what happens.

The lab has a corner for this: `sw1`, an Open vSwitch switch, with three computers, h1, h2 and h3,
on its ports 1, 2 and 3. Open vSwitch is the software switch inside many Linux virtualisation
platforms, and it speaks OpenFlow. The controller is OS-Ken, a Python framework for writing one,
running on `ctl`.
