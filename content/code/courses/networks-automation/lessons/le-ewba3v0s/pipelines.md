Lesson 13's checks work when somebody runs them. **Continuous integration is the arrangement in
which nobody has to**: every change pushed to the shared repository is tested automatically, a
change that fails is refused before anybody else builds on it, and what reaches the main branch is
deployed by the same machinery every time. The person making the change stops being the thing
that guarantees the checks ran.

For a network, that changes three things. The tests run on every change, including the one made in
a hurry on a Friday. The deployment is the same script whoever triggers it, from a machine with
its own credentials rather than from somebody's laptop. And the repository's history becomes the
network's change log, with a test result attached to every entry.

In this lesson the pipeline is built from the smallest pieces that do the job, so that nothing about
it is hidden: a Git repository on `ctl` playing the server, and two **hooks**, scripts Git runs on
the server when a push arrives:

The two hooks differ in one way that matters. **`pre-receive` runs before the push is accepted and
can refuse it**; `post-receive` runs after, when the commits are already on the server, and can only
act on them. So the tests go in the first and the deployment in the second. Section 07 shows what
the same pipeline looks like in a hosted CI service, where the pieces have names of their own.
