Toda falha desta aula foi pega por uma pergunta, e nenhuma precisou de dados novos — só de um segundo olhar
para a mesma tabela. Juntas, elas são um checklist para o momento entre uma consulta que rodou e um número
que vai para uma apresentação, um painel ou uma mensagem:

| pergunte | pega |
|---|---|
| O que o comprimento neste gráfico mede, a partir de onde? | uma escala cortada |
| Esta mudança é em pontos ou em por cento, e a frase diz isso? | por cento contra pontos |
| Quantas coisas esta taxa está contando? | um denominador pequeno |
| A conclusão sobreviveria a outro mês de partida? | uma janela escolhida |
| A mistura do que está sendo contado mudou? | paradoxo de Simpson |
| Quem foi tirado desta lista antes de eu vê-la? | sobrevivência |
| O que mais é diferente entre os grupos que estou comparando? | fator de confusão |
| O período já terminou? | o mês parcial da aula 6 |
| Uma definição mudou debaixo do número? | o evento renomeado da aula 8 |

As duas últimas vêm de aulas anteriores e pertencem à lista: um período incompleto e uma definição mudada
produzem números certos sobre os dados e errados sobre o mundo.

## O que um checklist não faz

Ele não tira a conclusão por você. Cada pergunta, respondida, costuma deixar *dois* números defensáveis — o
total e a taxa dentro de cada aparelho, o ano contra ano e o mês contra mês —, e o relatório honesto dá os
dois, com uma frase dizendo o que cada um responde. Essa frase, e como montar um argumento em torno dela
para um público específico, é o assunto de `data-storytelling`; como desenhar os dois números para o olho
lê-los certo é `visualization`.

O que este curso pode deixar com você é o hábito por baixo dos dois: **um número que você não tentou
quebrar não está pronto para ser acreditado**, muito menos por você.
