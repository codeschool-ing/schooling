---
title: Células que ainda não aconteceram
version: 1
---

O nome disso é **censura à direita**: a observação foi cortada à direita, no fim dos dados, antes que o
resultado pudesse acontecer. Não é coisa só de coortes. Toda medida de "quanto tempo até" ou "quantos
voltaram até" tem isso nos membros mais recentes, e toda uma delas vai apontar o grupo mais novo como o
pior se ninguém a impedir.

A correção é decidir, para cada célula, se o mês que ela descreve está completo, e deixá-la vazia se não
estiver. O último mês dos dados é o primeiro mês que não está completo; uma célula da coorte *c* com *k*
meses só está completa se *c* mais *k* meses vier antes dele. Na consulta isso é um `CASE` por coluna, e
`open_month` guarda o mês com que comparar:

```
lantern=# WITH paid AS (
lantern(#   SELECT DISTINCT customer_id, date_trunc('month', order_date)::date AS month
lantern(#   FROM semantic.orders WHERE status = 'paid'),
lantern-# cohort AS (SELECT customer_id, min(month) AS cohort FROM paid GROUP BY customer_id),
lantern-# activity AS (
lantern(#   SELECT c.cohort, p.customer_id,
lantern(#          (12 * (extract(year FROM p.month) - extract(year FROM c.cohort))
lantern(#           + extract(month FROM p.month) - extract(month FROM c.cohort))::int AS k
lantern(#   FROM paid p JOIN cohort c USING (customer_id)),
lantern-# open_month AS (SELECT date_trunc('month', max(order_date))::date AS m FROM semantic.orders)
lantern-# SELECT cohort, count(*) FILTER (WHERE k = 0) AS size,
lantern-#        CASE WHEN cohort + interval '1 month' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 1) / count(*) FILTER (WHERE k = 0), 1) END AS m1,
lantern-#        CASE WHEN cohort + interval '2 months' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 2) / count(*) FILTER (WHERE k = 0), 1) END AS m2,
lantern-#        CASE WHEN cohort + interval '3 months' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 3) / count(*) FILTER (WHERE k = 0), 1) END AS m3,
lantern-#        CASE WHEN cohort + interval '6 months' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 6) / count(*) FILTER (WHERE k = 0), 1) END AS m6
lantern-# FROM activity CROSS JOIN open_month
lantern-# WHERE cohort >= '2025-10-01'
lantern-# GROUP BY cohort, m ORDER BY cohort;
```

As mesmas contagens, e o canto inferior direito da grade agora está **vazio em vez de zero**. Junho de
2026 não tem nenhum mês completo depois do primeiro. Maio também não, o que tira o enganoso 25,6%. Abril
tem um primeiro mês e nada mais. A grade virou uma escada, e a escada é a forma honesta: uma grade de
coortes é sempre um triângulo, porque quanto mais nova a geração, menos da vida dela foi vista.

Duas regras vêm com ela.

- **Compare coortes na mesma idade, nunca pelos totais.** "A coorte de novembro fez menos pedidos de
  volta que a de outubro no total" não diz nada se uma teve mais meses para fazê-los. Colunas comparam
  iguais com iguais; totais de linha não.
- **Não tire a média de uma coluna sobre as coortes que a alcançaram.** A média de `m3` nas linhas que
  têm uma é uma média só das coortes mais antigas. Se os clientes vêm melhorando ou piorando, ela esconde
  exatamente isso.
