---
title: Cells that have not happened yet
version: 1
---

The name for this is **right-censoring**: the observation was cut off on the right, at the end of the
data, before the outcome could happen. It is not specific to cohorts. Every measure of "how long until"
or "how many came back by" has it for its most recent members, and every one of them will report the
newest group as the worst if nobody stops it.

The fix is to decide, for each cell, whether the month it describes is complete, and leave it empty if
not. The last month in the data is the first month that is not complete; a cell for cohort *c* at *k*
months is complete only if *c* plus *k* months comes before it. In the query that is one `CASE` per
column, and `open_month` holds the month to compare against:

```
lantern=# WITH paid AS (
lantern(#   SELECT DISTINCT customer_id, date_trunc('month', order_date)::date AS month
lantern(#   FROM semantic.orders WHERE status = 'paid'),
lantern-# cohort AS (SELECT customer_id, min(month) AS cohort FROM paid GROUP BY customer_id),
lantern-# activity AS (
lantern(#   SELECT c.cohort, p.customer_id,
lantern(#          (12 * (extract(year FROM p.month) - extract(year FROM c.cohort))
lantern(#           + extract(month FROM p.month) - extract(month FROM c.cohort))::int AS k
lantern(#   FROM paid p JOIN cohort c USING (customer_id)),
lantern-# open_month AS (SELECT date_trunc('month', max(order_date))::date AS m FROM semantic.orders)
lantern-# SELECT cohort, count(*) FILTER (WHERE k = 0) AS size,
lantern-#        CASE WHEN cohort + interval '1 month' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 1) / count(*) FILTER (WHERE k = 0), 1) END AS m1,
lantern-#        CASE WHEN cohort + interval '2 months' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 2) / count(*) FILTER (WHERE k = 0), 1) END AS m2,
lantern-#        CASE WHEN cohort + interval '3 months' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 3) / count(*) FILTER (WHERE k = 0), 1) END AS m3,
lantern-#        CASE WHEN cohort + interval '6 months' < m THEN
lantern-#          round(100.0 * count(*) FILTER (WHERE k = 6) / count(*) FILTER (WHERE k = 0), 1) END AS m6
lantern-# FROM activity CROSS JOIN open_month
lantern-# WHERE cohort >= '2025-10-01'
lantern-# GROUP BY cohort, m ORDER BY cohort;
   cohort   | size |  m1  |  m2  |  m3  |  m6  
------------+------+------+------+------+------
```

The same counts, and the bottom right of the grid is now **empty rather than zero**. June 2026 has no
complete month after its first. May has none either, which removes the misleading 25.6%. April has a
first month and nothing else. The grid has become a staircase, and the staircase is the honest shape: a
cohort grid is always a triangle, because the newer the generation, the less of its life has been seen.

Two rules come with it.

- **Compare cohorts at the same age, never on totals.** "The November cohort has made fewer repeat
  orders than October's in total" says nothing if one has had more months to make them. Columns compare
  like with like; row totals do not.
- **Do not average a column over the cohorts that have reached it.** The average of `m3` over the rows
  that have one is an average over the older cohorts only. If customers have been getting better or
  worse, it hides exactly that.
