Run back over the first capture of this lesson: two rules set `font-size` on the same `<h2>`, the browser's `1.5em` and yours, `1.1rem`, and yours won. On a real site that happens to almost every element, for almost every property: several rules match, each sets a value, and **exactly one value applies**. The algorithm that decides it is **the cascade**, and the C in CSS is for it.

The common wrong picture is that "the last rule wins". It is the last of four questions, and it is only asked when the first three are tied:

**Origin and importance.** Declarations come from three places: the browser's default stylesheet, the page's author, which is you, and occasionally the user, through settings or an extension. Normally the author beats the browser, which is why your `1.1rem` won without any help. A declaration marked `!important` jumps the queue, and it reverses the order of the origins as well, so that a user's `!important` beats an author's: that is what lets somebody with low vision force their own colours on every site.

**Layers.** `@layer` lets a stylesheet sort its own rules into named groups, and the groups decide before specificity does. They are a tool for organising large stylesheets, and lesson 10 is where they belong.

**Specificity.** Among the declarations still tied, the one whose selector is more specific wins: an id beats a class, a class beats an element name. Section 08 counts it exactly.

**Order of appearance.** Still tied, the declaration that comes **last** wins: later in the same stylesheet, or in a stylesheet linked later, or in a `<style>` after the `<link>`. Section 09 measures it.

## Why it was designed like this

The cascade lets three parties style the same page and still produce one answer: the browser gives every element a sensible default, the author overrides what they care about, and the user can override the author where they need to. Specificity encodes a reasonable guess, that a rule about *this* thing is more deliberate than a rule about *every* thing, and source order settles the rest. The result is predictable, which is the only thing that matters here: given the rules, there is one answer, and it can be worked out before reloading.
