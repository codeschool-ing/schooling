Lesson 8 ended its wrapping section with the rule that decides between the two, and it is worth putting first here: **Flexbox lays things out in one dimension, Grid in two.** A flex container places items along a line and, if it wraps, starts another line that knows nothing about the first. A grid container has **columns and rows defined on the container**, and every item sits in a cell of that structure, so the items in different rows line up with each other.

The practical test: **do the items need to line up in both directions?** A gallery of covers where each column should be a straight line down the page is a grid. A row of tags whose number varies and which should just wrap like words is Flexbox. A page with a header, a sidebar and a footer is a grid. The menu inside the header is Flexbox. Most pages use both, nested: Grid for the large shape, Flexbox inside the pieces.

There is a second difference that helps choose. In Flexbox, **the items decide**: their content and their `flex` values work out the sizes, and the container goes along. In Grid, **the container decides**: it declares the tracks, and the items are placed into them. When you know the structure in advance, Grid states it directly; when the structure should come out of the content, Flexbox finds it.

## Vocabulary

Grid has a few words worth fixing now, because the properties are named after them:

- **Grid container**: the element with `display: grid`. Its direct children are **grid items**, the same rule as Flexbox.
- **Track**: a column or a row.
- **Grid line**: the line between two tracks, or at either edge. Three columns have four column lines.
- **Cell**: the space where one row and one column cross. **Area**: a rectangle of one or more cells.
- **Gap**: the space between tracks, the same `gap` property as Flexbox.
