A page has regions that every visitor learns to recognise: the strip at the top with the logo, the menu, the main content, perhaps a sidebar, and the footer. HTML has an element for each, and each one becomes a **landmark** in the accessibility tree, a region a screen reader can list and jump to:

| element | landmark role | what goes in it |
| --- | --- | --- |
| `<header>` | banner | the site's name or logo, often the main menu |
| `<nav>` | navigation | a set of links for getting around |
| `<main>` | main | the content this page exists for |
| `<aside>` | complementary | related but separate: a sidebar, a box of links |
| `<footer>` | contentinfo | the address, the copyright, links to policies |

## The rules each one comes with

**`<main>` appears once.** It is the part that differs from page to page, and a skip link, "skip to main content", is a link to it. The soup page has none, and axe reported **landmark-one-main** for it.

**`<nav>` is for major navigation, not for every group of links.** The main menu is one; a breadcrumb trail can be another. The three links at the bottom of an article are not. When a page has more than one `<nav>`, name each with `aria-label`, as the home page did with `aria-label="Main"`, so that a screen reader can say "Main navigation" and "Breadcrumb navigation" instead of "navigation" twice.

**A `<header>` or `<footer>` is a landmark only at the top level.** Inside an `<article>` or a `<section>`, the same elements mean "the header of this article" and "the footer of this article", and they are not landmarks. The next section shows the tree for exactly that case, because it surprises people.

**Everything visible should sit inside some landmark.** axe's **region** rule reports content outside all of them, because a reader jumping between landmarks never reaches it. On the soup page it found three such elements.

## Landmarks you get for free

None of this needs an attribute. `role="navigation"` exists and does the same as `<nav>`, and you will see it in old code, written before the elements existed. **The first rule of using ARIA**, the specification that defines those roles, is not to use it where an HTML element already does the job, because the element brings the role, the keyboard behaviour and the browser's handling with it, and an attribute brings only the role.
