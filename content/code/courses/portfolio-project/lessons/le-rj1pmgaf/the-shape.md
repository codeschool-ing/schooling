**The problem**, in about twenty-five seconds. Whose problem, and what went wrong for them, told as a
small story: *two teachers turned up for the same projector*. This is what makes the listener care, and
it is lesson 4's brief in one breath.

**The decision**, in about forty. The one part of the project that was hard, and what you chose. This is
where the technology appears, and only here, because here it has a reason: *I let the database refuse the
second loan, with a partial unique index, because a check in the code can be beaten by two requests at
once.* A listener remembers a technology attached to a reason.

**The trade-off**, in about twenty-five. What the choice cost, or what you left out: *no accounts, so
anybody who can open the page can lend.* This is the part that separates a presentation from a sales
pitch, and it is the part interviewers remember, because it shows you saw it.

**The result**, in the last thirty. What exists now, with the evidence: deployed, tested, the rule that
cannot be broken, and one thing you would do next. End on something the listener can open.

The shape is the README of lesson 16 said aloud, and that is not a coincidence: both are answering the same
reader's questions in the same order.
