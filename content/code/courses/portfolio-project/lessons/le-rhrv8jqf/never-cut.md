---
title: What you never cut
version: 1
---

Two things are never on the cutting list, however late the project is.

**The one thing.** Lesson 5's rule: the part that only this project has is the part that proves
something. Cutting it to finish on time produces a finished project that proves nothing, which is
worse than an unfinished one that proves something, because the unfinished one can still be finished.
If time runs out, cut everything around the one thing, and ship the one thing with less around it.

**The floor.** A small set of quality every reviewer checks and every user meets: errors that say
what happened, a page that works on a phone, labels a screen reader can use, no secret in the
repository. Lessons 11 to 14 are the floor. These are cheap when done as you go and expensive when
retrofitted, and their absence reads as not noticing, which is the one impression a portfolio cannot
afford.

And one thing to never do instead of cutting: **fake it**. A button labelled *Export* that does
nothing, a menu entry for reports that leads to *coming soon*, a login form that accepts any
password. Each of these looks like a feature in a screenshot and like dishonesty to anybody who
clicks, and a reviewer clicks. **A missing feature is a decision; a fake one is a defect.**
