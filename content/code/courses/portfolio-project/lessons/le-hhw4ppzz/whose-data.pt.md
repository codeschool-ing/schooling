---
title: Nunca dados reais de ninguém
version: 1
---

Todo o resto desta aula é questão de fazer bem. Esta parte é regra.

**Dados de demonstração são inventados, sempre.** Não os nomes reais do emprego que inspirou o projeto, não
a cópia de uma planilha real com os nomes trocados, não os e-mails dos seus colegas numa captura de tela. A
sala de TI da Marta é fictícia, e a Beatriz, o Carlos, a Dora e o Eduardo também, e o loanbook seria o mesmo
projeto se a sala real ficasse no fim do corredor.

Três motivos, cada um suficiente. **Não é seu para publicar.** As pessoas deram o nome a uma escola para pegar
um projetor emprestado, não para aparecer no portfólio de alguém. **A lei concorda**: leis de proteção de
dados como a LGPD no Brasil e o GDPR na Europa regem dados pessoais independentemente do tamanho do projeto.
**E quem avalia percebe**: dados privados com cara de reais num repositório público se leem como falta de
critério exatamente na área em que quem contrata não pode aceitar uma.

Dois lugares onde eles se escondem. **Em capturas de tela**: uma aba do navegador, uma barra de favoritos ou
uma notificação pode mostrar um e-mail ou um nome; tire capturas num perfil de navegador limpo, ou com um
script, como esta aula fez. **No histórico**: uma exportação real que entrou num commit uma vez e foi apagada
continua no repositório, a lição da aula 14 aplicada a pessoas em vez de senhas.

Dados inventados têm mais uma vantagem: dá para moldá-los. Dados reais raramente têm exatamente um
empréstimo atrasado no momento em que você precisa de uma captura.
