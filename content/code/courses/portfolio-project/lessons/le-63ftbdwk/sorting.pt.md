title: Deve, deveria, poderia, não vai
version: 1

Com o esqueleto rodando e a coisa única identificada, todo o resto ainda precisa ser separado. Um jeito
comum de fazer isso é o **MoSCoW**, quatro baldes nomeados pelas iniciais em inglês: must, should, could,
won't (deve, deveria, poderia, não vai desta vez). Aqui está a lista inteira do loanbook, como estava
depois do briefing:

| balde | loanbook | o teste do balde |
|---|---|---|
| **deve** | listar, emprestar, receber de volta; recusar um segundo empréstimo; mostrar o que está atrasado | sem isso, o *pronto quando* do briefing falha |
| **deveria** | mensagens de erro claras; uma página que funcione no celular; rótulos que um leitor de tela consiga usar | sem isso funciona, e quem avalia nota a falta |
| **poderia** | um layout mais bonito; dados de exemplo para a demo; uma caixa de busca | agradável, e ninguém sentiria falta na primeira versão |
| **não vai** (desta vez) | lembretes por e-mail; relatórios; a biblioteca; contas | nomeados em *fora do escopo*, guardados para depois |

Duas regras deixam os baldes honestos. **O balde do deve é definido pelo briefing, não pelo gosto**: um
item só é deve se uma linha de *pronto quando* falha sem ele. E **não vai é um balde, não uma lixeira**: o
que está nele fica escrito, e é isso que permite dizer não hoje sem perder a ideia.

O balde do deveria é onde projetos de portfólio diferem de projetos de trabalho. Mensagens de erro, layout
de celular e rótulos acessíveis são *deveria* para a Marta, que usaria sem eles. Para quem avalia, que
está verificando o que você repara, ficam perto de *deve*, e as aulas 11 e 13 os tratam assim.
