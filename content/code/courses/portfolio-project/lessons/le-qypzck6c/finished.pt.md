"Terminado" é uma palavra que todo mundo usa e ninguém define, então um projeto de portfólio precisa da
sua própria definição. Cinco coisas, cada uma verificável por quem lê:

1. **Roda a partir do README na máquina de outra pessoa.** Não na sua, onde tudo já está instalado. A
   aula 16 testa isso numa máquina limpa.
2. **Tem um endereço, ou uma gravação do deploy.** Algo que quem lê consegue abrir sem instalar nada.
   Aula 15.
3. **Testa a regra que mais pode quebrar.** Não tudo; a regra cuja falha seria um erro e não só uma
   feiura. Aula 12.
4. **Registra duas ou três decisões**, com o custo de cada uma. De novo a aula 16, no README.
5. **Você sabe explicar cada parte.** Se há um arquivo que você copiou e não conseguiria reescrever, ainda
   não está terminado. Aulas 19 e 20.

Repare no que a lista deixa de fora. Não pede muitas funcionalidades, uma linguagem específica nem um
provedor de nuvem. Um projeto com uma tela que cumpre as cinco está terminado. Um com trinta
funcionalidades que cumpre duas não está, e **terminado é a propriedade que quem lê verifica primeiro**.

A figura põe cinco tutoriais ao lado de um projeto. Os tutoriais marcam a primeira linha cinco vezes,
porque cada tutorial escreveu um README que funciona. O projeto marca cada linha uma vez. Quem avalia
está contando linhas.
