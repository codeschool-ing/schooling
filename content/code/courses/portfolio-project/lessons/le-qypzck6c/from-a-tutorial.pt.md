---
title: Transformando um tutorial num projeto
version: 1
---

Um tutorial pode ser o começo de um projeto de portfólio, desde que não seja o fim. O teste é a mesma
pergunta: o que você decidiu que as instruções não decidiram? Três movimentos fazem a resposta ser
diferente de nada.

**Mude o problema, não a pintura.** Outro esquema de cores ou outro nome para o app continua sendo o
mesmo tutorial. Outro problema muda tudo o que está abaixo dele: a lista de tarefas vira um registro de
empréstimos de equipamento, e de repente um item pode ser emprestado duas vezes, o que nenhuma tarefa
pode. O problema novo traz regras próprias, e é das regras que vêm as decisões.

**Acrescente a regra que o tutorial não tinha.** Todo tutorial para no caminho feliz. A primeira regra
que você acrescenta — uma recusa, um limite, uma data que torna algo atrasado — é código que ninguém
escreveu por você, e ela precisa de um teste, de uma mensagem de erro e de uma decisão sobre onde mora.

**Leve para onde o tutorial não foi.** Faça o deploy, que a maioria dos tutoriais deixa como exercício.
Ou torne acessível, ou faça sobreviver a uma entrada ruim. Cada um desses encontra problemas que o autor
do tutorial nunca viu, porque parou antes deles.

Depois desses três movimentos o projeto é seu, e **o tutorial vira uma linha no README**: *começou pelo
tutorial de X sobre Y; tudo depois do primeiro commit é meu*. Dizer onde começou não é fraqueza. Omitir,
quando quem avalia reconhece os nomes dos arquivos de qualquer jeito, é.
