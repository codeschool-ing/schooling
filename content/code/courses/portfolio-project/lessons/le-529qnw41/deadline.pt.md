---
title: Um prazo que você define, e cumpre
version: 1
---

Ninguém vai definir o prazo de um projeto de portfólio. Isso torna fácil não ter nenhum, e um projeto sem
prazo termina quando tudo estiver perfeito, ou seja, nunca. Então defina um, e defina do jeito que os
marcos são definidos: **uma data para cada marco, e uma data para o último**.

```
ana@laptop:~/loanbook$ git log --tags --no-walk --format='%ad %d' --date=short
2026-07-06  (HEAD -> main, tag: v1.0.0)
2026-06-29  (tag: v0.3.0)
2026-06-15  (tag: v0.2.0)
2026-06-05  (tag: v0.1.0)
```

Essas são as do loanbook, lidas direto das tags. Três coisas fazem um prazo que você mesmo definiu se
manter.

**Conte para alguém.** Uma data que só você conhece é uma data que você move em silêncio. Conte a um
amigo, a um grupo de estudo, a um mentor, ou escreva no primeiro commit do README: *primeira versão até 6
de julho*. Você não está pedindo que ninguém cobre; está tornando mover a data um pouco constrangedor.

**Ponha data em cada marco, não só no fim.** Um prazo daqui a seis semanas parece folgado até a quinta
semana. Um marco a cada uma ou duas semanas faz você descobrir o atraso enquanto ainda dá tempo de cortar.

**Decida antes o que acontece quando você perde um.** A resposta quase sempre é a mesma: **corte, não
estenda**. A lista do que pode ser cortado da aula 6 existe exatamente para esse dia. Mover a data em vez
disso é o que transforma um projeto de seis semanas num de seis meses, porque a segunda mudança é mais
fácil que a primeira. A coisa única e o piso ficam; todo o resto é negociável.
