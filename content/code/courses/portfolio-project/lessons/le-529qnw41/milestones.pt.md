---
title: Um marco é algo que dá para mostrar
version: 1
---

Um marco não é uma data, nem uma porcentagem. É **um estado do projeto que você conseguiria demonstrar a
alguém**, com uma data junto. *80% pronto* não se demonstra; *uma professora empresta um projetor e o
segundo empréstimo é recusado* se demonstra.

O loanbook teve quatro:

| marco | o que dá para mostrar | as linhas do briefing que fecha |
|---|---|---|
| `v0.1.0` o esqueleto | uma página que lista, empresta e recebe de volta, de ponta a ponta | nenhuma ainda, e isso é esperado |
| `v0.2.0` as regras | um segundo empréstimo recusado dizendo com quem está; atrasos marcados | a primeira e a terceira linhas de *pronto quando* |
| `v0.3.0` implantado | a página num endereço, com HTTPS, sobrevivendo a um reinício | a quarta: a Marta e um celular conseguem abrir |
| `v1.0.0` vale mostrar | README, captura de tela, dados de exemplo, licença | o *terminado* da aula 2 inteiro |

Três propriedades fazem desses bons marcos. **Cada um é demonstrável**, ou seja, termina em algo que roda
e não num documento. **Cada um é útil sozinho**: se o projeto tivesse parado na `v0.2.0`, o que existia
ainda seria a parte interessante. E **são poucos**: quatro marcos em cinco semanas. Um marco a cada dois
dias é uma lista de tarefas; um para o projeto inteiro é um desejo.

Repare que o segundo marco é a coisa única da aula 5. Pôr o ponto do projeto no primeiro marco depois do
esqueleto é deliberado: aconteça o que acontecer depois, a parte que prova algo já está feita.
