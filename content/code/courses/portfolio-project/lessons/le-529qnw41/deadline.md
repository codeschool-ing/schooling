---
title: A deadline you set, and keep
version: 1
---

Nobody will set the deadline for a portfolio project. That makes it easy to have none, and a project
with none gets finished when everything is perfect, which is never. So set one, and set it the way the
milestones are set: **a date for each milestone, and a date for the last one**.

```
ana@laptop:~/loanbook$ git log --tags --no-walk --format='%ad %d' --date=short
2026-07-06  (HEAD -> main, tag: v1.0.0)
2026-06-29  (tag: v0.3.0)
2026-06-15  (tag: v0.2.0)
2026-06-05  (tag: v0.1.0)
```

Those are loanbook's, read straight off the tags. Three things make a self-set deadline hold.

**Say it to somebody.** A date only you know is a date you can move quietly. Tell a friend, a study
group, a mentor, or write it in the README's first commit: *first version by 6 July*. You are not
asking anybody to check; you are making it slightly embarrassing to move.

**Put a date on each milestone, not only the end.** A deadline six weeks away feels like plenty until
week five. A milestone every week or two means you find out you are late while there is still time to
cut.

**Decide in advance what happens when you miss one.** The answer is almost always the same: **cut,
don't extend**. Lesson 6's list of what can be cut is exactly for this day. Moving the date instead is
what turns a six-week project into a six-month one, because the second move is easier than the first.
The one thing and the floor stay; everything else is negotiable.
