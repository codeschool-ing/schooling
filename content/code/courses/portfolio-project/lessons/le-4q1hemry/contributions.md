title: Contributions, and after
version: 1
---

A portfolio project is not really expecting contributions, and it should not pretend otherwise with a
long `CONTRIBUTING` file, a code of conduct and issue templates for a project with one author. Those are
lesson 8's theatre in another form. What it should do is smaller.

- **Leave issues open.** A reviewer who finds a bug and has nowhere to report it has nowhere to be
  impressed by your answer either. If somebody opens an issue, answer it within days; a polite, specific
  reply to a stranger is evidence of how you work with colleagues.
- **Say in one line how to contribute, if at all.** *Issues are welcome; this is a portfolio project, so
  I may not accept larger changes* is honest and enough.
- **Decide what happens after the job search.** A project you will not maintain can say so at the top of
  the README and be archived, lesson 2's meaning of *left*. A project you keep improving is itself
  evidence, and its later commits show what you learned since. Either is fine; what reads badly is a
  project that looks maintained and is not, with open issues nobody has answered for a year.

And one thing about the rest of the profile: **every public repository is part of the portfolio**, whether
you pinned it or not, lesson 1. Before you send the link to anyone, look at your profile the way a
stranger would, signed out, and decide about each thing a stranger can see.
