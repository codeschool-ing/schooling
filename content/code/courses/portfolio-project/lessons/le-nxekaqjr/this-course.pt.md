title: O projeto que este curso constrói
version: 2
---

Cada aula daqui em diante acrescenta uma peça a um projeto, e mostra essa peça num projeto de verdade:
o **loanbook**, um pequeno serviço web para a sala de TI de uma escola. Professores pegam emprestados
projetores, notebooks e adaptadores, e o registro de quem está com o quê é uma folha de papel na porta.
O loanbook troca a folha por uma página que mostra o que está fora, com quem e quando volta.

Ele é pequeno de propósito: uma página, uma API, um arquivo SQLite, umas duzentas linhas de Python sem
framework. Tem uma parte difícil, que é o assunto da aula 5. Termina implantado num servidor, com README,
testes, licença e uma apresentação de dois minutos. A história dele é contada uma aula de cada vez:
quando uma aula diz *o commit 6 recusou o segundo empréstimo*, a transcrição do commit 6 está ali.

**O loanbook é para ler, não para digitar.** O curso não lhe entrega o código dele, e as transcrições
não são passos a repetir. Cada uma mostra um passo bem feito num projeto de verdade, e o passo que você
dá é o mesmo, no seu. Duas coisas você monta à mão, porque o seu projeto também precisa delas: o seu
computador, pronto para trabalhar, na próxima seção, e o servidor para onde você faz o deploy, na aula 15.

O exemplo é um serviço web porque esse formato tem mais partes móveis para mostrar. O seu projeto terá o
formato que a sua trilha pede:

::: track frontend mobile
Para você o projeto é a interface: algo que uma pessoa abre e usa, num aparelho de verdade ou num
navegador de verdade. Tome as aulas de acessibilidade, estados vazios e demo como o centro do curso.
:::

::: track backend ai prompt
Para você o projeto é um serviço com um contrato: uma API, o que ela recusa, e o que acontece quando
falha. O loanbook já está perto do seu formato, e as aulas de erros, testes e deploy são suas.
:::

::: track data data-science bi
Para você o projeto é uma pergunta respondida com dados: um pipeline, uma análise ou um painel. Onde o
loanbook tem uma API, você tem um conjunto de dados e um método; onde ele tem uma página, você tem o
resultado que alguém olha.
:::

::: track devops devsecops cloud-engineering
Para você o projeto é o caminho de um commit até algo rodando: o build, o deploy, o que mantém de pé e
como você descobre que parou. Trate o loanbook como a carga de trabalho e a aula 15 como o seu centro.
:::

::: track it-support networks-infra dba
Para você o projeto é um ambiente em que outra pessoa pode confiar: um laboratório que você montou,
documentado bem o bastante para outra pessoa reconstruí-lo. Onde o loanbook tem código, você tem
configuração e um runbook.
:::

::: track qa security
Para você o projeto é evidência sobre o sistema de outra pessoa: uma suíte de testes, uma avaliação, um
achado escrito de forma que possa ser reproduzido. O loanbook pode ser esse sistema; os testes e as
recusas dele são um começo.
:::

::: track *
Qualquer que seja a sua área, o projeto é aquilo que um desconhecido consegue abrir e verificar. Leia o
loanbook como um exemplo disso, e a aula 3 para o que quem contrata na sua área abre primeiro.
:::

A aula 3 vai mais fundo no que quem contrata em cada área abre de fato.
