---
title: Por que um museu joga contra você
version: 1
---

O instinto é mostrar tudo. Todo exercício, todo tutorial, toda experiência de fim de semana, com o
raciocínio de que mais é mais. Não é, por um motivo que não tem nada a ver com qualidade: **quem lê faz
uma amostra**. Abre uma ou duas coisas, e julga você pelo que abriu.

Se o seu perfil tem vinte repositórios, quem lê não vê vinte. Vê aquele que chamou atenção: o do commit
mais recente, o de nome mais engraçado, ou só o primeiro da lista. Se esse for uma experiência pela
metade de dois anos atrás, esse é o seu portfólio para essa pessoa, e o bom projeto três posições abaixo
é como se não existisse.

Então um museu não é neutro. **Cada item fraco é uma chance de ser julgado por ele.** A saída não é apagar
a sua história; é decidir o que aparece primeiro:

- **Fixe de um a três projetos.** O GitHub e o GitLab deixam escolher o que aparece no topo do perfil.
  Esses são os únicos que a maioria dos leitores vai ver.
- **Ponha uma frase no perfil** que diga qual projeto você quer que seja lido primeiro.
- **Deixe o resto onde está.** Exercícios antigos não atrapalham quando não são a primeira coisa que
  alguém encontra. Um perfil vazio com um projeto fixado é mais forte do que um cheio sem nenhum.

E **um projeto terminado vale mais do que vários quase prontos**, que é a aula 2.
