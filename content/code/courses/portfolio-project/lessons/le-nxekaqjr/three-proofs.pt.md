---
title: O que um projeto precisa provar
version: 1
---

Tire a tecnologia e um projeto de portfólio prova três coisas sobre quem o fez. Cada uma corresponde a
um dos três leitores.

**Que você termina.** Um projeto que roda, que outra pessoa consegue iniciar a partir do README, que tem um
endereço ou uma gravação. Todo leitor já viu muitos projetos que pararam antes do fim, e é por isso que
um terminado se destaca antes de alguém ler uma linha de código. É o que a
triagem vê.

**Que você decide.** Trabalho de verdade é uma sequência de escolhas com custo: este banco e não aquele,
esta funcionalidade cortada para o resto sair. Um projeto que registra duas ou três dessas escolhas, com o
que cada uma custou, mostra critério, e critério é o que quem contrata está tentando contratar.

**Que você explica.** Alguém vai perguntar *por que você fez desse jeito*, e a resposta é a entrevista.
Um projeto que você entende de ponta a ponta, incluindo a parte que faria diferente hoje, vale mais do
que um maior montado com peças que você não sabe explicar. É a pergunta inteira da entrevista técnica.

Repare no que falta na lista. **Tamanho não está nela**, e novidade também não. Um serviço pequeno que faz
uma coisa direito, com as decisões escritas, prova as três. O exemplo do curso foi escolhido para ser
exatamente desse tamanho, para que as três provas fiquem visíveis em vez de enterradas.
