title: O que deixar de fora
version: 1
---

Um README cresce por acúmulo, e a maior parte do que acumula o piora. Seis coisas comuns sem as quais um
README de portfólio fica melhor:

- **Um muro de selos.** Build passando, cobertura, licença, linguagem, último commit, cada um um retângulo
  colorido. Um só, o status do build da aula 12, diz algo; dez dizem que você encontrou o site de selos.
- **Instalação para toda plataforma.** Se precisa de Python, diga qual versão e aponte para python.org. Três
  páginas sobre instalar Python no Windows, no macOS e em quatro distribuições Linux pertencem ao Python.
- **Uma descrição de cada arquivo.** Quem lê vê os arquivos. Descreva os que não são óbvios, se houver, numa
  linha cada.
- **Um changelog no README.** É para isso que existem tags e releases, aula 7.
- **Afirmações sem evidência.** *Rápido*, *escalável*, *seguro*, *pronto para produção*. A regra da aula 1
  vale: ou há algo que quem lê consegue verificar, ou a palavra é lida como enchimento, e enchimento custa
  confiança.
- **Um parágrafo sobre você.** O seu perfil existe para isso. O README é sobre o projeto, e o projeto é a
  melhor coisa que ele pode dizer sobre você.

O teste para qualquer linha é o mesmo de tudo neste curso: **quem avalia ficaria pior sem ela?** Se não, ela
sai, e as linhas que ficam são lidas.
