---
title: What to leave out
version: 1
---

A README grows by accretion, and most of what it accumulates makes it worse. Six things that are
common and that a portfolio README is better without:

- **A wall of badges.** Build passing, coverage, licence, language, last commit, each a coloured
  rectangle. One, the build status of lesson 12, says something; ten say that you found the badge site.
- **Installation for every platform.** If it needs Python, say which version and link to python.org.
  Three pages on installing Python on Windows, macOS and four Linux distributions belong to Python.
- **A description of every file.** The reader can see the files. Describe the ones that are not obvious,
  if any, in one line each.
- **A changelog in the README.** That is what tags and releases are for, lesson 7.
- **Claims with no evidence.** *Fast*, *scalable*, *secure*, *production-ready*. Lesson 1's rule applies:
  either there is something the reader can check, or the word reads as filler, and filler costs trust.
- **A paragraph about yourself.** Your profile is for that. The README is about the project, and the
  project is the best thing it can say about you.

The test for any line is the same as for everything in this course: **would a reviewer be worse off
without it?** If not, it goes, and the lines that remain get read.
