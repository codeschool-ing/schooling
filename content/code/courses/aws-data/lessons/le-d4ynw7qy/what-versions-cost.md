title: What keeping every version costs
version: 1
---

**Versioning multiplies the bill by the number of versions kept, and nothing caps that number unless
a rule does.** A key written once a day for a year is 365 versions, each billed in full, and the
listing that a person or a dashboard looks at shows one object. The bucket's size in the console's
metrics includes every version; the size anybody estimates from `aws s3 ls` does not.

Quitanda's curated customer table is 50 GB and rewritten every night. The program below prices a year
of it in Standard, at the sheet's 0.04050 a GB-month, with no rule and with a rule that expires each
noncurrent version seven days after it is replaced. Save it as `~/aws/versions.py`:

```schooling-example

The price is the sheet's line for Standard; the other two describe Quitanda's table and the rule."}, {"code": "def stored(day, rule):\n    versions = day if not rule else min(day, KEEP + 1)\n    return versions * TABLE_GB\n\n\n", "note": "**How many GB the bucket holds on a given day.** With no rule, day `d` holds `d` versions: the current one and every one before it. With the rule, the current version plus the seven written in the last seven days, so never more than eight."}, {"code": "print(f'{\"month\":>5}{\"GB, no rule\":>13}{\"USD\":>10}{\"GB, rule\":>10}{\"USD\":>8}')\ntotal = {False: 0.0, True: 0.0}\nfor month in range(1, 13):\n    cost = {}\n    for rule in (False, True):\n        days = range((month - 1) * 30 + 1, month * 30 + 1)\n        cost[rule] = sum(stored(d, rule) for d in days) * PRICE / 30\n        total[rule] += cost[rule]\n    end = month * 30\n    print(f'{month:>5}{stored(end, False):>13,}{cost[False]:>10,.2f}'\n          f'{stored(end, True):>10,}{cost[True]:>8.2f}')\nprint(f'{\"year\":>5}{\"\":>13}{total[False]:>10,.2f}{\"\":>10}{total[True]:>8.2f}')\n", "note": "A month is 30 days here, and a day's storage is a thirtieth of a GB-month. **The last month without a rule costs 699.64, and with one 16.20.** At the end of the year the bucket
without a rule holds 360 copies of a 50 GB table, 18,000 GB, for a dataset whose current size never
moved. The year's total is 4,386.15 against 192.51: more than twenty times as much, spent on versions
that nobody had asked for after their first week.

**The rule changes the shape, and the size of the table does not matter to the argument.** Without a
rule the stored size grows by one copy of the table every night, forever. With a rule it climbs for
eight days, one current version and seven noncurrent, and then stays flat. A table ten times bigger
gives a bill ten times bigger in both columns, and the same ratio between them.

The arithmetic counts storage and nothing else, which is the cost that grows. Each night's write is
one `PUT` whatever the rule, and expiring a version through a rule is not billed as a request.

## How many days to keep

**Seven days is a choice about how long a mistake can go unnoticed**, not a number with a right
answer. A noncurrent version is a way back from a bad nightly job, and it is useful only for as long
as somebody would still notice the job was bad. Quitanda's analysts look at the customer table every
morning, so a broken rewrite is seen within a day and seven is generous. A table read once a month
needs a month and a few days. A rule can also keep a fixed number of noncurrent versions,
`NewerNoncurrentVersions`, which suits a key written irregularly.
