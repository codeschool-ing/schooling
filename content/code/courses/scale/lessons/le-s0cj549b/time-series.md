A **time-series database** stores measurements: a value, a timestamp, and a few labels saying what
was measured. Tickets sold per minute, the latency of each request, the temperature of a server.
The data has a shape that relational tables can hold and that this family exploits:

- **It arrives in time order and is almost never changed.** Writes are appends at the end.
- **It is read by time ranges**, "the last hour", and usually aggregated: averages, sums,
  percentiles per minute.
- **Its value falls with age.** Yesterday's per-second numbers matter; last year's matter only as
  daily totals.

The fifth access pattern of section 03, sales per minute for a dashboard, is all three. A point in
InfluxDB's **line protocol**, the text format it ingests, looks like this:

```
sales,show=1,channel=web tickets=3i 1794776400000000000
```

The measurement is `sales`; `show` and `channel` are **tags**, indexed labels to filter and group
by; `tickets=3i` is a **field**, the value, an integer here; the last number is the time in
nanoseconds.

## What the family does with that shape

- **Compression.** Consecutive timestamps differ by similar amounts and consecutive values are
  close, so storing differences instead of values shrinks the data many times over.
- **Retention.** Data older than a set age is dropped automatically, partition by partition, the
  way lesson 2 dropped a month: by deleting files, not rows.
- **Downsampling.** Raw points are rolled up into coarser ones, one per minute, then one per hour,
  and the raw points are discarded. A year of per-second data becomes a year of hourly data that
  still answers every question anybody asks about last year.

## The cost: cardinality

Every combination of tag values is a separate **series**, with its own index entries. `show` with
a hundred values and `channel` with three make 300 series, which is nothing. A tag with a value per
buyer, or per request, makes millions, and the index outgrows memory. **Tags are for the few
dimensions you group by; anything with many values is a field**, which is not indexed. Lesson 7
meets exactly this problem in Prometheus's labels, which is the same idea in a monitoring system.
