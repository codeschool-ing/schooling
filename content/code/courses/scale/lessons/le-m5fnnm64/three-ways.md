---
title: When one database is not enough
version: 1
---

Lesson 1 ended with a rule of thumb: **the stateless parts scale out, and the database scales up
for a long time**. This lesson is about what happens at the end of that long time, when one
PostgreSQL on the largest machine you are willing to pay for is still not enough, or when losing
that one machine is not a risk you can take.

"Not enough" comes in three different shapes, and each has its own answer:

- **Too many reads.** The box office's page for a show is read thousands of times for every
  ticket sold. The database spends its processors answering the same questions about the same
  rows.
- **Too much data in one table.** Two years of sales are a table of hundreds of millions of rows,
  whose indexes no longer fit in memory, and whose oldest rows nobody asks about.
- **Too many writes, or too much data altogether.** Every sale has to be written somewhere, and
  one machine writes at one machine's speed.

The answers are three techniques that are often confused, because each one divides the data in
some sense:

| | what is divided | where the pieces live | what it solves |
|---|---|---|---|
| **replication** | nothing: every copy holds everything | several servers | reads, and surviving the loss of one server |
| **partitioning** | one table, into pieces by a key | one server | big tables, and throwing away old data |
| **sharding** | the data, into pieces by a key | several servers, each holding a share | writes and total size |

They combine freely, and real systems use all three at once: a sharded database where every shard
has replicas, and every big table on every shard is partitioned by month. **The order to reach for
them is the order of this lesson**, because each is more expensive than the one before. A replica
costs a server and a little care. Partitioning costs a migration of one table. Sharding costs a
change to every query the program makes, forever, and it is the one that is hardest to undo.

`architecture` lesson 10 gave these their names and their place among the patterns. Here each one
runs on the box office, so you can see what it buys and what it charges.
