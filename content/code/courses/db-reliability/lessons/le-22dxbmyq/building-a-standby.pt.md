O standby precisa de três coisas do primário: um papel com permissão para replicar, um jeito de fazer
login com ele e um base backup de onde partir. A primeira é um único comando, no primário:

```
shop=# CREATE ROLE replicator LOGIN REPLICATION PASSWORD 'replica-pass-1';
CREATE ROLE
ana@vm:~$ echo '127.0.0.1:5432:*:replicator:replica-pass-1' | sudo -u postgres tee /var/lib/postgresql/.pgpass > /dev/null
ana@vm:~$ sudo -u postgres chmod 600 /var/lib/postgresql/.pgpass
```

`REPLICATION` é o direito de receber o log, e nada mais; o papel não consegue ler uma tabela. A senha
vai num **arquivo `.pgpass`** no diretório home do `postgres`, o usuário que roda o standby, para que
nunca fique escrita num arquivo de configuração que um backup copia. O `pg_hba.conf` do Ubuntu já
aceita conexões de replicação vindas da mesma máquina com senha, que é o que o standby vai fazer.

## O servidor do standby

As ferramentas do Ubuntu montam a configuração de um servidor novo: a porta, 5434 aqui, o arquivo de
log e o diretório em `/etc/postgresql`. Crie um, e depois jogue fora os dados recém-inicializados,
porque os dados do standby têm que ser uma cópia dos do primário:

```
ana@vm:~$ sudo pg_createcluster 16 standby --port 5434
```

## O base backup, com mais três opções

O `pg_basebackup` da lição 3, rodado como `postgres` direto no diretório de dados do standby, com três
opções que fazem da cópia um standby em vez de um backup:

```
ana@vm:~$ sudo -u postgres pg_basebackup -h 127.0.0.1 -p 5432 -U replicator -D /var/lib/postgresql/16/standby -R -C -S standby1 -X stream -c fast
ana@vm:~$ sudo cat /var/lib/postgresql/16/standby/postgresql.auto.conf
# Do not edit this file manually!
# It will be overwritten by the ALTER SYSTEM command.
primary_conninfo = 'user=replicator passfile=''/var/lib/postgresql/.pgpass'' channel_binding=prefer host=127.0.0.1 port=5432 sslmode=prefer sslcompression=0 sslcertmode=allow sslsni=1 ssl_min_protocol_version=TLSv1.2 gssencmode=prefer krbsrvname=postgres gssdelegation=0 target_session_attrs=any load_balance_hosts=disable'
primary_slot_name = 'standby1'
ana@vm:~$ sudo ls /var/lib/postgresql/16/standby/standby.signal
/var/lib/postgresql/16/standby/standby.signal
```

- **`-R`** escreve as configurações de replicação no `postgresql.auto.conf` da cópia e cria o
  `standby.signal`, o arquivo vazio cuja presença diz ao PostgreSQL para subir como standby.
- **`-C -S standby1`** cria um **slot de replicação** chamado `standby1` no primário e diz ao standby
  para usá-lo. O slot é a promessa do primário de guardar o log que o standby ainda não recebeu; as
  duas últimas seções desta lição tratam do preço dessa promessa.
- **`-X stream`**, como na lição 3, traz junto o log escrito durante a cópia.

O `primary_conninfo` é uma string de conexão completa, quase toda feita de valores padrão escritos por
extenso. As partes que importam são o usuário, o `passfile`, o host e a porta: o standby se conecta ao
primário exatamente como qualquer cliente faria.
