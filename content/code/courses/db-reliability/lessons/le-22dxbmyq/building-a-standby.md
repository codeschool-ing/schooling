The standby needs three things from the primary: a role allowed to replicate, a way to log in as it,
and a base backup to start from. The first is one statement, on the primary:

```
shop=# CREATE ROLE replicator LOGIN REPLICATION PASSWORD 'replica-pass-1';
CREATE ROLE
ana@vm:~$ echo '127.0.0.1:5432:*:replicator:replica-pass-1' | sudo -u postgres tee /var/lib/postgresql/.pgpass > /dev/null
ana@vm:~$ sudo -u postgres chmod 600 /var/lib/postgresql/.pgpass
```

`REPLICATION` is the right to receive the log, and nothing else; the role cannot read a table. The
password goes in a **`.pgpass` file** in the home directory of `postgres`, the user that runs the
standby, so that it is never written into a configuration file a backup copies. Ubuntu's
`pg_hba.conf` already accepts replication connections from the same machine with a password, which
is what the standby will make.

## The standby's server

Ubuntu's tooling builds the configuration of a new server: its port, 5434 here, its log file and its
directory under `/etc/postgresql`. Make one, and then throw its freshly initialised data away,
because the standby's data has to be a copy of the primary's:

```
ana@vm:~$ sudo pg_createcluster 16 standby --port 5434
```

## The base backup, with three more options

Lesson 3's `pg_basebackup`, run as `postgres` straight into the standby's data directory, with three
options that make the copy a standby rather than a backup:

```
ana@vm:~$ sudo -u postgres pg_basebackup -h 127.0.0.1 -p 5432 -U replicator -D /var/lib/postgresql/16/standby -R -C -S standby1 -X stream -c fast
ana@vm:~$ sudo cat /var/lib/postgresql/16/standby/postgresql.auto.conf
# Do not edit this file manually!
# It will be overwritten by the ALTER SYSTEM command.
primary_conninfo = 'user=replicator passfile=''/var/lib/postgresql/.pgpass'' channel_binding=prefer host=127.0.0.1 port=5432 sslmode=prefer sslcompression=0 sslcertmode=allow sslsni=1 ssl_min_protocol_version=TLSv1.2 gssencmode=prefer krbsrvname=postgres gssdelegation=0 target_session_attrs=any load_balance_hosts=disable'
primary_slot_name = 'standby1'
ana@vm:~$ sudo ls /var/lib/postgresql/16/standby/standby.signal
/var/lib/postgresql/16/standby/standby.signal
```

- **`-R`** writes the replication settings into the copy's `postgresql.auto.conf`, and creates
  `standby.signal`, the empty file whose presence tells PostgreSQL to start as a standby.
- **`-C -S standby1`** creates a **replication slot** called `standby1` on the primary and tells the
  standby to use it. The slot is the primary's promise to keep log the standby has not received yet;
  the last two sections of this lesson are about the price of that promise.
- **`-X stream`**, as in lesson 3, brings the log written during the copy along with it.

`primary_conninfo` is a full connection string, most of it defaults written out. The parts that
matter are the user, the `passfile`, the host and the port: the standby connects to the primary
exactly as any client would.
