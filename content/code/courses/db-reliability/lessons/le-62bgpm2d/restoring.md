---
title: Restoring with pgBackRest
version: 1
---

A pgBackRest restore is lesson 3's four steps with the copying done by the tool: stop the target,
empty its data directory, restore into it, start it. The target is again the second server, on port
5433, and `--pg1-path` points the restore there instead of at the stanza's own data directory:

```
ana@vm:~$ sudo pg_ctlcluster 16 restore stop
ana@vm:~$ sudo rm -rf /var/lib/postgresql/16/restore
ana@vm:~$ time sudo -u postgres pgbackrest --stanza=main --pg1-path=/var/lib/postgresql/16/restore --archive-mode=off restore

real	0m1.207s
user	0m0.174s
sys	0m0.431s
ana@vm:~$ sudo tail -n 3 /var/lib/postgresql/16/restore/postgresql.auto.conf
# Recovery settings generated by pgBackRest restore on 2026-10-10 16:27:58
archive_mode = 'off'
restore_command = 'pgbackrest --pg1-path=/var/lib/postgresql/16/restore --stanza=main archive-get %f "%p"'
ana@vm:~$ sudo pg_ctlcluster 16 restore start
ana@vm:~$ psql -X -A -t shop -f verify.sql > live.txt
ana@vm:~$ psql -X -A -t -p 5433 shop -f verify.sql > restored.txt
ana@vm:~$ diff live.txt restored.txt && echo identical
identical
```

**About a second** to put the files back, decompressing them on the way. Then the three lines
pgBackRest added to the copy's `postgresql.auto.conf`, which deserve attention:

- `restore_command` tells the restored server how to fetch archived segments, one at a time, as
  recovery asks for them. It is the reverse of `archive_command`, and it is what lets the copy
  replay past the end of the backup, up to the last segment in the archive.
- **`archive_mode = 'off'`**, because the command line asked for it with `--archive-mode=off`. That
  is not a detail. The copy carries the original's settings, including `archive_command`, and a
  restored server with archiving on would **push its own segments into the same stanza** as the
  live server, from a different history. The repository would then hold two servers' log under one
  name, and the next recovery could replay the wrong one. A restore that is a test, a drill or a
  copy for somebody's analysis gets `--archive-mode=off`, always.

The report agrees with the live server. That is pgBackRest's whole loop, backup, verify and restore,
on the same machine; lesson 7 times it, and lesson 9 puts the repository somewhere a failure of this
machine cannot reach.
