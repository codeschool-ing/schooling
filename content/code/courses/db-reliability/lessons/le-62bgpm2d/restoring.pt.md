---
title: Restaurando com o pgBackRest
version: 1
---

Uma restauração com o pgBackRest são os quatro passos da lição 3 com a cópia feita pela ferramenta:
parar o destino, esvaziar o diretório de dados dele, restaurar ali dentro, subir. O destino é de
novo o segundo servidor, na porta 5433, e o `--pg1-path` aponta a restauração para lá em vez de para
o diretório de dados da própria stanza:

```
ana@vm:~$ sudo pg_ctlcluster 16 restore stop
ana@vm:~$ sudo rm -rf /var/lib/postgresql/16/restore
ana@vm:~$ time sudo -u postgres pgbackrest --stanza=main --pg1-path=/var/lib/postgresql/16/restore --archive-mode=off restore

real	0m1.207s
user	0m0.174s
sys	0m0.431s
ana@vm:~$ sudo tail -n 3 /var/lib/postgresql/16/restore/postgresql.auto.conf
# Recovery settings generated by pgBackRest restore on 2026-10-10 16:27:58
archive_mode = 'off'
restore_command = 'pgbackrest --pg1-path=/var/lib/postgresql/16/restore --stanza=main archive-get %f "%p"'
ana@vm:~$ sudo pg_ctlcluster 16 restore start
ana@vm:~$ psql -X -A -t shop -f verify.sql > live.txt
ana@vm:~$ psql -X -A -t -p 5433 shop -f verify.sql > restored.txt
ana@vm:~$ diff live.txt restored.txt && echo identical
identical
```

**Cerca de um segundo** para pôr os arquivos de volta, descomprimindo-os no caminho. Depois, as três
linhas que o pgBackRest acrescentou ao `postgresql.auto.conf` da cópia, que merecem atenção:

- O `restore_command` diz ao servidor restaurado como buscar segmentos arquivados, um de cada vez, à
  medida que a recuperação pede. É o inverso do `archive_command`, e é o que deixa a cópia reaplicar
  log além do fim do backup, até o último segmento do arquivo.
- **`archive_mode = 'off'`**, porque a linha de comando pediu isso com `--archive-mode=off`. Não é
  detalhe. A cópia carrega as configurações do original, inclusive o `archive_command`, e um servidor
  restaurado com o arquivamento ligado **empurraria os próprios segmentos para a mesma stanza** que o
  servidor de produção, a partir de outra história. O repositório passaria a guardar o log de dois
  servidores sob um mesmo nome, e a próxima recuperação poderia reaplicar o errado. Uma restauração
  que é um teste, um ensaio ou uma cópia para a análise de alguém leva `--archive-mode=off`, sempre.

O relatório bate com o do servidor de produção. Esse é o ciclo inteiro do pgBackRest, backup,
verificação e restauração, na mesma máquina; a lição 7 mede o tempo dele, e a lição 9 coloca o
repositório num lugar que uma falha desta máquina não alcança.
