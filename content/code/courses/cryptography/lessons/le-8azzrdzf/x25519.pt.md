**A X25519 é o Diffie-Hellman na Curve25519: o segredo de cada lado é uma chave privada de 32
bytes, o valor que ele manda é sua chave pública de 32 bytes, e o segredo compartilhado tem 32
bytes.** Ela é a troca de chaves padrão no TLS 1.3, no SSH, no Signal e no WireGuard, e é o que o
brinquedo da seção anterior vira em tamanho real.

## Ana e Bruno, de novo

O laboratório tem um par X25519 para cada um. As metades públicas são o que cada um mandaria:

```
ana@lab:~/lab$ cat keys/x25519-ana.pub keys/x25519-bruno.pub
-----BEGIN PUBLIC KEY-----
MCowBQYDK2VuAyEASTbzLBVkMLZYXweeov2PfYEtT5ofFaRNGCwbTD0AaRI=
-----END PUBLIC KEY-----
-----BEGIN PUBLIC KEY-----
MCowBQYDK2VuAyEAhULFT23bDRg+0PZvKDTwvrRc7SlAQWOXgnIfa4B/yAs=
-----END PUBLIC KEY-----
```

A Ana combina sua chave privada com a chave pública do Bruno; o Bruno combina sua chave privada com
a da Ana:

```
ana@lab:~/lab$ openssl pkeyutl -derive -inkey keys/x25519-ana.key -peerkey keys/x25519-bruno.pub | xxd -p -c 32
1d3d4704e495e9da6c993a3bb7d20b8906d2d1e8c06a85c5610a27d42bf97436
ana@lab:~/lab$ openssl pkeyutl -derive -inkey keys/x25519-bruno.key -peerkey keys/x25519-ana.pub | xxd -p -c 32
1d3d4704e495e9da6c993a3bb7d20b8906d2d1e8c06a85c5610a27d42bf97436
```

Os mesmos 32 bytes, calculados separadamente a partir de metades opostas. Nada naqueles dois blocos
PEM permite a mais ninguém calculá-los.

## Do segredo compartilhado às chaves

O segredo compartilhado é um ponto de uma curva codificado como bytes, e seus bits não são
uniformemente aleatórios. Ele nunca é usado diretamente como chave AES. A **HKDF** (RFC 5869), uma
função de derivação de chaves feita a partir do HMAC, o transforma em chaves do tamanho certo, e um
rótulo, o *info*, faz chaves para propósitos diferentes saírem sem relação entre si:

```
ana@lab:~/lab$ openssl kdf -keylen 32 -kdfopt digest:SHA256 -kdfopt info:vereda-session -kdfopt hexkey:$(openssl pkeyutl -derive -inkey keys/x25519-ana.key -peerkey keys/x25519-bruno.pub | xxd -p -c 32) HKDF
D6:B1:28:59:90:C5:95:FD:99:BC:42:92:27:A1:51:4C:B7:C6:43:40:6A:36:D6:61:F4:00:5C:08:95:F6:05:B4
```

O TLS 1.3 roda a HKDF muitas vezes sobre um único segredo compartilhado, com rótulos como
`c hs traffic` e `s ap traffic`, para obter chaves separadas para cada sentido e cada etapa da
conexão. Uma chave comprometida para um propósito não diz nada sobre as outras.

## Por que as curvas ganharam este trabalho

A troca clássica da seção anterior funciona com um primo de 2048 bits e ainda é aceita, como
Diffie-Hellman de *corpo finito* (`ffdhe2048` em diante no TLS 1.3). A X25519 a substituiu na
prática pelos motivos que a aula 2 deu para as curvas em geral: os valores enviados têm 32 bytes em
vez de 256, o cálculo é muito mais rápido, e a curva foi projetada para que a implementação óbvia
seja também a segura. Toda chave pública de 32 bytes é uma entrada válida, então uma categoria
inteira de verificações que as implementações de corpo finito erravam simplesmente não existe.

A X25519 serve para **combinar** uma chave, e para mais nada. Ela não assina: isso é a Ed25519, a
mesma curva em outro papel, e as duas chaves não são intercambiáveis.
