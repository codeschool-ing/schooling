A table ranks functions; it cannot show which ones sit inside which. **A flame graph draws every
sampled stack at once**, merged where they share a beginning, so the shape of the program and the
places its time goes are one picture. It was invented for exactly this kind of profile, and it is the
view most people open first.

## How it is built

Take every stack in the profile, the root at the bottom and the function that was running at the
top. Stacks that begin with the same frames share those boxes, and a box is as wide as the number of
samples that passed through it. So:

- **The width of a box is its cum.** `tally.Count` is on 82.5% of the stacks, so its box spans
  82.5% of the picture.
- **The top edge of a box that nothing stands on is its flat.** Wherever a box has no child above it,
  the samples ended there, in that function's own code.
- **Up is deeper into the calls**, and a box's children are the functions it called.
- **The order from left to right means nothing.** This drawing puts the widest child first; others
  sort alphabetically. Neither is time.
- **The colours mean nothing either**, in the original design and in most tools since. They separate
  neighbours, and some tools tint by package.

## Getting one

`go tool pprof -http=localhost:8080 cpu.out` starts a small web server on your machine and opens a
browser at it. **The page it opens on is a flame graph**, interactive, and the View menu leads to the
other reports: `Top`, the graph, the source. It draws the root at the top with the callees hanging
below, which is the same picture upside down. It needs a browser on the machine
running `go tool pprof`; on a server without one, copy the profile file to your own machine first.
That interface is not shown here, since this course's lab has no desktop.

`-http` binds to `localhost` when you give no host, for the same reason as section 05 of lesson 12:
the page shows the source of your program to anybody who can reach the port.
