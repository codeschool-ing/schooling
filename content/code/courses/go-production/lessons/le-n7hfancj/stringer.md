`fmt` prints a value by calling its `String() string` method when it has one, and prints the bare
number when a named integer type has none. **`stringer` writes that method for a set of integer
constants, from the constants themselves**, so the names on the screen are always the names in the
source. It is the generator Go's own source tree uses most, and the tree on this machine can be
asked:

```
ana@vm:~/gen-hits$ grep -r --include="*.go" "^//go:generate" $(go env GOROOT)/src | wc -l
132
ana@vm:~/gen-hits$ grep -r --include="*.go" "^//go:generate stringer" $(go env GOROOT)/src | wc -l
31
```

**31 of the 132 directives in the standard library and the toolchain run stringer**, for things like
the DWARF tags in `debug/dwarf` and the escaping contexts of `html/template`. Of the rest, 78 are
`go run` on a Go program, most often one kept beside the package, writing tables and system-call
wrappers, which is the shape of section 04.

## Five classes of answer

An HTTP status code says what kind of answer it is by its first digit: 2 for success, 4 for the
client's mistake, 5 for the server's. `hits` counts codes one by one, and a report by class is a
small step from there. This section works in a fresh copy of lesson 1's module, in `~/gen-hits`: the
`tally` package and `main.go` from lesson 1 section 03, `genlog` from lesson 1 section 02, and the
same 20,000-line `access.log`. The new package is `internal/status/class.go`:

```go
// Package status sorts HTTP status codes into their five classes.
package status

//go:generate go tool stringer -type=Class

// Class is the kind of answer a status code gives, named after its first
// digit.
type Class int

const (
	Informational Class = iota + 1 // 1xx
	Success                        // 2xx
	Redirection                    // 3xx
	ClientError                    // 4xx
	ServerError                    // 5xx
)

// Of returns the class of an HTTP status code, or 0 for a number outside
// 100 to 599.
func Of(code int) Class {
	if code < 100 || code > 599 {
		return 0
	}
	return Class(code / 100)
}
```

**`iota + 1` makes each constant equal to its first digit**, so `Of` is one division. The directive
asks for `go tool stringer` rather than a `stringer` on the `PATH`, which needs the tool recorded in
the module first. `go get -tool` does that, as lesson 5 section 03 mentioned in passing:

```
ana@vm:~/gen-hits$ go get -tool golang.org/x/tools/cmd/stringer@v0.52.0
go: added golang.org/x/mod v0.42.0
go: added golang.org/x/sync v0.24.0
go: added golang.org/x/tools v0.52.0
ana@vm:~/gen-hits$ cat go.mod
module example.com/hits

go 1.27.1

tool golang.org/x/tools/cmd/stringer

require (
	golang.org/x/mod v0.42.0 // indirect
	golang.org/x/sync v0.24.0 // indirect
	golang.org/x/tools v0.52.0 // indirect
)
```

**The `tool` line names the package, and the `require` block pins the module it comes from at
v0.52.0**, with the two modules that one needs. They are marked `// indirect` because no package of
`hits` imports them, and nothing in them is compiled into `hits` itself. Section 05 compares this with
the other ways a directive can name its generator.

## What stringer wrote

```
ana@vm:~/gen-hits$ go generate -x ./...
go tool stringer -type=Class
ana@vm:~/gen-hits$ cat internal/status/class_string.go
// Code generated by "stringer -type=Class"; DO NOT EDIT.

package status

import "strconv"

func _() {
	// An "invalid array index" compiler error signifies that the constant values have changed.
	// Re-run the stringer command to generate them again.
	var x [1]struct{}
	_ = x[Informational-1]
	_ = x[Success-2]
	_ = x[Redirection-3]
	_ = x[ClientError-4]
	_ = x[ServerError-5]
}

const _Class_name = "InformationalSuccessRedirectionClientErrorServerError"

var _Class_index = [...]uint8{0, 13, 20, 31, 42, 53}

func (i Class) String() string {
	idx := int(i) - 1
	if i < 1 || idx >= len(_Class_index)-1 {
		return "Class(" + strconv.FormatInt(int64(i), 10) + ")"
	}
	return _Class_name[_Class_index[idx]:_Class_index[idx+1]]
}
```

`go generate -x` printed the one command it ran, and stringer named its file after the type,
`class_string.go`, beside `class.go`. Read it from the bottom up:

- **All five names are one string**, 53 bytes, and `_Class_index` holds where each name starts and
  ends. `ClientError` is bytes 31 to 42. `String` subtracts the first constant's value, 1, and slices
  the string: two array reads and no map, no switch and no allocation.
- A value with no name, 0 or 6 or -3, fails the range check and comes back as `Class(0)`, `Class(6)`
  or `Class(-3)`. The number is formatted with `strconv` rather than `fmt`: inside `String`,
  formatting `i` with `%v` would call `String` again, and again, while `strconv.FormatInt` only
  sees an `int64`.
- `func _()` is never called. Its name is the blank identifier, so nothing can call it, and it exists
  to be compiled. The last part of this section breaks it on purpose.
- The first line is the header every generated Go file carries, with the command that made it. It
  is a convention with a precise form, and section 05 shows who reads it.

A program that uses it is short. It reads a log on standard input with lesson 1's `tally.Count` and
adds the counts up by class, in `cmd/classes/main.go`:

```go
// Command classes counts an access log's requests by the class of their
// status code. It reads standard input.
package main

import (
	"fmt"
	"os"

	"example.com/hits/internal/status"
	"example.com/hits/internal/tally"
)

func main() {
	s, err := tally.Count(os.Stdin)
	if err != nil {
		fmt.Fprintln(os.Stderr, "classes:", err)
		os.Exit(1)
	}
	byClass := map[status.Class]int{}
	for code, n := range s.ByStatus {
		byClass[status.Of(code)] += n
	}
	for c := status.Class(0); c <= status.ServerError; c++ {
		fmt.Printf("%-14v %5d\n", c, byClass[c])
	}
}
```

```
ana@vm:~/gen-hits$ go run ./cmd/classes < access.log
Class(0)           0
Informational      0
Success        10058
Redirection     2421
ClientError     4998
ServerError     2523
```

`%v` found the `String` method and printed names; without `class_string.go` the left column would
read 0 to 5. **The numbers add up to lesson 1's table**: `Success` is 7,554 + 1,256 + 1,248, the
`200`, `201` and `204` rows, and the four classes with requests make 20,000. The loop starts at 0 on
purpose, to show the fallback: `Of` answers 0 for a number outside 100 to 599, and 0 has no name.

## The guard that breaks the build

`func _()` indexes an array of length 1 with `Informational-1`, `Success-2` and so on. Those are
constant expressions, so **the compiler checks every index while compiling**, and each one is 0 only
while each constant still has the value stringer saw. Change the values without regenerating, here
by turning `iota + 1` into `iota` so that every constant drops by one:

```
ana@vm:~/gen-hits$ sed -i "s/iota + 1/iota/" internal/status/class.go && go build ./...; echo $?
# example.com/hits/internal/status
internal/status/class_string.go:11:8: invalid argument: index Informational - 1 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:12:8: invalid argument: index Success - 2 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:13:8: invalid argument: index Redirection - 3 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:14:8: invalid argument: index ClientError - 4 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:15:8: invalid argument: index ServerError - 5 (constant -1 of int type Class) must not be negative
1
ana@vm:~/gen-hits$ sed -i "s/= iota /= iota + 1 /" internal/status/class.go && go build ./... && echo built
built
```

**A stale `String` method became a compile error instead of a wrong name on a report.** Without the
guard, `Success` would now be 1, and the old `String` would subtract 1 and print `Informational` for
it. The comment inside `_()` promises an "invalid array
index" error and the compiler words it differently today, as "must not be negative"; the line it
points at is the same. The second `sed` put `+ 1` back, and the build passed again.

The guard has an edge. **It checks the constants stringer saw, and nothing else**: a sixth constant
added after `ServerError`, with the value 6, has no line in `_()`, so the build passes and `String`
sends it to the `Class(6)` fallback until somebody runs `go generate`. Changing the directive's flags
is invisible to it in the same way. Section 05's check in continuous integration catches both.
