title: O `stringer`, e um método que ninguém digita
version: 1
---

O `fmt` imprime um valor chamando o método `String() string` dele quando existe, e imprime o número
puro quando um tipo inteiro com nome não tem esse método. **O `stringer` escreve esse método para um
conjunto de constantes inteiras, a partir das próprias constantes**, então os nomes na tela são
sempre os nomes do código. É o gerador que a própria árvore de fontes do Go mais usa, e a árvore
desta máquina pode ser consultada:

```
ana@vm:~/gen-hits$ grep -r --include="*.go" "^//go:generate" $(go env GOROOT)/src | wc -l
132
ana@vm:~/gen-hits$ grep -r --include="*.go" "^//go:generate stringer" $(go env GOROOT)/src | wc -l
31
```

**31 das 132 diretivas da biblioteca padrão e do ferramental rodam o stringer**, para coisas como as
tags DWARF de `debug/dwarf` e os contextos de escape de `html/template`. Do resto, 78 são
`go run` sobre um programa Go, quase sempre guardado ao lado do pacote, escrevendo tabelas e
invólucros de chamadas de sistema, que é o formato da seção 04.

## Cinco classes de resposta

Um código de status HTTP diz que tipo de resposta é pelo primeiro dígito: 2 para sucesso, 4 para
erro do cliente, 5 para erro do servidor. O `hits` conta os códigos um a um, e um relatório por
classe fica a um passo dali. Esta seção trabalha numa cópia nova do módulo da lição 1, em
`~/gen-hits`: o pacote `tally` e o `main.go` da lição 1 seção 04, o `genlog` da lição 1 seção 03 e o
mesmo `access.log` de 20.000 linhas. O pacote novo é `internal/status/class.go`:

```go
// Package status sorts HTTP status codes into their five classes.
package status

//go:generate go tool stringer -type=Class

// Class is the kind of answer a status code gives, named after its first
// digit.
type Class int

const (
	Informational Class = iota + 1 // 1xx
	Success                        // 2xx
	Redirection                    // 3xx
	ClientError                    // 4xx
	ServerError                    // 5xx
)

// Of returns the class of an HTTP status code, or 0 for a number outside
// 100 to 599.
func Of(code int) Class {
	if code < 100 || code > 599 {
		return 0
	}
	return Class(code / 100)
}
```

**O `iota + 1` faz cada constante valer o seu primeiro dígito**, então o `Of` é uma divisão. A
diretiva pede `go tool stringer`, e não um `stringer` no `PATH`, o que exige registrar a ferramenta
no módulo antes. O `go get -tool` faz isso, como a lição 5 seção 03 mencionou de passagem:

```
ana@vm:~/gen-hits$ go get -tool golang.org/x/tools/cmd/stringer@v0.52.0
go: added golang.org/x/mod v0.42.0
go: added golang.org/x/sync v0.24.0
go: added golang.org/x/tools v0.52.0
ana@vm:~/gen-hits$ cat go.mod
module example.com/hits

go 1.27.1

tool golang.org/x/tools/cmd/stringer

require (
	golang.org/x/mod v0.42.0 // indirect
	golang.org/x/sync v0.24.0 // indirect
	golang.org/x/tools v0.52.0 // indirect

```

**A linha `tool` nomeia o pacote, e o bloco `require` fixa o módulo de onde ele vem na v0.52.0**,
junto com os dois módulos de que ele precisa. Eles aparecem como `// indirect` porque nenhum pacote
do `hits` os importa, e nada deles é compilado dentro do próprio `hits`. A seção 05 compara isso com
os outros jeitos de uma diretiva nomear o seu gerador.

## O que o stringer escreveu

```
ana@vm:~/gen-hits$ go generate -x ./...
go tool stringer -type=Class
ana@vm:~/gen-hits$ cat internal/status/class_string.go
// Code generated by "stringer -type=Class"; DO NOT EDIT.

package status

import "strconv"

func _() {
	// An "invalid array index" compiler error signifies that the constant values have changed.
	// Re-run the stringer command to generate them again.
	var x [1]struct{}
	_ = x[Informational-1]
	_ = x[Success-2]
	_ = x[Redirection-3]
	_ = x[ClientError-4]
	_ = x[ServerError-5]
}

const _Class_name = "InformationalSuccessRedirectionClientErrorServerError"

var _Class_index = [...]uint8{0, 13, 20, 31, 42, 53}

func (i Class) String() string {
	idx := int(i) - 1
	if i < 1 || idx >= len(_Class_index)-1 {
		return "Class(" + strconv.FormatInt(int64(i), 10) + ")"
	}
	return _Class_name[_Class_index[idx]:_Class_index[idx+1]]
}
```

O `go generate -x` imprimiu o único comando que rodou, e o stringer deu ao arquivo o nome do tipo,
`class_string.go`, ao lado do `class.go`. Leia de baixo para cima:

- **Os cinco nomes são uma string só**, de 53 bytes, e o `_Class_index` guarda onde cada nome começa
  e termina. `ClientError` vai do byte 31 ao 42. O `String` subtrai o valor da primeira constante, 1,
  e fatia a string: duas leituras de array, sem mapa, sem switch e sem alocação.
- Um valor sem nome, 0, 6 ou -3, falha na verificação de faixa e volta como `Class(0)`, `Class(6)`
  ou `Class(-3)`. O número é formatado com `strconv`, e não com `fmt`: dentro do `String`, formatar
  `i` com `%v` chamaria o `String` de novo, e de novo, enquanto o `strconv.FormatInt` só enxerga um
  `int64`.
- A `func _()` nunca é chamada. O nome dela é o identificador em branco, então nada consegue chamá-la,
  e ela existe para ser compilada. A última parte desta seção a quebra de propósito.
- A primeira linha é o cabeçalho que todo arquivo Go gerado carrega, com o comando que o produziu. É
  uma convenção de forma precisa, e a seção 05 mostra quem a lê.

Um programa que usa isso é curto. Ele lê um log da entrada padrão com o `tally.Count` da lição 1 e
soma as contagens por classe, em `cmd/classes/main.go`:

```go
// Command classes counts an access log's requests by the class of their
// status code. It reads standard input.
package main

import (
	"fmt"
	"os"

	"example.com/hits/internal/status"
	"example.com/hits/internal/tally"
)

func main() {
	s, err := tally.Count(os.Stdin)
	if err != nil {
		fmt.Fprintln(os.Stderr, "classes:", err)
		os.Exit(1)
	}
	byClass := map[status.Class]int{}
	for code, n := range s.ByStatus {
		byClass[status.Of(code)] += n
	}
	for c := status.Class(0); c <= status.ServerError; c++ {
		fmt.Printf("%-14v %5d\n", c, byClass[c])
	}
}
```

```
ana@vm:~/gen-hits$ go run ./cmd/classes < access.log
Class(0)           0
Informational      0
Success        10058
Redirection     2421
ClientError     4998
ServerError     2523
```

O `%v` encontrou o método `String` e imprimiu nomes; sem o `class_string.go`, a coluna da esquerda
mostraria de 0 a 5. **Os números batem com a tabela da lição 1**: `Success` é 7.554 + 1.256 + 1.248,
as linhas `200`, `201` e `204`, e as quatro classes com requisições somam 20.000. O laço começa em 0
de propósito, para mostrar o plano B: o `Of` responde 0 para um número fora de 100 a 599, e o 0 não
tem nome.

## O guarda que quebra o build

A `func _()` indexa um array de tamanho 1 com `Informational-1`, `Success-2` e assim por diante.
Essas são expressões constantes, então **o compilador confere cada índice durante a compilação**, e
cada um só vale 0 enquanto cada constante tiver o valor que o stringer viu. Mude os valores sem
regenerar, aqui trocando `iota + 1` por `iota` para que todas as constantes caiam um:

```
ana@vm:~/gen-hits$ sed -i "s/iota + 1/iota/" internal/status/class.go && go build ./...; echo $?
# example.com/hits/internal/status
internal/status/class_string.go:11:8: invalid argument: index Informational - 1 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:12:8: invalid argument: index Success - 2 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:13:8: invalid argument: index Redirection - 3 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:14:8: invalid argument: index ClientError - 4 (constant -1 of int type Class) must not be negative
internal/status/class_string.go:15:8: invalid argument: index ServerError - 5 (constant -1 of int type Class) must not be negative
1
ana@vm:~/gen-hits$ sed -i "s/= iota /= iota + 1 /" internal/status/class.go && go build ./... && echo built
built
```

**Um método `String` desatualizado virou erro de compilação, e não um nome errado num relatório.**
Sem o guarda, `Success` agora valeria 1, e o `String` antigo subtrairia 1 e imprimiria
`Informational` para ele. O comentário dentro de `_()` promete um erro de "invalid array index", e o
compilador hoje o escreve de outro jeito, como "must not be negative"; a linha apontada é a mesma. O
segundo `sed` devolveu o `+ 1`, e o build voltou a passar.

O guarda tem um limite. **Ele confere as constantes que o stringer viu, e nada mais**: uma sexta
constante acrescentada depois de `ServerError`, com valor 6, não tem linha em `_()`, então o build
passa e o `String` a manda para o plano B `Class(6)` até alguém rodar o `go generate`. Mudar as flags
da diretiva é igualmente invisível para ele. A verificação na integração contínua da seção 05 pega
os dois casos.
