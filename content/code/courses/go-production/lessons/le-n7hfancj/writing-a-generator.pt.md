Um gerador não é um tipo especial de programa. **É um programa Go comum que lê alguma coisa e
escreve um arquivo `.go`**, e a diretiva que o roda é uma linha. As 78 diretivas `go run` da árvore
de fontes do Go funcionam assim: um programa rodado a partir do fonte, sem passo de
instalação. Esta seção escreve um para o `hits`, pequeno o bastante para ser lido
inteiro.

## Uma lista que outra pessoa mantém

Todo caminho do site pertence a uma equipe, e a equipe que atende às três da manhã mantém a lista.
Eles não escrevem Go, e não deveriam precisar. A lista é um arquivo de texto,
`internal/owner/owners.txt`:

```
# Which team answers for which path: the path, then the team.
/                frontend
/static/app.js   frontend
/static/app.css  frontend
/login           accounts
/api/users       accounts
/api/orders      payments
/api/orders/42   payments
/health          platform
```

O que o `hits` quer é uma função de um caminho para uma equipe. Ela poderia ler o arquivo em tempo
de execução, e a última parte da seção 05 pesa essa opção. **Aqui a lista vira Go antes de o
programa ser compilado**: um mapa literal num arquivo gerado, com os erros da lista pegos por um
gerador que diz qual linha está errada. O gerador fica em `tools/genowners/main.go`, ao lado do
`genlog`:

O pacote que usa o mapa guarda a diretiva, e só a diretiva e uma função são escritas à mão.
`internal/owner/owner.go`:

```go
// Package owner says which team answers for a path of the site.
package owner

//go:generate go run example.com/hits/tools/genowners -in owners.txt -out owners_gen.go

// Of returns the team that owns path, or "nobody" for a path not on the
// list.
func Of(path string) string {
	if team, ok := byPath[path]; ok {
		return team
	}
	return "nobody"
}
```

**A diretiva nomeia o gerador pelo caminho de import**, `example.com/hits/tools/genowners`.
`go run ../../tools/genowners` também funcionaria, já que a diretiva roda em `internal/owner`, mas
quebra no dia em que alguém mover o pacote um nível abaixo; o caminho de import significa a mesma
coisa a partir de qualquer diretório do módulo. O `byPath` é usado aqui e ainda não está definido em
lugar nenhum, então, até o gerador rodar, o pacote não compila.

## Rodando

```
ana@vm:~/gen-hits$ go generate -x ./internal/owner
go run example.com/hits/tools/genowners -in owners.txt -out owners_gen.go
ana@vm:~/gen-hits$ cat internal/owner/owners_gen.go
// Code generated by genowners from owners.txt; DO NOT EDIT.

package owner

// byPath maps each path to the team that owns it.
var byPath = map[string]string{
	"/":               "frontend",
	"/static/app.js":  "frontend",
	"/static/app.css": "frontend",
	"/login":          "accounts",
	"/api/users":      "accounts",
	"/api/orders":     "payments",
	"/api/orders/42":  "payments",
	"/health":         "platform",
}
ana@vm:~/gen-hits$ gofmt -l internal/owner; echo $?
0
```

O `package owner` veio do `$GOPACKAGE`, e o cabeçalho cita `owners.txt` porque foi isso que a
diretiva passou em `-in`. Compare as entradas com o template que as escreveu. **O template pôs cada
entrada no começo da linha, com um espaço depois dos dois-pontos; o arquivo tem um tab na frente e
os valores alinhados numa coluna**, e isso é o `format.Source`. O `gofmt -l` lista os arquivos que
mudaria e não listou nenhum. Um gerador que pula esse passo escreve arquivos que a verificação de
formato da lição 6 reprova a cada execução. A correção tem de ir no gerador, já que uma edição na
saída dura até o próximo `go generate`.

O mapa em uso, no `cmd/teams/main.go`, que conta o log por equipe:

```go
// Command teams counts an access log's requests by the team that owns each
// path. It reads standard input.
package main

import (
	"fmt"
	"maps"
	"os"
	"slices"

	"example.com/hits/internal/owner"
	"example.com/hits/internal/tally"
)

func main() {
	s, err := tally.Count(os.Stdin)
	if err != nil {
		fmt.Fprintln(os.Stderr, "teams:", err)
		os.Exit(1)
	}
	byTeam := map[string]int{}
	for path, n := range s.ByPath {
		byTeam[owner.Of(path)] += n
	}
	for _, team := range slices.Sorted(maps.Keys(byTeam)) {
		fmt.Printf("%-9s %5d\n", team, byTeam[team])
	}
}
```

```
ana@vm:~/gen-hits$ go run ./cmd/teams < access.log
accounts   5088
frontend   7503
payments   5045
platform   2364
```

As quatro equipes respondem pelas 20.000 linhas, e nenhuma linha caiu em `nobody`, porque todo
caminho que o `genlog` escreve está na lista. `frontend` é a maior porque é dona de três dos oito
caminhos.

## Quando a lista está errada

Alguém acrescenta uma linha para `/login` sem notar que ela já existe, e a próxima pessoa a gerar
descobre:

```
ana@vm:~/gen-hits$ echo "/login  security" >> internal/owner/owners.txt && go generate ./internal/owner; echo $?
genowners: owners.txt:10: /login is already on line 5
exit status 1
internal/owner/owner.go:4: running "go": exit status 1
1
ana@vm:~/gen-hits$ sed -i "\$d" internal/owner/owners.txt && go generate ./internal/owner && echo regenerated
regenerated
```

Três programas se manifestaram, cada um com suas palavras. **A primeira linha é do gerador**, citando
o arquivo e as duas linhas envolvidas. `exit status 1` é o `go run`, repassando o status do filho. A
terceira linha é o go generate, citando a diretiva que falhou, `owner.go:4`, e parando; ele saiu com
1 por sua vez, então um script ou um passo de CI que roda `go generate` também para. O
`owners_gen.go` não foi tocado, porque o `run` só grava depois de tudo lido e formatado. O `sed`
tirou a última linha, e o gerador voltou a rodar sem erro.

**Faça um gerador tão rigoroso quanto um compilador**, porque ele é o único lugar em que o erro ainda
está nos termos de quem lê. Sem a verificação de duplicata, o template teria escrito duas chaves
`"/login"`, e o build falharia depois, dentro de um arquivo que ninguém edita, com
`duplicate key "/login" in map literal` apontando para o `owners_gen.go`.
