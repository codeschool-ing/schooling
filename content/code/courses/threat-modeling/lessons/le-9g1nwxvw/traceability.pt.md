title: Rastreabilidade
version: 1
---

**Rastreabilidade** é conseguir seguir cada ameaça até os requisitos que respondem a ela, e cada
requisito até a evidência de que ele vale. O valor prático cabe numa frase: **ela acha a ameaça que
ninguém cobriu e o requisito que ninguém confere**, e os dois são invisíveis numa lista de requisitos
lida sozinha.

A ligação são dois arquivos CSV e um programa curto. O `trace.py` lê os dois, registra cada requisito
sob cada ameaça que ele cita, e imprime o que acha:

```schooling-example
{"language": "python", "file": "trace.py", "parts": [{"code": "#!/usr/bin/env python3\n\"\"\"Join threats to requirements: what covers each threat, and what is not covered or not verified.\"\"\"\nimport csv\n\nthreats = {row[\"id\"]: row for row in csv.DictReader(open(\"threats.csv\"))}\nrequirements = list(csv.DictReader(open(\"requirements.csv\")))\n", "note": "Dois arquivos CSV, lidos com a biblioteca padrão. As ameaças ficam guardadas por id para que um requisito as encontre."}, {"code": "covered = {tid: [] for tid in threats}\nfor req in requirements:\n    for tid in req[\"threats\"].split():\n        covered[tid].append(req)\n", "note": "Toda ameaça começa com uma lista vazia, e cada requisito entra na lista de cada ameaça que ele cita. Um id de ameaça que não existe para o programa aqui."}, {"code": "for tid, reqs in covered.items():\n    ids = \", \".join(f\"{r['id']} ({r['verified by'] or 'not verified'})\" for r in reqs)\n    print(f\"{tid}  {threats[tid]['stride']}  {ids or '-- no requirement'}\")\n", "note": "Uma linha por ameaça: a letra dela, e os requisitos com o modo de verificação de cada um."}, {"code": "bare = [tid for tid, reqs in covered.items() if not reqs]\nunverified = [r[\"id\"] for r in requirements if not r[\"verified by\"]]\nprint(f\"\\n{len(threats)} threats, {len(requirements)} requirements\")\nprint(\"no requirement:\", \" \".join(bare) or \"none\")\nprint(\"not verified:  \", \" \".join(unverified) or \"none\")", "note": "As duas listas para as quais o programa existe: ameaças sem requisito, e requisitos que nada verifica."}]}
```

As duas últimas linhas são o motivo de rodá-lo. **A T14 não tem requisito, e o R14 e o R17 não são
verificados.** Cada uma é uma lacuna conhecida, e não esquecida, e o programa vai continuar dizendo
isso até os arquivos mudarem.

### Por que um programa e não uma planilha

Uma planilha com uma coluna de ids de ameaça faz a mesma ligação, uma vez. O programa faz toda vez que
roda, e a aula 15 o roda a cada pull request: uma ameaça nova acrescentada sem requisito, ou um
requisito cujo teste foi apagado, faz a verificação avisar no dia em que acontece. A ligação também
é conferida no outro sentido, pela própria construção: um requisito que cita um id de ameaça
inexistente para o programa com um erro, porque `covered[tid]` não tem essa chave, então um erro de
digitação num id não passa calado.
