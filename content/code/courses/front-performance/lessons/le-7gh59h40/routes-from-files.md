**Three of the four turn the folders of a project into its addresses, and the fourth declares them
in a list.** Next.js, Nuxt and SvelteKit read a folder of files and make a route of each, which is
called *file-based routing*. Angular writes its routes in `app.routes.ts`, as an array of paths and
components. Either way the same two addresses come out of it, and the next four sections write the files
that answer them in each project.

## The same two addresses, file by file

| address | Next.js | Nuxt | SvelteKit | Angular |
|---|---|---|---|---|
| `/` | `app/page.tsx` | `app/pages/index.vue` | `src/routes/+page.svelte` | `{ path: "" }` → `Home` |
| `/courses/git` | `app/courses/[slug]/page.tsx` | `app/pages/courses/[slug].vue` | `src/routes/courses/[slug]/+page.svelte` | `{ path: "courses/:slug" }` → `Course` |
| around every page | `app/layout.tsx` | `app/app.vue` | `src/routes/+layout.svelte` | `App`, with `<router-outlet />` |
| the data, on the server | `lib/plan.ts`, called by the page | `server/api/plan.get.ts` | `+page.server.ts` beside each page | `HttpClient`, sent to the browser with the page |

**A parameter is written `[slug]` in a file name and `:slug` in a list**, and in all four it reaches
the page as a string called `slug`. A request for `/courses/nonsense` matches the route in all four,
because the route only says the shape of the address. It is the page that has to find no such
course and say so, and the section "The same page, four ways" checks which of them answer 404.

## What file-based routing buys, and what it costs

A folder of routes can be read as a map of the site, and adding a page is adding a file. The router
is also known before the app runs, which is what lets a build list every route and decide, for
each, how to render it, as Next.js's build does at the end of its section.

The cost is a set of names with meanings. `page.tsx`, `+page.server.ts`, `[slug]`, `layout.tsx`,
`+layout.svelte`: a file in the wrong folder, or with a name one character off, is not an error,
it is a file that is not a route. A list of routes in code fails the other way: a mistyped
component name stops the build. Neither is better, and the one you learnt first will feel obvious.
