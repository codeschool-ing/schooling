The whole network is built by one script, `netlab.sh`, and here it is, all of it. Copy it with the
button in the corner of the listing, open an editor on a new file in your home directory with
`nano ~/netlab.sh`, paste, then `Ctrl+O` to save and `Ctrl+X` to leave. The notes beside the code say
what each part does; you do not need to understand all of it today, and most of it comes back in the
lesson that uses it.

## Building it

One command builds everything, and it prints nothing when it works. The second lists the machines, plus
`wire`, which holds the switches. The third opens a shell on one of them, `laptop`, and the prompt
changes to say so:

Your prompt carries your own user name where these transcripts say `ana`, the name of the person whose
work the course follows; on a Multipass machine it is `ubuntu`. Everything else is the same. `exit`
leaves a machine's shell and takes you back to `netlab`.

## The map

The table at the top of the script is the map, and it is worth reading once now. Six segments, each a
switch with the machines plugged into it:

| segment | network | machines, by the last part of their address |
|---|---|---|
| `hq` | `192.168.10.0/24`, the head-office LAN | `hq` .1, `hq2` .3, `files` .10, `laptop` .20 |
| `hqwan` | `203.0.113.0/24`, head office to the ISP | `hq` .2, `hq2` .3, `isp` .1 |
| `branch` | `192.168.20.0/24`, the branch LAN | `branch` .1, `till` .30 |
| `net` | `198.51.100.0/24`, the branch and the home to the ISP | `branch` .2, `homegw` .77, `isp` .1 |

The three public ranges are the ones reserved for documentation, and the names, `example.com` and
`example.net`, are reserved the same way. **Nothing in this network reaches the internet**, and nothing
on the internet reaches it.

## Working in it

**Every transcript says which machine it was typed on.** A line starting `ana@hq:~$` was typed in a
shell on `hq`, opened with `sudo bash netlab.sh shell hq`; a line starting `ana@netlab:~$` was typed on
the virtual machine itself, outside every namespace. When a lesson captures on one machine while
another sends traffic, that is two terminals, one shell on each.

**Every lesson starts from a fresh network.** Run `sudo bash netlab.sh reset` before you begin one: it
takes everything down and builds it again, so what an earlier lesson changed cannot change what this
one prints. When you are finished for the day, `sudo bash netlab.sh down` removes it all; a reboot of
the virtual machine removes the machines too, and `up` brings them back.

**Times in the transcripts are not a network's.** Every link here is one computer copying memory, so a
round trip takes a fraction of a millisecond and a bandwidth test reaches gigabits. The lessons say so
wherever a time is read, and they read the shape of a result rather than its decimals: yours will
differ in the decimals and agree in everything else.

**Three things in this network are done in user space rather than in the kernel**: the GRE and IP-in-IP
tunnels of this lesson, WireGuard, and IPsec's encryption. The machine the course was recorded on had a
kernel built without them, as some online environments do, so the course uses programs that work on
any kernel. Your Ubuntu has all of them in the kernel; each lesson says where that changes a line of
output, and on the wire it changes nothing.
