---
title: Symptom, hypothesis, test, result, fix
version: 1
---

An incident record has five fields, and each one exists because leaving it out loses something the next
reader cannot get back. Here they are, filled in from lesson 21's case:

| field | what it holds | lesson 21's case |
|---|---|---|
| symptom | what was observed, measured, before anybody explains it | the page `/` returns `200 16 bytes`; `big.bin` gets 0 bytes in 8002 ms |
| hypothesis | one cause, stated so that a test could prove it wrong | packets bigger than the tunnel's MTU are being lost |
| test | the exact command, the machine it ran on, and what would refute the hypothesis | `ping -M do -s 1392` and `-s 1400` from `files` to the till |
| result | what the test printed, pasted rather than summarised | 1392 crosses; 1400 is lost with no error; `wg0` has `mtu 1420` |
| fix | the change, where it was made, and the test that proves it worked | MSS clamped to 1380 on `hq`; `big.bin` returns `200 20000000 bytes` |

**The symptom is an observation, not a diagnosis.** "The VPN is broken" is somebody's first theory
wearing the clothes of a fact, and the record that starts with it has already ruled out everything else.
"The page opens and the download never finishes" is what the branch saw, and the two curl lines are the
same thing measured. Both belong in the record: the user's words are what the next person will search
for, and the measurement is what they will compare against.

**A hypothesis is one cause, and the record keeps the ones that were wrong**. In lesson 21 the small page
refuted a whole family at once: the name, the route, the tunnel and the web server were all working, or
16 bytes could not have arrived. Writing that down saves the next person checking the same four things
again. A refuted hypothesis is a result, and often the most useful one in the record.

**A test names its machine.** `ping -M do -s 1400` from `files` and the same command from the till cross
the tunnel in opposite directions and hit different routers' rules, so the record says where it ran.
Lesson 21 ran only the first. It also says what would count against the hypothesis before the result is in, which is what keeps a
result from being read to fit.

**A result is pasted.** "The big ping failed" loses the detail that solved the case: the statistics line
had no `+1 errors`, where lesson 1's tunnel had printed `Frag needed`. Nobody summarising knows yet which
detail will matter, so the record keeps the output as it was printed.

**A fix is verified by the test that found the fault.** The download that got 0 bytes is the download
that has to arrive whole. A ping, or the small page, worked all along and proves nothing about the fix.

The five fields are a loop rather than a list. A result either confirms a hypothesis or sends you back to
write the next one, and a fix that fails its verification is a result too:
