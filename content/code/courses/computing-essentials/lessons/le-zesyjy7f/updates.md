---
title: Updates, which are cheap and get postponed
version: 1
---

A security update exists because somebody found a way in and it was fixed. The moment that fix is
published, the problem it fixes becomes **public knowledge**, and tools to use it against
unpatched machines appear within days.

So the window is not *am I interesting enough to attack*. Nobody is choosing you. It is automated,
it is indiscriminate, and the only question is whether your machine is one of the ones still
standing open.

## What to turn on, and leave on

- **The operating system: automatic, and let it restart.** The update that is downloaded and never
  applied is the same as no update, and *restart later* pressed for six weeks is the common case.
- **The browser: automatic.** It is the program that runs code from strangers all day, which makes
  it the single most important thing on the machine to keep current.
- **The phone: automatic**, and the same argument doubled, because it is the thing holding the
  second factor.

## And the part that is not automatic

**A device that has stopped receiving updates is a different situation**, and it arrives quietly:
a phone after four or five years, a router after three, a machine whose system version is no
longer supported.

Nothing breaks on the day support ends. What changes is that from then on, every new problem found
stays open forever. A phone that no longer updates is fine for music and a torch, and should not
be the thing that receives your bank's codes.

## The one legitimate reason to wait

Updates occasionally break things — a driver, a program somebody depends on, a machine that will
not start. This is real and it is rare, and it is why *wait a week before a major version* is a
reasonable habit for a work machine.

Two things about that. **It applies to feature updates, not to security ones**, and the difference
is usually stated. And a week is a week: *I will do it later* is not a risk calculation, it is the
thing that produces a machine three years behind.

## What an update is not

It is not a performance fix, it is not a cause of slowness, and it is not what is filling the
disk. Those beliefs are common and they cost people the cheapest defence there is.

**The exception is honest**: a machine near the end of its life genuinely does run a newer system
less comfortably, and that is a reason to plan a replacement rather than to stop updating the one
that holds your e-mail.
