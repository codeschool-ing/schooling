A backup answers *is the file still there*. This section answers the question underneath it,
which is *can anything still open it*.

Both matter and only one of them is usually thought about. A perfectly preserved file in a format
nothing reads is a preserved file you cannot have back.

## The twenty-year test

Ask of anything you intend to keep: **if the company that makes this program stops existing, what
opens the file?**

| | opens in twenty years | why |
|---|---|---|
| `.txt`, `.md`, `.csv` | certainly | the format is the characters. Anything reads it |
| `.pdf` | very probably | an open standard with dozens of implementations |
| `.jpg`, `.png` | very probably | the same, and universally implemented |
| `.docx`, `.xlsx` | probably | published standards, zip archives of XML underneath |
| `.psd`, `.ai`, `.indd` | only with that company's program | proprietary, and undocumented on purpose |
| a note in an app | often not at all | the format is whatever the app's database is |

The last row is the one to watch, because it is where most people's notes and journals now live.
**A note-taking application that cannot export to files is a filing cabinet with no door**, and
the export is the thing to test before you have five years of notes in it.

## The rule, in one line

**Work in whatever is comfortable; archive in something plain.**

Nobody is asking you to write in a text editor. The point is that when a document is finished,
the copy you are keeping for ten years should be a format that does not depend on one vendor
remaining in business and one file version remaining supported.

For most things that means **exporting a PDF beside the original** — the editable file for the
day you need to change it, the PDF for the day you need to read it.

## PDF/A, which is the archival one

A plain PDF can refer to fonts it does not contain and to content it fetches. `PDF/A` is the
subset made for keeping: everything embedded, nothing external, no scripting. Most programs offer
it in the export dialogue and almost nobody uses it.

It is what public archives require, and it is the right answer for a contract, a diploma or
anything else you want to open exactly as it looks today.

## Paper, and what scanning it is for

Scanning a document does two jobs, and only the second one needs any care:

- **A photograph of the page** proves what it said. Any resolution above 200 dpi manages this.
- **A searchable document** needs text recognition, and it is what makes a folder of a thousand
  scans usable instead of decorative.

Lesson three said that OCR invents plausible words when it fails and that the failure does not
look like one. For an archive, that means **keeping the picture as well as the text** — which is
what a searchable PDF is: the scan you can read and a text layer underneath it you can search.

## And the last idea in this course

Everything since lesson one has been about a machine: the parts, the ports, the radios, the
files. This is the only part of it that is about **time**.

A machine lasts five years. A format lasts as long as somebody keeps implementing it. **Your
documents should be readable by the person you will be when none of the hardware in this course
exists** — and the way to arrange that is the same three sentences: a plain format, a copy that
does not change when the original does, and one of them somewhere else.
