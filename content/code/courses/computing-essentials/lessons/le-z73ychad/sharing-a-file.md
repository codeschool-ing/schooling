---
title: Sharing a file, which is not the same as sharing a document
version: 1
---

The last lesson's sharing was a document on a server: one copy, several people in it, edits
merged as they happen. **This is different.** A link to a file in a synced folder is a link to a
*file*, and what the other person gets is a copy.

| | a shared document | a shared file |
|---|---|---|
| what the recipient opens | the same copy you have | a download, or a preview |
| what happens when they edit | you see it as they type | nothing reaches you |
| how many copies exist | one | as many as have been downloaded |
| what revoking does | ends their access at once | stops new downloads |

**That last row is the one to carry.** Turning off a link stops anybody fetching the file again;
it does not reach the copies already on other people's disks. Sharing a file is a decision you
cannot fully undo, and it is a different decision from sharing a document.

## The settings, which are the same three everywhere

- **Specific people**, by e-mail. The only one that produces a list you can audit.
- **Anyone with the link**, which means exactly what it did last lesson: forwarded, archived,
  found.
- **A password and an expiry date**, on OneDrive and Drive with a paid plan, and on iCloud for
  some link types. Where it is available, use it on anything sent outside the building.

And one that is specific to files: **a link to a folder shares everything in it, now and later.**
Which is the same trap as last lesson, with the extra wrinkle that your own machine keeps putting
files in there.

## What happens when you move or rename the file

This catches people once and expensively.

- **Moving a file within your own Drive keeps the link working.** The link points at an
  identifier, not a path — which is the same distinction lesson seven made about ids and names.
- **Moving it out of the synced folder breaks it**, because the file is no longer in the account.
- **Deleting and re-uploading a file with the same name breaks it**, because it is a different
  file with a different identifier. The link does not fail helpfully; it says the file does not
  exist, to somebody who can see it in their own folder.

The habit that avoids all three: **replace the contents rather than the file.** *Manage versions*
on Drive, and simply saving over it in OneDrive and iCloud, keep the identifier and therefore
keep every link anybody has.

## The shared-with-me trap

A file somebody shares with you appears in *Shared with me* and **is not in your Drive** and does
not count against your quota. Adding a shortcut to it puts it in your folders without copying it.

Which means three things at once:

- **It is not yours.** The owner deleting it removes it from your view, with no warning and no
  copy.
- **It is not backed up by you**, because it is not in your folder for any backup to find.
- **Making a copy makes it yours**, at the cost of it no longer being the same file as theirs —
  which is the four-file problem from the last lesson, arriving through a different door.

For anything you depend on and do not own, make the copy deliberately and know that you have.
