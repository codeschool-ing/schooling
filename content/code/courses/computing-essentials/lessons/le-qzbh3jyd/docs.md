Everything the last lesson said about structure applies here unchanged: **a heading is a heading
because it is marked as one**, a contents page falls out of it, and the outline in the left margin
is the navigation pane under another name.

What differs is scope. Docs has perhaps a fifth of Word's features, and for most documents that
is the correct fifth.

| | Docs | Word |
|---|---|---|
| styles | a handful, edited in place | a full system with inheritance |
| sections and page setup | one layout, mostly | section breaks and everything they enable |
| references and citations | basic, plus add-ons | bibliographies, cross-references, captions |
| mail merge | an add-on | built in |
| collaboration | the reason it exists | possible, through a server |
| offline | arranged in advance | it is a file, so always |

**The honest summary is that Docs is better at the thing people actually do and worse at the
things that appear on page four hundred of a manual.** A letter, a report, a set of notes, a
proposal: Docs. A thesis with numbered figures, a book with section-dependent headers, a mail
merge to six hundred addresses: Word.

## Setting a style, which is done the other way round

In Word you edit the style and everything follows. In Docs you **format one paragraph the way you
want it, then choose the style menu, then *Update Heading 1 to match***.

Same result, opposite order, and it catches everybody once. There is also *Options, Save as my
default styles*, which carries your choices into new documents — the nearest thing Docs has to a
template, and worth doing once.

## The three things Docs has that Word does not

- **`@` anywhere.** Typing `@` offers people, documents, dates and a menu of blocks — a table, a
  checklist, a dropdown. It is the fastest thing in the product and almost nobody uses it.
- **Comments that become tasks.** Assigning a comment to somebody puts it in their list and mails
  them. A comment nobody owns is a comment nobody answers.
- **Version naming.** *File, Version history, Name current version* marks a point you can return
  to by name rather than by hunting through timestamps. Do it before a large edit, not after.

## Exporting, and what the export is

*File, Download* produces a `.docx`, a `.pdf`, an `.odt`, plain text or a web page. The `.docx` is
a **translation**, not the document: Google renders its model into Microsoft's, and the two do not
have the same features.

What survives cleanly: text, headings, lists, tables, images, comments. What moves: precise
spacing, some table borders, anything from an add-on, and page breaks in a long document.

**For anything that will be read rather than edited, send the PDF.** It is the same advice as the
last lesson's fonts problem, for the same reason: a format that has already made all the layout
decisions cannot make a different one on somebody else's machine.
