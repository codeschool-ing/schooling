---
title: Por que uma posição não é uma identidade
version: 1
---

**Uma linha identificada pela posição muda de identidade sempre que uma linha acima dela é inserida
ou apagada, e tudo o que o SwiftUI guardou para ela vai com a posição, não com a linha.** A crença a
largar é que identidade só importa para animação. Ela importa para estado: o `@State` de uma linha, o
texto meio digitado de um campo, se as notas dela estão abertas, qual linha está selecionada. O
SwiftUI guarda isso pela identidade, e uma identidade que se move leva tudo para a linha errada.

Dá para mostrar isso sem o SwiftUI, porque a pergunta é só *a que linha pertence este estado*. Crie um
diretório, `~/rows`, e salve isto como `identity.swift` nele:

**Depois de apagar, as notas abertas foram para `SQL, indexes`**, uma linha que a pessoa nunca tocou,
enquanto `Mobile, lifecycle` fechou. Nada no programa estava errado, só a escolha da chave. Guardado
pelo id, o estado ficou na sua linha.

Numa lista de verdade os sintomas são os mesmos e mais difíceis de rastrear: um toggle que pula para a
linha seguinte depois de apagar, um campo de texto mostrando o rascunho de outra, uma linha que não
anima ao sair porque o SwiftUI viu o conteúdo mudar em vez de a linha sumir. Todos vêm de escrever
`ForEach(0..<plan.sessions.count)` ou `ForEach(Array(plan.sessions.enumerated()), id: \.offset)` em
vez de `ForEach(plan.sessions)`.
