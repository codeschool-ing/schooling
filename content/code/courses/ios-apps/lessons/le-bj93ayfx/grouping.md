**Every element on the screen is a stop for VoiceOver, and a screen with too many stops is a screen
nobody finishes.** The session row in section 02 draws a title, a number, a unit and an icon. Left
alone, SwiftUI could make it four stops: *SQL Databases*, *50 min*, whatever the image says about itself, and so on for
every row of the week. Grouping decides how many stops a piece of the screen makes and what each one
says. Nothing in this section was run; it follows Apple's documentation for
`accessibilityElement(children:)`, read on 30 October 2026, where the default is `.ignore`.

The modifier takes one of three behaviours for the children of the view it is applied to:

- **`.ignore`**, the default: the view becomes one element and its children say nothing. You then
  give it a label and a value yourself, which is what section 02's row does. It is the choice when
  the sentence you want is not the children's words in order.
- **`.combine`**: one element, whose label is the children's labels joined. It is the quick choice
  when the children already read well in order, a name and an address.
- **`.contain`**: the children stay separate elements, grouped as a container that VoiceOver can
  enter and leave. It is the choice for a card with two buttons in it, where each button must stay
  its own stop.

**A row with a button inside it cannot be `.ignore`d**, or the button disappears for VoiceOver. The
planner's course row in `CourseListView` has a title, the week's minutes and a button to add a
session; it is `.contain`, so the person hears the course, and then the button, as two stops that
belong together.

## Hiding what is not information

A decorative image, a divider, a background shape: each is a stop that says nothing useful.
`Image(decorative:)` makes an image that VoiceOver skips, and `.accessibilityHidden(true)` hides any
view. **Hide only what carries no information.** The tick in the session row looks decorative and
is not: it is whether the session is done, which is why section 02 moved it into the value rather
than deleting it.

The order of the stops follows the layout, leading to trailing and top to bottom. Where the layout
reads in the wrong order, `.accessibilitySortPriority` reorders the stops without moving anything on
the screen.
