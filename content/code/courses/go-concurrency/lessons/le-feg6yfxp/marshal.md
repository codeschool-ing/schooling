JSON is how most programs written today talk to each other, and `encoding/json` is how a Go
program speaks it. **The package works from your types: you describe the data once, as a struct,
and the same description serves for writing JSON out and for reading it back in.** This section is
the writing half. The work of this lesson lives in `~/jsondemo`, made with
`go mod init example.com/jsondemo`, and the first program is an order with two items, saved as
`order.go`:

## What each line of output says

**The first line is the whole order as compact JSON**, and every rule in the type shows up in it.
The keys are the names the tags gave, `price_cents` and not `Cents`. The slice became an array and
each `Item` an object inside it. The time became `"2026-10-16T14:30:00Z"`, the RFC 3339 form,
because `time.Time` knows how to write itself as JSON; lesson 20 says more about times. There is no
`note`, because `omitempty` removed the empty string, and no `internal`, because nothing outside the
package can see an unexported field, `encoding/json` included.

**The indented block is the same kind of value written by an `Encoder`**, straight to standard
output. `Encode` also writes a newline after each value, which is why one JSON value per line, a
format called JSON Lines, is the natural thing for an `Encoder` to produce.

**The last line is the refusal.** `json: unsupported type: chan bool`: a channel, a function and a
complex number have no JSON form, and asking for one is an error rather than an empty value.

## The tag, in full

A tag is a string the compiler stores beside a field and `encoding/json` reads at run time. Its
format is the key, then a comma and the options:

| tag | effect |
|---|---|
| `json:"sku"` | the key is `sku` |
| `json:"note,omitempty"` | the key is `note`, and the field is left out when it holds its zero value |
| `json:"retired,omitzero"` | left out when it is the zero value, judged in a way section 04 shows matters |
| `json:"-"` | never written and never read, whatever its value |
| `json:",string"` | a number or a bool written inside a string, `"42"` instead of `42` |

**`json:"-"` is how a field that must not leave the program is kept in**, a password hash or an
internal identifier, when the field has to be exported for other reasons. A misspelled tag is not
an error the compiler sees; `go vet` checks that each tag has the right shape, which is one more
reason to run it.
