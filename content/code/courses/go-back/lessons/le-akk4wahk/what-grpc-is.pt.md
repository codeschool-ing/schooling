Tudo o que o boxoffice respondeu até aqui foi REST: um cliente escolhe um caminho e um método, manda
JSON e lê um status e mais JSON. **O gRPC parte de outra imagem: o cliente chama uma função, e a função
roda em outra máquina.** O código do cliente diz `client.GetEvent(ctx, req)` e recebe de volta um
`*Event` ou um erro, como se o servidor fosse um pacote importado. Tudo o que fica no meio, a conexão,
a codificação, o caminho por onde a requisição viaja, pertence à biblioteca.

Três escolhas fazem isso funcionar, e cada uma é o oposto de algo que o REST deixa livre:

- **O contrato vem primeiro, e é obrigatório.** Um arquivo `.proto` declara cada função, o argumento
  e o resultado dela, numa linguagem própria, e **tanto o servidor quanto os clientes são gerados a
  partir dele**. Uma API REST tem uma descrição OpenAPI ou nenhuma; um serviço gRPC não existe sem o
  seu `.proto`.
- **As mensagens são Protocol Buffers**, uma codificação binária compacta em que cada campo é um
  número, não um nome. A seção 04 conta os bytes.
- **O transporte é HTTP/2**, sempre. Uma conexão carrega muitas chamadas ao mesmo tempo, e uma chamada
  pode ser um fluxo de mensagens em qualquer sentido, e é assim que o gRPC oferece quatro tipos de
  chamada onde o REST tem um.

| tipo | o cliente manda | o servidor manda | o exemplo do boxoffice |
|---|---|---|---|
| **unária** | uma mensagem | uma mensagem | `GetEvent`: um id entra, um evento sai |
| **streaming do servidor** | uma mensagem | muitas, ao longo do tempo | `Watch`: um id de evento entra, a disponibilidade dele sai a cada mudança |
| **streaming do cliente** | muitas | uma, no fim | `Scan`: os ingressos mostrados na porta, um a um, depois um resumo |
| **bidirecional** | muitas | muitas, de forma independente | um chat; o boxoffice não tem nenhuma |

## Para quem é o gRPC do boxoffice

Navegadores não falam gRPC diretamente, um ponto a que a aula 11 volta. **O gRPC é para programas
conversando com programas**: os leitores de ingresso na porta, um painel na bilheteria, outro serviço
da casa que precisa saber o que foi vendido. Esta aula dá ao boxoffice uma segunda porta para eles, um
serviço chamado `Seats` na porta 9090, ao lado da API HTTP na 8080, compartilhando o mesmo store. A aula
11 pergunta quando uma segunda porta dessas vale a pena.
