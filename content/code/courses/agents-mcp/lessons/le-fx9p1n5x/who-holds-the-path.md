In `automation.py` the sequence is the source code, read top to bottom. In `assistant.py` there is one step, and what follows it belongs to a person. In `agent.py` the source code contains no sequence at all, only a loop that asks the model what to do and does it. **The path exists only at run time**, which is why the same file took three steps for Bia, three different ones for Caio and two for the payment question.

## Workflows and agents

Anthropic's engineering article *Building effective agents* (December 2024) drew the line this course uses, and most of the field has adopted it. A **workflow** is a system where models and tools are joined by paths written in code, and an **agent** is a system where the model directs its own process and its own use of tools. A workflow can call a model at several steps; what makes it a workflow is that the programmer chose the order.

That article's advice is also lesson 2's: start with the simplest arrangement that works, and give the model control of the path only when the path cannot be written down in advance.

## Autonomy is a dial, not a switch

Between "the programmer decided everything" and "the model decides everything" lie many systems, and each sits somewhere along that line depending on how many decisions it hands over:

| decision | handed to the model in |
|---|---|
| which of a few fixed branches to take | a router: classify the message, then run the procedure for its class |
| what arguments a fixed step gets | extraction: read the message and fill in the order id |
| which tool to call next | a loop like `agent.py` |
| whether to stop | a loop like `agent.py`, inside the limit its host sets |
| which tools exist at all | an agent that writes and runs code, which this course does not build |

**Each row is a decision you can keep or give away separately.** `agent.py` gives away the choice of tool and the choice of when to answer, and keeps the number of steps: `range(1, 6)` is the programmer's, and no reply from the model can change it. Lesson 5 is about the decisions an agent should not be handed, and lesson 17 about the ones that should need a person's yes.

## The wrong picture, named

The common belief is that an agent is a model that has become capable enough to be trusted with actions. The model in `agent.py` is the same one `assistant.py` calls. What changed is the program around it: a loop, two tools, and an `if` that reads `stop_reason`. **Agency is a property of the program, not of the model.** Any model that can return a structured request for a tool can sit inside that loop, and a weak one will make the loop take worse decisions, faster.
