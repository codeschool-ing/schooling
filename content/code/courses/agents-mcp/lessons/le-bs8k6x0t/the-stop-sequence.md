A language model continues text. Asked for the next step of a transcript in which every `Action:` line has been followed by an `Observation:` line, the most likely continuation of an `Action:` line is an `Observation:` line, and the model has no way to know the program meant to write that one itself. **The invented observation in section 03 is not a malfunction; it is the model doing what it does, in a place where the program needed it to stop.**

A **stop sequence** is a string the provider watches for while it generates. The moment the text being produced would contain it, generation ends, the reply is returned without it, and `stop_reason` says `stop_sequence`. Anthropic's API takes `stop_sequences`, OpenAI's Chat Completions takes `stop`, Gemini takes `stopSequences` in its generation config; labllm implements all three, cutting the scripted reply exactly where a provider would. Putting `Observation:` in that list makes the provider enforce the rule the prompt could only ask for: the model writes thoughts and actions, and the program writes observations.

## Not the whole fix

A stop sequence handles the case it names. Three things remain the parser's job, and a careful one does all three:

- **Read only the first action.** If a model writes two `Action:` lines before stopping, run the first and discard the rest; the second was chosen without seeing the first one's result.
- **Distrust an `Answer:` that comes after an `Action:` in the same reply.** It was written before the action ran, so it cannot depend on its result. `react_text.py` checks for `Answer:` first, which is why the first run believed it; checking for an action first, and running it, is the safer order.
- **Refuse what does not parse.** `Action: get_order M-1047`, with no brackets, matches nothing; `action.group(1)` would raise. A production parser returns a short error as the observation (*"could not read the action; use tool[argument]"*) and lets the model try again, which is section 08's subject.

## Why native calls make this rarer

With native tool calling, the model's reply ends at the tool call by construction: the provider returns a `tool_use` block and stops, and the next thing in the conversation can only be what the program sends. There is no transcript for the model to continue, and no `Observation:` line to imitate. That is the main practical reason the industry moved from text ReAct to native calls, and section 05 shows the same task that way.
