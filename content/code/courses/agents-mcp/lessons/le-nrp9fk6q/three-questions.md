---
title: Three questions
version: 1
---

Every lesson since lesson 4 has added a boundary somewhere: a schema the arguments must fit, a step limit, a person before a refund, a hook, a callback, a token with a scope. This lesson puts them together under three questions, which are the ones to ask of any agent that can act.

1. **What may this agent do?** Not what it is likely to do, or what its instructions say it should do: what it is able to do if it asks. That is the set of tools it is offered and the permissions behind each one.
2. **What could it be led to ask for?** A model reads text it did not write: customers' messages, tool results, help articles, tool descriptions from servers (lesson 11). Some of that text may contain instructions. The answer to this question is never "nothing", so the first answer has to be small enough to live with.
3. **What happens when it is wrong?** Which actions need a person, which are refused in code whatever anybody says, and what is written down so that a wrong action can be found and undone.

**Least privilege** is the rule that ties them together: give each agent the smallest set of tools, and each tool the smallest access, that does its job. It is the same rule lesson 9 applied when it removed twenty built-in tools a support agent had no use for, lesson 12 when it gave a server three environment variables instead of thirty-five, and lesson 16 when the support agent's token could read and not refund.
