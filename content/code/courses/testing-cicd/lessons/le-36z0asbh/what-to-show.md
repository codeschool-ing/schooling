---
title: What a test should show, and what it should hide
version: 2
---

Factories hide data. That is their purpose, and it can be overdone. A test is read far more often
than it is written, usually by somebody trying to understand why it just failed, and they need to
see **every value the outcome depends on**, and none of the values it does not.

## The mystery guest

The classic failure has a name, the **mystery guest**: a test whose result depends on data defined
somewhere the reader cannot see. Suppose the factory's default weight were the one that decides a
test about weight bands:

```python
def test_a_heavy_parcel_pays_two_extra_bands():
    q = a_quote()
    assert freight(q["cep"], q["weight_g"], 5000) == 2190
```

The test passes, and nobody reading it can tell why 2190 is right. The answer depends on 1200 g,
which lives in another file. Change the factory's default to 800 g for some unrelated test, and this
one fails for no reason its own lines show. **A value the assertion depends on belongs in the test.**
The fix is one argument, `a_quote(weight_g=1200)`, or no factory at all.

## Irrelevant detail

The opposite failure is a test that spells out everything:

```python
def test_a_saved_quote_comes_back_by_id(store):
    quote_id = store.save("01310100", 1200, 2190, "2026-10-05T13:30:00-03:00")
    assert store.get(quote_id)["cents"] == 2190
```

This is the store test as lesson 1 wrote it, and it is not wrong. But a reader has to work out
which of the four values matters. Only `2190` does: it appears in the call and in the assertion. The
factory version, `a_quote(cents=2190)`, says that directly.

## The rule

Between the two, a single rule decides each value:

| the value | where it goes |
|---|---|
| the assertion depends on it | in the test, by name |
| it must be valid, and any valid value will do | in the factory's default |
| it must be different from another test's | generated by the factory |

A useful check when reviewing a test: **cover the factory file with your hand and read the test.**
If you can still tell why the expected value is right, the test shows enough. If you need to open
the factory, a mystery guest is hiding there.

## Names carry data too

The table of section 08 gives each row an id built from its data, `69005-010-5000g`, so a failure
says which case broke without opening the CSV. A test name or id is the first thing a reader of a
pipeline log sees, and it is worth spending a few characters on.
