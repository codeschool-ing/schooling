---
title: Trocar as instâncias uma de cada vez
version: 1

Um serviço com mais de uma instância não precisa parar todas. Um **rolling update** troca poucas por
vez: tira uma do balanceador de carga, implanta o release novo nela, confere, devolve, passa para a
próxima. A cada momento a maioria das instâncias está atendendo, e o cliente não vê lacuna.

O custo está nas colunas do meio. **Enquanto a troca acontece, duas versões atendem clientes ao mesmo
tempo**, e o balanceador decide qual delas cada requisição encontra. Isso é inofensivo quando o
release novo só acrescenta alguma coisa. Não é inofensivo quando:

- o release novo grava dados que o antigo não consegue ler, e a próxima requisição do cliente cai
  numa instância antiga;
- a API mudou de forma, e a página carregada pela versão nova chama um endpoint que a antiga não tem;
- as duas versões discordam de um preço, e o mesmo carrinho mostra dois totais no mesmo minuto.

A regra que mantém o rolling update seguro é a que a aula 11 retoma: **todo release precisa conseguir
rodar ao lado do anterior.** Uma mudança que não consegue, como renomear uma coluna, é dividida em
passos que conseguem.

## Os dois números que dão a forma

Os orquestradores descrevem um rolling update com dois números. O Kubernetes os chama de
`maxUnavailable`, quantas instâncias podem ficar fora de serviço ao mesmo tempo, e `maxSurge`,
quantas instâncias extras podem subir acima do número de costume. Com quatro instâncias:

- `maxUnavailable: 1, maxSurge: 0` troca uma por vez e nunca precisa de uma quinta máquina, mas
  atende com três quartos da capacidade durante a troca;
- `maxUnavailable: 0, maxSurge: 1` sobe uma quinta instância antes, e a capacidade nunca cai, ao
  preço de uma máquina a mais enquanto a troca dura.

## O que ele não dá

O rolling update não tem um caminho de volta limpo. Desfazer é outro rolling update, no sentido
contrário, na mesma velocidade. E a decisão de parar fica com quem estiver olhando: nada na
estratégia compara as instâncias novas com as antigas. As duas próximas estratégias cuidam dessas
duas lacunas, uma cada.
