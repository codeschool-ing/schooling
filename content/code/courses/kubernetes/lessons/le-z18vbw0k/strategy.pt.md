---
title: Dois números decidem como os pods são trocados
version: 1
---

Um Deployment troca de versão criando um ReplicaSet novo e passando as réplicas para ele, algumas de
cada vez. **Quantas de cada vez é definido por dois campos em `strategy.rollingUpdate`:**

- `maxSurge` é quantos pods podem existir **acima** de `replicas` durante a troca.
- `maxUnavailable` é quantas das `replicas` podem estar **não prontas** durante a troca.

Os dois aceitam um número ou uma porcentagem, e os dois valem `25%` por padrão. A loja abaixo usa quatro
réplicas, no máximo uma a mais e nenhuma a menos:


```
ana@laptop:~/shop$ kubectl apply -f shop.yaml
deployment.apps/shop created
service/shop created
ana@laptop:~/shop$ kubectl get rs -l app=shop
NAME              DESIRED   CURRENT   READY   AGE
shop-6ff4fb647d   4         4         4       3s
```

Com esses números só existe um jeito de avançar. O controlador pode acrescentar um pod, então acrescenta.
Ele não pode perder um, então nenhum pod antigo sai até o novo ficar pronto. Aí ele pode acrescentar outro,
e assim por diante:

Pôr os dois em `0` é recusado, porque aí nada poderia se mover. Aumentar o `maxSurge` deixa a troca mais
rápida e precisa de espaço nos nós para os pods a mais. Aumentar o `maxUnavailable` não precisa de espaço
e roda o serviço com menos pods enquanto dura. **O primeiro gasta capacidade; o segundo gasta folga.**

## Contando as requisições

Para ver quanto uma atualização custa a um cliente, o bloco a seguir manda trezentas requisições ao
Service, com um décimo de segundo entre elas, a partir do pod `probe`. Três segundos depois do início, a
imagem é trocada de um segundo terminal; esse comando aparece depois da contagem porque a contagem só
imprime quando termina:

```
ana@laptop:~/shop$ kubectl exec probe -- sh -c "for i in \$(seq 300); do wget -qO- -T 2 shop || echo FAILED; sleep 0.1; done" | cut -d" " -f1,2 | sort | uniq -c
wget: download timed out
      1 FAILED
     40 shop 1.0
    259 shop 1.1
ana@laptop:~/shop$ kubectl set image deployment/shop shop=shop:1.1
deployment.apps/shop image updated
ana@laptop:~/shop$ kubectl get rs -l app=shop
NAME              DESIRED   CURRENT   READY   AGE
shop-6ff4fb647d   0         0         0       37s
shop-7b9858cc8f   4         4         4       31s
```

O ReplicaSet antigo continua lá com `0` réplicas. É isso que torna possível voltar, e a última seção usa
isso. Uma requisição em trezentas falhou, e o erro foi um timeout. A próxima seção é sobre essa
requisição.

`strategy.type` tem um outro valor, `Recreate`, que remove todos os pods antigos antes de criar qualquer
novo. Isso significa indisponibilidade, e existe para a aplicação que não consegue rodar duas versões ao
mesmo tempo, como uma que migra o banco de dados ao iniciar.
