---
title: Two places a hypervisor can sit
version: 1
---

A hypervisor shares one computer among several guests: each gets processors, memory, a disk and a
network card that it believes are its own. **How** it does that depends mostly on one thing, what
sits directly on the hardware.

A **type 2** hypervisor, also called *hosted*, is an application. You install Windows, macOS or
Linux as usual, then install VirtualBox or VMware Workstation like any program, and it runs next to
your browser. When a guest needs the disk or the network, the hypervisor asks the operating system
underneath, the same way any application does. It is easy to install, easy to remove, and the host
stays your normal computer. It is what you want on a laptop.

A **type 1** hypervisor, also called *bare metal*, is what the computer boots. VMware ESXi and Xen
boot straight into the hypervisor, and every operating system on the machine runs on it as a guest,
including the small one you manage it from, if there is one. Nothing sits between the guests and the
hardware except the hypervisor, and there is no ordinary desktop to slow it down or crash. It is
what runs in server rooms, and lessons 6 and 7 are about two of them.

**Most people get this backwards about Hyper-V.** Switching it on in Windows does not add an
application to Windows. The computer then boots Microsoft's hypervisor first, and Windows itself
starts on top of it, as a guest with special rights. That is type 1, on a laptop, and section 07
shows why a support technician runs into it.
