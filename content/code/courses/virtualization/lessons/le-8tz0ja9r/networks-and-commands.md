- **VMnet0, bridged**: the guest's card is joined to the host's real one, and the guest asks the office's
  DHCP for an address like any other computer. Other people can reach it, and it can reach them.
- **VMnet1, host-only**: a private network of the host and its guests. Nothing leaves it.
- **VMnet8, NAT**: the guest gets an address from VMware's own DHCP and reaches the outside through the
  host, which is the only thing the office network sees. It is the default for a new guest.

They are changed in the **Virtual Network Editor**, which needs administrator rights. When a guest on
bridged "has no internet" on a laptop, the usual cause is that VMnet0 is bridged to the wrong adapter,
the wired one while the laptop is on Wi-Fi; the editor's *Automatic* setting picks one, and naming the
right adapter fixes it. Lesson 11 builds all three with libvirt and looks at why each exists.

Workstation also has a command line, `vmrun`, for starting, stopping and snapshotting guests from a
script, and VMware's `ovftool` converts between OVA and `.vmx`:

```sh
vmrun list                                       # the guests that are running
vmrun start "C:\VMs\lab1\lab1.vmx" nogui        # start one with no window
vmrun snapshot "C:\VMs\lab1\lab1.vmx" clean      # take a snapshot called clean
vmrun revertToSnapshot "C:\VMs\lab1\lab1.vmx" clean
vmrun stop "C:\VMs\lab1\lab1.vmx" soft          # ask the guest to shut down
ovftool lab1.ova "C:\VMs\lab1\lab1.vmx"          # convert an OVA into a Workstation machine
```

**None of these were run for this lesson**, as VMware is not installed here. The paths are the kind
Workstation uses on Windows; on Linux they are ordinary paths under your home.
