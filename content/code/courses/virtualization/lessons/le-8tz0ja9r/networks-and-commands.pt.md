- **VMnet0, bridged** (em ponte): a placa do convidado é unida à placa de verdade do host, e o convidado
  pede endereço ao DHCP do escritório como qualquer outro computador. Outras pessoas o alcançam, e ele as
  alcança.
- **VMnet1, host-only** (só com o host): uma rede privada do host e dos convidados dele. Nada sai dela.
- **VMnet8, NAT**: o convidado recebe endereço do DHCP do próprio VMware e alcança o lado de fora pelo
  host, que é a única coisa que a rede do escritório vê. É o padrão para um convidado novo.

Elas são mudadas no **Virtual Network Editor**, que exige direitos de administrador. Quando um convidado
em bridged "está sem internet" num laptop, a causa costuma ser que a VMnet0 está em ponte com o
adaptador errado, o cabeado enquanto o laptop está no Wi-Fi; a opção *Automatic* do editor escolhe um, e
nomear o adaptador certo resolve. A aula 11 monta as três com o libvirt e olha por que cada uma existe.

O Workstation também tem uma linha de comando, o `vmrun`, para ligar, desligar e tirar snapshots de
convidados por script, e o `ovftool` da VMware converte entre OVA e `.vmx`:

```sh
vmrun list                                       # the guests that are running
vmrun start "C:\VMs\lab1\lab1.vmx" nogui        # start one with no window
vmrun snapshot "C:\VMs\lab1\lab1.vmx" clean      # take a snapshot called clean
vmrun revertToSnapshot "C:\VMs\lab1\lab1.vmx" clean
vmrun stop "C:\VMs\lab1\lab1.vmx" soft          # ask the guest to shut down
ovftool lab1.ova "C:\VMs\lab1\lab1.vmx"          # convert an OVA into a Workstation machine
```

**Nenhum deles foi rodado para esta aula**, já que o VMware não está instalado aqui. Os caminhos são do
tipo que o Workstation usa no Windows; no Linux são caminhos comuns debaixo da sua pasta pessoal.
