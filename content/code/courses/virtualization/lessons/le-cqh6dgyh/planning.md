---
title: Three machines, three roles
version: 1
---

A lab is worth building when it is planned around what you want to practise. For support, that is the
shape of almost every ticket: **somebody at one computer cannot use a service on another.** So the lab
has three guests, each with one job:

- **client** is the user's computer, and where you work from. Every check starts here, because a
  service that works on the server and not from the client is the most common ticket there is.
- **server** runs a web server that works. It is the reference: when something looks odd on the
  target, the server shows what it ought to look like.
- **target** runs the same service, **broken on purpose**, and saved in that state so the exercise can
  be repeated.

They share **an isolated network**, lesson 11, so nothing done in the lab reaches a real network and
nothing from outside reaches the lab. Lesson 15 checks how isolated it really is.
