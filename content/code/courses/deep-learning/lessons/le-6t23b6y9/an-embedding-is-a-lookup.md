title: An embedding is a lookup
version: 1

An id is an integer, and a network takes numbers, so the tempting move is to feed 288 in as the
number 288. **That tells the model that ` baker` is a little more than ` the`, at 258, and a little
less than ` sells`, at 307**, which is nonsense: the ids are names, and their order is an accident of
training. The honest encoding gives each token its own dimension, a **one-hot** vector of 500 numbers
with a single 1, and puts no token closer to another than any other.

One-hot vectors are long and almost entirely zero, and multiplying them by a weight matrix is
mostly multiplying by zero. The first layer of a model that reads text skips the waste. It holds a
table with a row of numbers per token and, given an id, **returns that row**. PyTorch calls it
`nn.Embedding`, and the row is the token's **embedding**. Save this as `~/dl/lookup.py`; it needs
the `tok.json` that `tok.py` saved:

**`equal: True` is the point of the section.** Seven ids looked up in the table give a 7 by 8
matrix; seven one-hot rows of 500 times the same table give the same 7 by 8 matrix, to the last bit.
An embedding layer is a linear layer with no bias whose input is one-hot, computed by indexing
instead of by multiplying. The table is its weight matrix: 500 rows of 8, 4,000 parameters, and row
288 is the eight numbers that stand for ` baker`.

## Only the rows that were read learn

**Seven rows of 500 received a gradient.** The backward pass of a lookup sends the gradient to the
rows that were looked up and to nothing else, exactly as the one-hot product would: a zero in the
input gives a zero gradient for the weight it meets. So in each training step a token's row moves
only if that token is in the batch.

That is the cost of a large vocabulary from the last section, made concrete. A token seen once in
the training text has its row adjusted once, and keeps most of its random start. Frequent tokens get
well-trained rows; rare ones stay noisy, and BPE's habit of building rare words out of frequent
pieces is part of what keeps that from mattering.

At the start, as `lookup.py` shows, the rows are random and the model can tell nothing from them.
Training is what puts them somewhere useful, and the next section trains some.
