**What is the unit?** A task in Airflow, Luigi and Prefect; an asset in Dagster. The difference
shows when something goes wrong: a failed task is a step to rerun, and an out-of-date asset is a
thing to rebuild, whichever steps that takes.

**How is the order said?** Airflow writes it apart from the code, with `>>`. Luigi's `requires` and
Dagster's `deps` declare it inside each unit, and the tool assembles the graph. Prefect does not
declare it at all: the order is the order of the calls in the flow function, as in any Python
program.

**What counts as done?** This is the question that mattered in the lab. Airflow and Prefect record
that a run of a task succeeded; Luigi checks whether the output exists, now; Dagster records that an
asset was materialized, and when, and compares it with what it was made from. Only Luigi skipped
work it had already done; only Prefect redid everything; and none of them, on its own, knew that the
shop had changed the 14th after it was loaded. Lesson 15 is about making that last question safe
rather than lucky.

**What runs it on a schedule?** Airflow's scheduler; `luigid` plus `cron`, since Luigi has no
schedule of its own; a Prefect server with a deployment and a worker; `dagster-daemon` with a
schedule or a sensor. In every case it is a long-lived process that the lab started only for
Airflow.
