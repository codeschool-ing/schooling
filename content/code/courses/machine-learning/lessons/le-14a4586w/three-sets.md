One held-out set is enough to judge **one** model. The moment it is used to choose between two, it
has become part of the training: the model that won did so partly on that set's luck, as the best
of five rules did in lesson 2. So the data is cut three ways, and each part has one job.

| set | its job | how often it is looked at |
|---|---|---|
| **training** | `fit` learns from it | every time |
| **validation** | choosing: which model, which settings, which threshold | as often as you like |
| **test** | the final score, reported once | once, at the end |

**The test set is touched once.** Look at it twice, change something in between, and it is a
second validation set with a misleading name. The discipline is uncomfortable, because the test
score is the one people want to improve, and that is precisely why it has to be protected.

At Feira em Casa the three sets are cut by date, for reasons the section on time makes plain:

`by_time` from lesson 2 makes the outer cut: the twelve months before July 2025 on one side, the
six after on the other. Inside the twelve, the last three months can serve as a validation set when
a lesson has something to choose, and the first nine as its training set. The test months stay
untouched until a lesson has finished choosing.

## When there is not enough data for three sets

Holding out a validation set costs data the model could have learned from, and one validation set
is one sample with its own luck. Both problems have the same answer, which is the next section:
**cross-validation**, which uses every training row for validation once and for training the rest of
the time.
