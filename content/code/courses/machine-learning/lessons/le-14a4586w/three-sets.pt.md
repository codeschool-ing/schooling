Um conjunto separado basta para julgar **um** modelo. No momento em que ele é usado para escolher
entre dois, virou parte do treino: o modelo que venceu venceu em parte pela sorte daquele conjunto,
como a melhor de cinco regras na aula 2. Então os dados são cortados em três, e cada parte tem uma
função.

| conjunto | a função dele | quantas vezes é olhado |
|---|---|---|
| **treino** | o `fit` aprende com ele | toda vez |
| **validação** | escolher: qual modelo, quais ajustes, qual limiar | quantas vezes quiser |
| **teste** | a nota final, relatada uma vez | uma vez, no fim |

**O conjunto de teste é tocado uma vez.** Olhe duas vezes, mude alguma coisa entre uma e outra, e
ele é um segundo conjunto de validação com um nome enganoso. A disciplina é desconfortável, porque a
nota de teste é a que as pessoas querem melhorar, e é exatamente por isso que ela precisa ser
protegida.

Na Feira em Casa os três conjuntos são cortados por data, por motivos que a seção sobre tempo deixa
claros:

O `by_time` da aula 2 faz o corte de fora: os doze meses antes de julho de 2025 de um lado, os seis
depois do outro. Dentro dos doze, os três últimos meses podem servir de validação quando uma aula
tem algo a escolher, e os nove primeiros de treino. Os meses de teste ficam intocados até uma aula
terminar de escolher.

## Quando não há dados para três conjuntos

Separar um conjunto de validação custa dados com que o modelo poderia aprender, e um conjunto de
validação é uma amostra com a sua própria sorte. Os dois problemas têm a mesma resposta, que é a
próxima seção: a **validação cruzada**, que usa cada linha de treino uma vez para validar e no resto
do tempo para treinar.
