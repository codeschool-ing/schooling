**"Ainda não" continua sendo a resposta para a maioria das pessoas que terminam este curso.** Os cursos
depois dele na trilha, bancos de dados, APIs, arquitetura e o resto, são escritos para quem consegue
construir um serviço numa linguagem, qualquer uma das quatro que a trilha oferece, e você vai fazer o
trabalho deles em Node. Cada hora disso é uma hora de profundidade que a próxima linguagem vai
reaproveitar.

O momento para uma segunda linguagem é o que a aula 1 apontou, quando o Node não for mais aquilo com
que você está brigando. Quando esse momento chega, a escolha costuma ser feita pelo trabalho e não pela
linguagem:

| você se vê | a linguagem para onde aponta | por quê |
|---|---|---|
| escrevendo infraestrutura, ferramentas de linha de comando, um serviço que precisa usar todo processador | **Go** | um binário, concorrência barata, a linguagem das próprias ferramentas |
| perto de dados, análise ou aprendizado de máquina | **Python** | as bibliotecas estão lá, e as pessoas também |
| numa empresa grande com sistemas de longa vida | **Java** ou **C#** | é no que eles são feitos, com as ferramentas de que equipes grandes dependem |
| mantendo ou estendendo sites feitos em WordPress ou Laravel | **PHP** | o código já existe, e é muito |

**Aprenda a segunda do jeito que este curso ensinou a primeira**: não a sintaxe num tutorial, mas um
serviço de verdade nela, da configuração ao desligamento, com os próprios testes e o próprio
gerenciador de pacotes. A tabela da última seção é uma lista de conferência para esse serviço, e cada
linha dela tem resposta em cada uma das cinco.

Uma coisa vem junto que nenhuma tabela mostra. Este curso pediu, aula após aula, que você lesse o erro
que o runtime imprimiu antes de chutar a causa, que procurasse na documentação o que uma função faz, e
que medisse em vez de acreditar numa afirmação, inclusive nas deste curso. Esse hábito é a parte dele
que não se importa com a linguagem que vem a seguir.
