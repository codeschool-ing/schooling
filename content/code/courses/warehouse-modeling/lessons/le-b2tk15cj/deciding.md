Everything in this lesson, as a set of questions to ask about any table in a warehouse:

1. **Who writes it?** If many people or systems write it a row at a time, normalise: the anomalies are
   real. If one load writes it in batches, from a source of truth, repetition is safe.
2. **Who reads it?** If people and report tools read it, every join you save them is a mistake they cannot
   make. Denormalise dimensions into stars.
3. **How is it stored?** In a row store, repetition is paid in full: 2.8 times the space here. In a
   column store it is mostly compressed away: 1.3 times.
4. **Is it a model or a copy?** The star is the model. A wide table or an aggregate is a copy of it, rebuilt
   from it, never edited, and checked against it.
5. **What changes, and how often?** An attribute that is renamed now and then is cheap to repeat in a
   dimension and expensive to repeat in a fact table. A source that changes its structure every quarter
   argues for a vault underneath.

The short form, which is worth remembering: **normalise what is written by many, denormalise what is read
by many, and never edit a copy.**
