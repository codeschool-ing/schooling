title: What the three have in common

BigQuery, Snowflake and Redshift are **managed cloud data warehouses**: you create tables and run SQL,
and the provider runs the machines, the storage, the upgrades and the backups. Their marketing differs a
great deal more than their foundations, and the foundations are the ones the previous two lessons
measured:

- **Columnar storage with compression**, lesson 8. All three store each column apart, encoded and
  compressed, in blocks with minimum and maximum statistics that queries use to skip.
- **Parallel processing across many machines**, lesson 7. A query is split, run on many nodes at once,
  and the partial results are combined.
- **Storage kept apart from compute**, lesson 7 section 11. The data sits in the provider's object
  storage; the processing is a pool of machines that can grow, shrink or stop.
- **SQL**, with the dimensional model running nearly unchanged. Ana's star would load into any of the
  three with small changes of type names, which section 09 shows.

**Nothing in lessons 2 to 6 changes because the warehouse is rented.** Facts, dimensions, the grain,
surrogate keys and slowly changing dimensions are decisions about meaning, and every one of the three
runs them. What changes is two things the operator of a database used to decide alone: how you pay, and
which physical knobs you are given. The rest of the lesson is those two, product by product.

**None of the three runs in this lab.** There is no cloud account in this course. Their SQL appears in
this lesson marked as not run; the arithmetic is done on Ana's own data in DuckDB, and every price is
quoted from the provider's public page with the date it was read.
