---
title: Como o Memcached gasta a memória
version: 1
---

O Memcached não pede memória ao sistema operacional um valor por vez. Ele pega **páginas de um
megabyte** e corta cada página em pedaços de um tamanho só. Páginas cortadas em pedaços de 96 bytes
pertencem à classe de slab 1, páginas de pedaços de 120 bytes à classe 2, e assim por diante, cada
tamanho cerca de 1,25 vez o anterior. Uma cópia iniciada com `-vv` imprime as classes e sai quando o
`timeout` a para:

```
ana@web:~$ timeout 1 memcached -u memcache -vv -p 11299 -l 127.0.0.1 2>&1 | grep 'slab class' | sed -n '1,4p;$p'
slab class   1: chunk size        96 perslab   10922
slab class   2: chunk size       120 perslab    8738
slab class   3: chunk size       152 perslab    6898
slab class   4: chunk size       192 perslab    5461
slab class  39: chunk size    524288 perslab       2
```

**Um valor vai para o menor pedaço que o comporta**, junto com a chave e um cabeçalho de algumas dezenas
de bytes. Um valor de 1.000 bytes cai na classe 12, cujos pedaços têm 1.184 bytes, e a diferença é
memória que nada usa.

**Um reinício esvazia o Memcached.** O estoque e o contador das seções anteriores sumiram, porque nada
nunca foi gravado em disco. Agora este programa grava vinte mil valores de mil bytes, cerca de 20 MB,
em 8 MB:

```python
import sys

from pymemcache.client.base import Client

mc = Client(("127.0.0.1", 11211))
count, size = int(sys.argv[1]), int(sys.argv[2])
for i in range(count):
    mc.set(f"filler:{i}", b"x" * size, noreply=False)
print("written", count, "values of", size, "bytes")
```

As 20.000 gravações deram certo. 12.920 valores mais velhos foram despejados para abrir espaço, 7.080
ficaram, e eles enchem as oito páginas da classe 12, todos os oito megabytes. **O Memcached despeja em
vez de recusar uma gravação**: ele se comporta como o `allkeys-lru` da aula 8 de fábrica, e o `-M` é a
chave que o faz recusar, o que um cache raramente quer.

```
ana@web:~/work$ printf 'get filler:0\r\nget filler:19999\r\n' | nc -q1 127.0.0.1 11211 | cut -c1-40
END
VALUE filler:19999 0 1000
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
END
```

O primeiro valor gravado foi despejado e o último está lá. A ordem de uso menos recente é mantida **por
classe de slab**, então um valor novo de 1.000 bytes empurra para fora um velho da classe 12 mesmo que a
classe 3 esteja cheia de valores que ninguém lê. O Memcached move páginas entre classes em segundo plano
quando a mistura de tamanhos muda, o que suaviza isso, mas um cache cujos tamanhos mudam de repente
ainda pode despejar numa classe enquanto outra fica parada.

```
ana@web:~/work$ python3 -c 'from pymemcache.client.base import Client; Client(("127.0.0.1", 11211)).set("big", b"x" * 2_000_000, noreply=False)' 2>&1 | tail -1
pymemcache.exceptions.MemcacheServerError: b'object too large for cache'
```

**Nenhum valor pode passar de um megabyte**, o tamanho da página, a não ser que o `-I` aumente. Um
programa que guarda um fragmento de página grande sem conferir recebe esse erro, ou, com as respostas
desligadas, nada, e é disso que trata a próxima seção.
