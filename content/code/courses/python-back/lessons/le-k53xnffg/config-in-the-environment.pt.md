---
title: O que pertence ao ambiente
version: 1
---

O código do agenda vem carregando fatos sobre uma máquina: `DEBUG = True`, uma chave secreta que o
`startproject` escreveu, um banco alcançado pelo socket local como ana, uma chave de JWT colada no
`app/security.py` na aula 11. Num servidor cada um deles está errado, e dois são perigosos. A resposta
que a maioria dos projetos segue é a que o **Twelve-Factor App** escreveu: **a configuração que muda
entre implantações mora no ambiente**, e o código a lê de lá.

O **ambiente** é um conjunto de nomes e valores que todo processo herda de quem o iniciou. O Python o
vê como `os.environ`:

```
ana@vm:~/agenda$ uv run python -c "import os; print(os.environ.get('DJANGO_DEBUG'))"
None
ana@vm:~/agenda$ DJANGO_DEBUG=1 uv run python -c "import os; print(os.environ.get('DJANGO_DEBUG'))"
1
```

O mesmo código imprimiu dois valores diferentes, e nada nele mudou. Essa é a propriedade desejada: uma
base de código, implantada num notebook, num servidor de testes e em produção, cada um dizendo a ela o
que precisa saber.

O teste de cada valor é se ele mudaria caso o mesmo código rodasse em outro lugar. Os apps instalados
não mudariam; o host do banco mudaria. **Segredos** são valores do segundo tipo que também nunca podem
ser escritos onde alguém consiga lê-los: nem no código, nem no git, nem num log.
