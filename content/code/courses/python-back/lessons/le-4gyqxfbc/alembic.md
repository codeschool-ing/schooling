Alembic keeps a **chain of migration scripts**, each naming the one before it, and a table in the
database recording which one it has reached. Set it up in the project:

```
ana@vm:~/agenda-api$ uv run alembic init migrations
Creating directory /home/ana/agenda-api/migrations ...  done
Creating directory /home/ana/agenda-api/migrations/versions ...  done
Generating /home/ana/agenda-api/migrations/script.py.mako ...  done
Generating /home/ana/agenda-api/migrations/README ...  done
Generating /home/ana/agenda-api/migrations/env.py ...  done
Generating /home/ana/agenda-api/alembic.ini ...  done
Please edit configuration/connection/logging settings in /home/ana/agenda-api/alembic.ini before proceeding.
```

Two edits before it can do anything. In `alembic.ini`, the line `sqlalchemy.url` holds a placeholder;
replace it with the engine's URL. In `migrations/env.py`, the line `target_metadata = None` is what
autogenerate compares the database against; point it at the models' metadata:

```
ana@vm:~/agenda-api$ grep -n "^sqlalchemy.url" alembic.ini
89:sqlalchemy.url = postgresql+psycopg:///agenda_api
ana@vm:~/agenda-api$ grep -n -A2 "import Base" migrations/env.py
21:from app.models import Base
22-
23-target_metadata = Base.metadata
```

Now ask for a migration. `--autogenerate` compares `Base.metadata` with the database and writes the
difference; `--rev-id` names the revision `0001` instead of a random string of hex, which keeps the
files in order when listed:

```
ana@vm:~/agenda-api$ uv run alembic revision --autogenerate --rev-id 0001 -m "events and registrations"

because it means it**: the file is a draft written by comparing two schemas, and the next section is
the case where the draft is wrong. Here it is right, so apply it:

```

`registrations_event_id_email_key` is the one-address-per-event rule.

## Rows, through a session

The tables are empty. The three events still live in `app/store.py`, so a one-off script can copy
them. Save `seed.py`:

```python
# seed.py
from sqlalchemy.orm import Session

from app.db import engine
from app.models import Event
from app.store import EVENTS

with Session(engine) as session:
    session.add_all(Event(**data) for data in EVENTS.values())
    session.commit()
    print("added", len(EVENTS), "events")
```

```
ana@vm:~/agenda-api$ uv run python seed.py
added 3 events
ana@vm:~/agenda-api$ uv run alembic current
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
0001 (head)
```

The **session** is the ORM's unit of work: `add_all` hands it objects, nothing is sent until
`commit`, and then it writes them in one transaction. `alembic current` reads the `alembic_version`
table, which now holds one row, `0001`.
