Um **serializer** descreve o formato de um recurso. Dado um objeto, ele produz um dicionário que vira
JSON; dado um dicionário que chegou como JSON, ele o valida e produz valores limpos. Ele é para uma API
o que o `Form` da aula 3 é para uma página. Salve isto como `events/serializers.py`:

## Saída: um objeto vira dados

```
ana@vm:~/agenda$ uv run python manage.py shell -c "from events.serializers import EventSerializer; from events.models import Event; print(EventSerializer(Event.objects.get(slug=\"testing-dojo\")).data)"
14 objects imported automatically (use -v 2 for details).

{'slug': 'testing-dojo', 'title': 'Testing dojo', 'starts_at': '2026-11-26T19:00:00-03:00', 'venue': 'Community Centre, room 3', 'capacity': 20, 'description': ''}
```

Todos os campos de `fields`, com a data em ISO 8601 e **o deslocamento de São Paulo, `-03:00`**,
porque o DRF converte datas para o `TIME_ZONE` na saída. O `taken` falta porque este evento veio de
um `get()` simples, sem anotação; um campo só de leitura que o objeto não tem fica de fora em vez de
falhar.

## Entrada: os dados são conferidos antes de virar qualquer coisa

```
ana@vm:~/agenda$ uv run python manage.py shell -c "from events.serializers import EventSerializer; s = EventSerializer(data={\"slug\": \"bad slug\", \"title\": \"\", \"capacity\": -1}); print(s.is_valid()); print(s.errors)"
14 objects imported automatically (use -v 2 for details).

False
{'slug': [ErrorDetail(string='Enter a valid "slug" consisting of letters, numbers, underscores or hyphens.', code='invalid')], 'title': [ErrorDetail(string='This field may not be blank.', code='blank')], 'starts_at': [ErrorDetail(string='This field is required.', code='required')], 'venue': [ErrorDetail(string='This field is required.', code='required')], 'capacity': [ErrorDetail(string='Ensure this value is greater than or equal to 0.', code='min_value')]}
```

O `is_valid()` rodou todas as conferências e juntou **todos os erros de uma vez, campo a campo**, que
é o que um cliente precisa para mostrar um formulário com todos os problemas marcados. As mensagens
vêm do modelo: o padrão do slug, `title` sem ficar em branco, o mínimo de 0 do `CHECK` que a aula 4
viu como `PositiveIntegerField`. Os campos que o modelo exige e os dados deixaram de fora aparecem
como `required`. Nada foi gravado; gravar é um passo separado, e só dados válidos chegam a ele.
