**Um arquivo CSV guarda uma tabela linha a linha; Parquet e ORC a guardam coluna a coluna.** Os dois
têm os mesmos valores. O que muda é quais valores ficam lado a lado no disco, e isso decide o que um
leitor tem de atravessar para responder a uma pergunta.

Uma consulta analítica cita poucas colunas de uma tabela larga: os tipos de evento por dia, as
compras por categoria. **Guardada por linha, toda coluna de toda linha é lida para achar as poucas
que importam**, porque os valores de uma coluna estão espalhados pelo arquivo, um por linha.
Guardada por coluna, os valores de `kind` são um trecho contínuo, e as outras colunas não são
tocadas. A aula 6 mediu o resultado sem explicá-lo: uma contagem de livros distintos leu duas
colunas de sete.

Manter os valores de uma coluna juntos tem um segundo efeito, tão grande quanto o primeiro. **Os
valores de uma coluna se parecem**: os mesmos poucos tipos, os mesmos três dispositivos, timestamps
com um segundo ou pouco mais entre eles. Valores parecidos comprimem muito melhor que os valores
misturados de uma linha, e um arquivo colunar ainda pode codificá-los antes de comprimir, guardando
uma vez um valor repetido ou um timestamp como a diferença para o anterior. As seções 04 e 05 medem
as duas coisas.

**O que um arquivo colunar faz mal é a pergunta oposta**: uma linha inteira, ou acrescentar linhas
uma a uma. Ler uma linha é visitar o trecho de cada coluna; acrescentar uma é reescrever o arquivo.
É por isso que um banco de dados que atende uma aplicação guarda linhas e um lake que atende
analistas guarda colunas, e por isso os dados passam de um para o outro em lotes.
