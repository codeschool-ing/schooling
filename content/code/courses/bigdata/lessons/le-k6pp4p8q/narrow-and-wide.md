---
title: Narrow and wide
version: 1
---

**Every transformation is either narrow or wide, and the difference is the whole cost model of
Spark.**

**A narrow transformation** computes each output partition from one input partition. `filter`,
`select`, `withColumn` and a `map` are narrow: task 3 of the output reads partition 3 of the input and
nothing else. Spark chains any number of narrow steps into one task, so a filter followed by a
projection followed by another filter is one pass over the data, in one stage, with nothing written
between them.

**A wide transformation** needs, for each output partition, rows from every input partition.
`groupBy`, `join` (except a broadcast join), `distinct`, `orderBy` and `repartition` are wide: the
rows for one key can be in any input partition, so each input task must send each row to the task
that owns its key. That is a shuffle, and a stage ends there.

**So a job's stages are its narrow chains, and its shuffles are the joins between them.** Reading a
plan for cost is reading it for wide transformations: each one is every row written to disk by one
set of tasks and read across the network by another. Lesson 6's purchases per category had two, the
grouping and the sort, and the broadcast join that would otherwise have been a third.

**Narrow is not free and wide is not always expensive.** A narrow UDF in Python costs more than a
wide grouping by `kind` with four keys, as lesson 5 measured. What a shuffle costs depends on how
much crosses it, which is the next section.
