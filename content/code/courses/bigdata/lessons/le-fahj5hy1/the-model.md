**MapReduce is a way of writing a distributed job as two small functions, with the hard part done
between them by the framework.** Google described it in a paper in 2004; Hadoop was the open-source
version, and for most of the next decade it was what "big data" meant.

The programmer writes:

- **map**, which takes one input record and emits any number of *key-value pairs*. It sees one
  record at a time and keeps no memory between them.
- **reduce**, which takes one key and every value emitted for it, and emits the result for that key.

The framework does everything else, and the everything else is the subject of this course:

1. It **splits the input** into pieces, one per HDFS block, and runs a map task on each, on a machine
   that holds the block where it can.
2. It **partitions** each map task's output by key, so that every pair with the same key goes to the
   same reduce task, wherever it was produced.
3. It **sorts** each reduce task's input by key and hands the reducer one key's values at a time.
4. It **reruns** any task whose machine fails, from its input, which is still in HDFS.

Steps 2 and 3 together are the *shuffle*, the same word lesson 1 gave to `buckets.py`'s first pass.
`buckets.py` was a MapReduce program written by hand: its first pass mapped each event to a visitor
and sent it to the bucket its key decided, and its second pass reduced each bucket. The framework
adds the distribution and the recovery, and takes away the need to write either.

**The constraint is the point.** A program that can only be a map and a reduce cannot hold global
state, cannot depend on the order of its input, and cannot ask what another task is doing. In
exchange, the framework can run any number of copies of each function anywhere, rerun any of them,
and know the answer will be the same. Every restriction is a promise the framework needs in order to
scale.
