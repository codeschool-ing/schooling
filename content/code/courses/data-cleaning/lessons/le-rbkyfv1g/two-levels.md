Spellings run into categories and categories into departments, and every arrow is a line of the
same file. **Keeping the hierarchy in the mapping, rather than in each report, means a category
moves department in one place.** If the managers decide next year that eggs and cheese belong with
the delicatessen, one cell of the table changes and every report follows.

A hierarchy has rules that a flat list does not, and they are worth checking:

- **each category has exactly one parent.** Two lines mapping `Mercearia` to different departments
  would split its sales between them. A count of departments per category, expected to be 1, finds
  it;
- **the parent of a spelling depends only on its category.** If `emporio` mapped to `Mercearia` in
  one line and to `Empório` in another, the table would be contradicting itself;
- **totals add up across levels.** The sum of the seven categories' sales must equal the sum of the
  four departments' — a check that fails loudly if any product fell between the levels.

Lesson 12 builds derived columns from levels like these, and `visualization` draws them; both rely on
the hierarchy being decided once, here.
