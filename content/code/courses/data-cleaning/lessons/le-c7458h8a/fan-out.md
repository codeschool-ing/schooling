Run the join without `validate` and nothing stops it:

```
ana@lab:~/clean$ python -c "import pandas as pd; from lines import lines as l; p = pd.read_csv('raw/products.csv', dtype=str); m = l.merge(p, left_on='code', right_on='product_code', how='left', suffixes=('', '_catalogue')); print(len(l), len(m)); print(l['line_cents'].sum() / 100, m['line_cents'].sum() / 100)"
99161 103578
2516503.95 2684107.5
```

99,161 order lines went in and 103,578 came out. Every line of rocket, banana or sugar met two
catalogue rows and was copied once for each, 4,417 extra rows in all. The revenue summed after
the join is R$ 2,684,107.50 against R$ 2,516,503.95 before it: **R$ 167,603.55 that nobody
sold**, created by a key that was not unique.

Three things make this failure dangerous rather than merely wrong:

- **There is no error and no warning.** The join did exactly what it was asked.
- **The extra rows look real.** Each copy is a complete line with a quantity, a price and an
  order; nothing marks it as a copy.
- **The size is plausible.** Revenue 6.7% above the truth looks like a good year, not an obvious
  mistake.

The check that catches it is the dullest one there is: **count the rows before and after**. In a
many-to-one join with a left join, the count must not change. If it grew, a key on the right
repeats; if it shrank, the join was an inner join and something had no partner. Both are the
next two sections.
