The same numbers can be laid out in two shapes. Here are the sales targets for 2025, as the
commercial team keeps them:

```
ana@lab:~/clean$ head -3 raw/targets_2025.csv
loja,jan/25,fev/25,mar/25,abr/25,mai/25,jun/25,jul/25,ago/25,set/25,out/25,nov/25,dez/25,Total
Pinheiros,52000,52000,52000,54000,54000,54000,56000,56000,56000,58000,58000,58000,660000
Cambuí,14000,14000,14000,15000,15000,15000,15000,15000,15000,16000,16000,16000,180000
```

This is the **wide** format: one row per shop, and the month spread across the columns. It is how
a person writes a plan, because a whole year fits on one line and each shop can be read across.
The same data in **long** format has one row per shop and month, three columns in all: `loja`,
`month`, `target`. Six shops times twelve months is 72 rows.

Neither shape is wrong. They answer different questions well:

- **Wide is for reading.** A person comparing January with December for one shop wants them side by
  side, and a report printed on a page is almost always wide.
- **Long is for computing.** Filtering by month, joining to sales, grouping by quarter, charting a
  line over time: each of these wants the month as a value in a column, not as a column name.

The principle behind the long shape has a name, **tidy data**: each variable is a column, each
observation is a row. In the wide file, `month` is a variable that has been hidden in the header,
where no filter or join can reach it. **Most reshaping is moving a variable out of the header and
into a column**, or back again for the final report.

There is one more thing in the header that is not a month at all: `Total`. A sum stored as a column
is fine for a reader and a trap for a program, and it is the subject of the next section.
