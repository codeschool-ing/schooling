Os mesmos números podem ser dispostos em dois formatos. Estas são as metas de venda de 2025, como
a equipe comercial as guarda:

```
ana@lab:~/clean$ head -3 raw/targets_2025.csv
loja,jan/25,fev/25,mar/25,abr/25,mai/25,jun/25,jul/25,ago/25,set/25,out/25,nov/25,dez/25,Total
Pinheiros,52000,52000,52000,54000,54000,54000,56000,56000,56000,58000,58000,58000,660000
Cambuí,14000,14000,14000,15000,15000,15000,15000,15000,15000,16000,16000,16000,180000
```

Este é o formato **largo** (*wide*): uma linha por loja, e o mês espalhado pelas colunas. É como uma
pessoa escreve um plano, porque um ano inteiro cabe numa linha e cada loja se lê da esquerda para
a direita. Os mesmos dados no formato **longo** (*long*) têm uma linha por loja e mês, três colunas
ao todo: `loja`, `month`, `target`. Seis lojas vezes doze meses dá 72 linhas.

Nenhum dos dois formatos está errado. Eles respondem bem a perguntas diferentes:

- **O largo é para ler.** Quem compara janeiro com dezembro numa loja quer os dois lado a lado, e um
  relatório impresso numa página quase sempre é largo.
- **O longo é para calcular.** Filtrar por mês, juntar com vendas, agrupar por trimestre, traçar uma
  linha no tempo: cada uma dessas coisas quer o mês como valor numa coluna, não como nome de
  coluna.

O princípio por trás do formato longo tem nome, **dados organizados** (*tidy data*): cada variável é
uma coluna, cada observação é uma linha. No arquivo largo, `month` é uma variável escondida no
cabeçalho, onde nenhum filtro ou junção a alcança. **A maior parte das mudanças de formato é tirar
uma variável do cabeçalho e pô-la numa coluna**, ou devolvê-la para o relatório final.

Há mais uma coisa no cabeçalho que nem é um mês: `Total`. Uma soma guardada como coluna serve para
quem lê e é uma armadilha para um programa, e ela é o assunto da próxima seção.
