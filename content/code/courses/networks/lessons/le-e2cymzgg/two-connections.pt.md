Todo `ls` e todo `put` imprimiram um `229` antes. O FTP leva os comandos numa conexão, para a porta 21,
e cada listagem e cada arquivo numa **segunda conexão, aberta para aquela transferência e fechada
depois dela**. `229 Entering Extended Passive Mode (|||40007|)` é o servidor dizendo a que porta
conectar para a próxima.

Esse é o modo **passivo**: o cliente abre as duas conexões. O FTP é mais velho que o NAT e os
firewalls, e o modo original dele, o **ativo**, funciona ao contrário: o cliente diz onde está
escutando, e o servidor conecta de volta nele. Dá para mandar o curl fazer isso:

```
ana@laptop:~$ curl -sS -v --ftp-port - -u example:Sunflower-77 ftp://www.example.com/ 2>&1 | grep -E "^[<>] (PORT|EPRT|5)|curl:"
> EPRT |1|192.168.10.20|38787|
< 500 Illegal EPRT command.
> PORT 192,168,10,20,177,245
< 500 Illegal PORT command.
curl: (30) Failed to do PORT
ana@laptop:~$ curl -sS -v -u example:Sunflower-77 ftp://www.example.com/ 2>&1 | grep -E "^[<>] (EPSV|229)|Connecting|^-rw"
> EPSV
< 229 Entering Extended Passive Mode (|||40000|)
* Connecting to 192.0.2.80 (192.0.2.80) port 40000
-rw-r--r--    1 1001     1001          109 Sep 25 18:26 index.html
```

`EPRT` e `PORT` dizem ao servidor `192.168.10.20`, o endereço do próprio laptop, que é privado (aula
2). O router reescreveu a origem dos pacotes para `203.0.113.2` na saída, mas não o endereço escrito
dentro do comando. O servidor viu um comando vindo de um endereço pedindo que ele conectasse em outro,
e recusou: `500 Illegal PORT command`. Mesmo que tentasse, nada na internet alcança `192.168.10.20`.

O segundo comando é o padrão do curl, passivo: `EPSV`, uma porta na resposta, e uma conexão que o
próprio laptop abre, e que o NAT trata como qualquer outra. **Atrás de NAT, o FTP funciona em modo
passivo ou não funciona.**
