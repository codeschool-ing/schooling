(data for the program), `F` is FIN.

**The first three packets are the three-way handshake.** The laptop sends SYN with a random starting
number, `2071506207`. The server answers SYN-ACK: it acknowledges `2071506208`, one more, and sends a
starting number of its own. The laptop acknowledges that. Both sides now know the other is there and
agree on where the counting starts, and from here `tcpdump` prints the numbers relative to that start,
which is why the next ones are small.

Then the conversation. The request is bytes 1 to 78 (`seq 1:79`), and the server answers `ack 79`:
"I have everything up to 78, send 79 next." Its reply, the redirect, is bytes 1 to 386 in its own
direction, and the laptop acknowledges 387. **Every byte is counted and acknowledged**; a gap in the
count is how a loss is noticed, which section 05 makes happen.

Closing takes a FIN from each side, because each direction is closed separately. The laptop was done
first, the server followed, and the last ACK finished it. The whole exchange took under a millisecond,
because this is the lab.
