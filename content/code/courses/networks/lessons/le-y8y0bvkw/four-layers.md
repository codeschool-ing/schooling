The protocols that carry the internet, TCP and IP, were designed in the 1970s with a model of their
own, written down in **RFC 1122** in 1989. It has four layers, and each one is a group of OSI's:

- **Link**: getting a frame across one link. Ethernet, Wi-Fi, ARP. OSI's layers 1 and 2.
- **Internet**: getting a packet across networks. IP, and ICMP for its error messages. OSI's layer 3,
  and the reason the whole thing is called an *internet*: a network of networks.
- **Transport**: getting data to a program, reliably with TCP or as it comes with UDP. OSI's layer 4.
- **Application**: everything the program does. OSI's layers 5, 6 and 7 together, because in practice
  one program does all three, as lesson 1 section 06 showed with `curl`.

Some books split the link layer into two and count five layers. They describe the same protocols;
the argument is only about where to draw one line.

**The column on the right is the useful one.** The TCP/IP layers match who does the work on a real
computer: the program handles its own protocol; the operating system's kernel handles TCP, UDP, IP and
routing; the network card and its driver handle the link. When a user's program misbehaves and every
other program on the same machine is fine, the fault is almost certainly in that program's layer, and
the network below it is doing its job.
