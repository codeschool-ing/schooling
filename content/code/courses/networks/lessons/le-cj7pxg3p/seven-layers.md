A network is too many things to hold in your head at once. The **OSI model** (*Open Systems
Interconnection*, published by the ISO in 1984) splits it into seven layers. Each layer does one job,
uses the layer below it to do that job, and offers a service to the layer above.

Read it from the bottom. Layer 1 moves signals over a cable or through the air. Layer 2 uses those
signals to deliver a frame to one device on the same link. Layer 3 moves a packet between networks,
router by router, to the right machine. Layer 4 hands the data to the right program on that machine,
and in TCP's case makes sure it all arrives. Layers 5 to 7 are about what the programs say to each
other.

Two consequences make the model useful rather than academic:

- **When a layer fails, everything above it fails too**, whatever the error message on the screen
  says. A browser reporting that a site "cannot be reached" may be looking at an unplugged cable.
- Each layer has its own kind of address. A MAC address at layer 2, an IP address at layer 3, a port
  at layer 4, a name like `www.example.com` at layer 7. Asking which address a message is about tells
  you which layer you are in.

The protocols the model was written for lost to TCP/IP, which lesson 2 covers, and the model is still
taught because of that first consequence. "The internet is down" becomes questions you can answer in
order: is there a link, is there an address, can it reach the router, can it reach the server, is the
service listening, does the name resolve. This lesson asks each one on a real network.

## The lab

Every command in this course ran on a lab built for it: the office of Example Ltd, with a laptop, a
server and a router; an internet provider; and a small internet with its own DNS servers and a web
server for `www.example.com`. It is one Linux computer playing every machine in the drawing, which is
why its addresses are all ones reserved for documentation, and why a round trip across its "internet"
takes a fraction of a millisecond. **A prompt that says `ana@laptop` ran on the laptop, `ana@www` on
the web server**, and so on.
