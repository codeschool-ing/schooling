title: O caminho de uma mensagem
version: 1
---

A Ana, do `example.com`, escreve para o Bruno, de um fornecedor cujo domínio é `example.net`. O
programa de e-mail dela não entrega a mensagem sozinho. Ele a passa para o servidor de e-mail dela, que
acha o do Bruno do mesmo jeito que um navegador acha um site, pelo DNS, só que pedindo o registro **MX**
em vez de um `A`:

```
ana@laptop:~$ dig +short MX example.net
10 mail.example.net.
ana@laptop:~$ dig +short A mail.example.net
192.0.2.26
```

`10 mail.example.net.` é o servidor de e-mail (*mail exchanger*) do `example.net`, com prioridade 10;
um domínio com dois lista os dois, e o número menor é tentado primeiro. O endereço desse nome é a
segunda resposta.

**Dois tipos de servidor fazem dois trabalhos.** Um manda: recebe a mensagem do programa da Ana na
porta 587 e a passa adiante pela porta 25 para o servidor que o MX indicar. O outro recebe: aceita
e-mail para o domínio dele na porta 25, guarda na caixa postal e deixa o dono ler com IMAP ou POP3. Na
prática, uma máquina costuma fazer os dois para o seu domínio, como o `mail.example.com` faz aqui.
