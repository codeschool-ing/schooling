title: The path of a message
version: 1
---

Ana, at `example.com`, writes to Bruno, at a supplier whose domain is `example.net`. Her mail program
does not deliver the message itself. It hands it to her own mail server, which finds Bruno's the same
way a browser finds a website, through DNS, only asking for the **MX** record instead of an `A`:

```
ana@laptop:~$ dig +short MX example.net
10 mail.example.net.
ana@laptop:~$ dig +short A mail.example.net
192.0.2.26
```

`10 mail.example.net.` is the mail exchanger for `example.net`, with a priority of 10; a domain with two
lists both, and the lower number is tried first. The address of that name is the second answer.

**Two kinds of server do two jobs.** One sends: it takes the message from Ana's program on port 587,
and passes it on over port 25 to whichever server the MX names. The other receives: it takes in mail
for its domain on port 25, files it in the mailbox, and lets the owner read it with IMAP or POP3. In
practice one machine often does both for its domain, as `mail.example.com` does here.
