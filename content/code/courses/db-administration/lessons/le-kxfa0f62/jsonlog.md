title: jsonlog, for a machine to read
version: 1
---

A person reads the text log with `grep`. A program that collects logs from many servers — a log
shipper feeding a search engine, a cloud provider's logging service — wants **fields**, and parsing
a prefix with a regular expression breaks the day somebody adds `%a` to it. PostgreSQL 15 added
**`jsonlog`**: one JSON object per line, with every field named.

It needs the logging collector, because only the server's own logger can write a format other than
plain text, so this is a restart:

```
shop=# ALTER SYSTEM SET logging_collector = on;
ALTER SYSTEM

shop=# ALTER SYSTEM SET log_destination = 'jsonlog';
ALTER SYSTEM
```

```
ana@db:~$ sudo systemctl restart postgresql@16-main
```

```
shop=# SELECT pg_current_logfile();
          pg_current_logfile           
---------------------------------------
 log/postgresql-2026-10-10_164137.json
(1 row)

shop=# SELECT 1/0;
ERROR:  division by zero
```

`pg_current_logfile()` has an answer now, because the server opened the file itself. It is a path
relative to the data directory. And the file Ubuntu set up has stopped growing:

```
ana@db:~$ sudo tail -n 5 /var/log/postgresql/postgresql-16-main.log
```

**The last two lines in `/var/log/postgresql` say where the log went.** That is the trap the first
section warned about, seen from the other side: somebody who knows only the Ubuntu default opens
that file, sees a clean shutdown and a start, and concludes nothing has happened since.

```
ana@db:~$ sudo ls -l /var/lib/postgresql/16/main/log
total 8
-rw------- 1 postgres postgres 2186 Oct 10 16:41 postgresql-2026-10-10_164137.json
-rw------- 1 postgres postgres  165 Oct 10 16:41 postgresql-2026-10-10_164137.log
ana@db:~$ sudo sh -c 'tail -n 1 /var/lib/postgresql/16/main/log/*.json' | jq .
{
  "timestamp": "2026-10-10 16:41:40.385 -03",
  "user": "ana",
  "dbname": "shop",
  "pid": 435,
  "remote_host": "[local]",
  "session_id": "6aca94f3.1b3",
  "line_num": 1,
  "ps": "SELECT",
  "session_start": "2026-10-10 16:41:39 -03",
  "vxid": "3/9",
  "txid": 0,
  "error_severity": "ERROR",
  "state_code": "22012",
  "message": "division by zero",
  "statement": "SELECT 1/0;",
  "application_name": "psql",
  "backend_type": "client backend",
  "query_id": 0
}
```

The `sh -c` is there because the directory belongs to `postgres`: the `*` has to be expanded by a
shell that can read it. `jq .` prints the line indented. Every part of the prefix is a field of its own — `user`,
`dbname`, `pid`, `application_name` — and some are there that no prefix had: `state_code` is the
SQLSTATE, `22012` for division by zero, which a program can match without reading English, and
`backend_type` says what kind of process wrote the line. The small `.log` file beside the JSON one
is the collector's plain-text file, which it keeps for anything written to standard error that did
not come through PostgreSQL's own logging.

The files are now named by `log_filename`, by default the date and time the file was opened, and
**rotated by the server**, by `log_rotation_age` (a day) and `log_rotation_size` (10 MB).
logrotate is no longer involved, and nothing deletes old files unless `log_truncate_on_rotation`
and a `log_filename` that repeats are set up to overwrite them, or something outside the server
cleans the directory. That is a second thing to arrange before turning this on for real.

## Putting it all back

The course goes on with Ubuntu's logging, so every parameter this lesson set is reset, the restart
takes the collector away again, and `postgresql.auto.conf` is back to its two comment lines:

```
shop=# ALTER SYSTEM RESET logging_collector;
ALTER SYSTEM

shop=# ALTER SYSTEM RESET log_destination;
ALTER SYSTEM

shop=# ALTER SYSTEM RESET log_line_prefix;
ALTER SYSTEM

shop=# ALTER SYSTEM RESET log_lock_waits;
ALTER SYSTEM

shop=# ALTER SYSTEM RESET log_temp_files;
ALTER SYSTEM
```

```
ana@db:~$ sudo systemctl restart postgresql@16-main
ana@db:~$ sudo cat /var/lib/postgresql/16/main/postgresql.auto.conf
# Do not edit this file manually!
# It will be overwritten by the ALTER SYSTEM command.
ana@db:~$ dropdb bench
ana@db:~$ rm logcost.sh
```
