title: Segurança em nível de linha
version: 1

A Carla atende clientes de São Paulo e do Rio de Janeiro. Para isso ela precisa do nome e do
endereço deles, então o cargo dela tem `SELECT` na tabela de clientes inteira. Hoje isso quer
dizer todos:

```
ana@lab:~/gov$ psql service=carla -c "SELECT count(*) AS customers, count(DISTINCT state) AS states FROM sales.customers"
 customers | states 
-----------+--------
      6012 |     15
(1 row)
```

Seis mil clientes em quinze estados, dos quais o trabalho dela envolve dois. **Uma concessão numa
tabela é tudo ou nada por linha.** Para dar a ela as linhas dos estados dela e nenhuma outra, a
tabela precisa de uma regra sobre linhas, e o PostgreSQL chama isso de **política** (*policy*).

```sql
-- Which states each support agent serves. Only the owner writes it.
SET ROLE ipe_owner;
CREATE TABLE support.agent_regions (
  agent name    NOT NULL,
  state char(2) NOT NULL,
  PRIMARY KEY (agent, state)
);
INSERT INTO support.agent_regions VALUES ('carla', 'SP'), ('carla', 'RJ');
GRANT SELECT ON support.agent_regions TO support_agent;

-- Support agents see the customers of their own states, and no others.
ALTER TABLE sales.customers ENABLE ROW LEVEL SECURITY;
CREATE POLICY agent_sees_own_states ON sales.customers
  FOR SELECT TO support_agent
  USING (state IN (SELECT r.state FROM support.agent_regions r
                   WHERE r.agent = current_user));
```

Duas partes, e as duas são necessárias. `ENABLE ROW LEVEL SECURITY` põe a tabela num modo em que
**toda linha precisa ser permitida por uma política** para que um papel a veja. A política diz
quais: para `SELECT`, para membros de `support_agent`, as linhas cujo `state` é um dos estados
listados para o usuário corrente em `support.agent_regions`. Essa tabela é de `ipe_owner`; os
atendentes podem lê-la e não alterá-la.

```
ana@lab:~/gov$ psql -f rls.sql
SET
CREATE TABLE
INSERT 0 2
GRANT
ALTER TABLE
CREATE POLICY
ana@lab:~/gov$ psql service=carla -c "SELECT count(*) AS customers, count(DISTINCT state) AS states FROM sales.customers"
 customers | states 
-----------+--------
      3386 |      2
(1 row)

ana@lab:~/gov$ psql service=carla -c "SELECT count(*) FROM sales.customers WHERE state = 'MG'"
 count 
-------
     0
(1 row)

ana@lab:~/gov$ psql service=bruno -c "SELECT count(*) FROM sales.customers"
 count 
-------
     0
(1 row)

ana@lab:~/gov$ psql service=site_app -c "SELECT count(*) FROM sales.customers"
ERROR:  permission denied for table customers
```

A Carla agora vê 3.386 clientes em dois estados, e um cliente de Minas Gerais é invisível para
ela: não recusado, **ausente**. A consulta rodou e não achou nada, que é o que ela deve ver.

## O padrão é nada, e é silencioso

Olhe a linha do Bruno. **Zero.** Um minuto antes ele contou 2.322 clientes só em São Paulo.

Ninguém revogou nada dele. O que aconteceu é que a tabela agora exige uma política para cada
linha, e há política para `support_agent` e nenhuma para `analyst`, então nenhuma linha é
permitida. A segurança de linha **falha fechada**, que é a direção certa para um controle falhar.
E também **falha calada**: sem erro, sem aviso, um resultado que é um número perfeitamente válido e
está errado. Todo painel que contava clientes passaria a dizer que a Ipê não tem nenhum, e a
exportação noturna que lê a tabela via `pipeline` gravaria um arquivo vazio e relataria sucesso.

A linha do site é diferente, `permission denied`, porque `app_web` nunca teve `SELECT` na tabela:
a concessão é conferida antes de qualquer política. Segurança de linha estreita o que uma
concessão permite. Nunca a alarga.

Então ligá-la é o momento de escrever uma política para **todo** papel que lê a tabela:

```sql
-- Analysts and the pipeline see every customer: their limit is the columns.
SET ROLE ipe_owner;
CREATE POLICY analysts_see_all ON sales.customers
  FOR SELECT TO analyst, pipeline
  USING (true);
```

```
ana@lab:~/gov$ psql -f rls-analyst.sql

CREATE POLICY
ana@lab:~/gov$ psql service=bruno -c "SELECT count(*) FROM sales.customers"

-------
  6012
(1 row)
```

O limite dos analistas são as colunas, não as linhas, e a política diz isso explicitamente:
`USING (true)`. Uma política que permite tudo parece redundante. É a linha que será lida, daqui a
um ano, por quem se perguntar por que os analistas não são restritos por região — e ela diz que
alguém decidiu.

**Antes de ligar a segurança de linha numa tabela, liste todo papel que a lê.** A matriz da
seção 10 é um jeito, e o exercício final da aula pede que você preveja o que cada papel veria.
