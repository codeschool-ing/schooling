---
title: Row-level security
version: 1
---

Carla answers customers from São Paulo and Rio de Janeiro. To do that she needs their names and
addresses, so her job has `SELECT` on the whole customers table. Today that means all of them:

```
ana@lab:~/gov$ psql service=carla -c "SELECT count(*) AS customers, count(DISTINCT state) AS states FROM sales.customers"
 customers | states 
-----------+--------
      6012 |     15
(1 row)
```

Six thousand customers in fifteen states, of whom her work concerns two. **A grant on a table is
all or nothing per row.** To give her the rows of her states and no others, the table needs a
rule about rows, and PostgreSQL calls that a **policy**.

```sql
-- Which states each support agent serves. Only the owner writes it.
SET ROLE ipe_owner;
CREATE TABLE support.agent_regions (
  agent name    NOT NULL,
  state char(2) NOT NULL,
  PRIMARY KEY (agent, state)
);
INSERT INTO support.agent_regions VALUES ('carla', 'SP'), ('carla', 'RJ');
GRANT SELECT ON support.agent_regions TO support_agent;

-- Support agents see the customers of their own states, and no others.
ALTER TABLE sales.customers ENABLE ROW LEVEL SECURITY;
CREATE POLICY agent_sees_own_states ON sales.customers
  FOR SELECT TO support_agent
  USING (state IN (SELECT r.state FROM support.agent_regions r
                   WHERE r.agent = current_user));
```

Two parts, and both are needed. `ENABLE ROW LEVEL SECURITY` switches the table into a mode where
**every row must be allowed by a policy** before a role can see it. The policy then says which:
for `SELECT`, for members of `support_agent`, the rows whose `state` is one of the states listed
for the current user in `support.agent_regions`. That table is owned by `ipe_owner`; agents may
read it and not change it.

```
ana@lab:~/gov$ psql -f rls.sql
SET
CREATE TABLE
INSERT 0 2
GRANT
ALTER TABLE
CREATE POLICY
ana@lab:~/gov$ psql service=carla -c "SELECT count(*) AS customers, count(DISTINCT state) AS states FROM sales.customers"
 customers | states 
-----------+--------
      3386 |      2
(1 row)

ana@lab:~/gov$ psql service=carla -c "SELECT count(*) FROM sales.customers WHERE state = 'MG'"
 count 
-------
     0
(1 row)

ana@lab:~/gov$ psql service=bruno -c "SELECT count(*) FROM sales.customers"
 count 
-------
     0
(1 row)

ana@lab:~/gov$ psql service=site_app -c "SELECT count(*) FROM sales.customers"
ERROR:  permission denied for table customers
```

Carla now sees 3,386 customers in two states, and a customer from Minas Gerais is invisible to
her: not refused, **absent**. The query ran and found nothing, which is what she should see.

## The default is nothing, and it is silent

Look at Bruno's line. **Zero.** A minute earlier he counted 2,322 customers in São Paulo alone.

Nobody revoked anything from him. What happened is that the table now requires a policy for every
row, and there is a policy for `support_agent` and none for `analyst`, so no row is allowed. Row
security **fails closed**, which is the right direction for a control to fail. It also **fails
quietly**: no error, no warning, a result that is a perfectly valid number and is wrong. Every
dashboard that counted customers would now say Ipê has none, and the nightly export that reads the
table through `pipeline` would write an empty file and report success.

The website's line is different, `permission denied`, because `app_web` never had `SELECT` on the
table: the grant is checked before any policy is. Row security narrows what a grant allows. It
never widens it.

So enabling it is the moment to write a policy for **every** role that reads the table:

```sql
-- Analysts and the pipeline see every customer: their limit is the columns.
SET ROLE ipe_owner;
CREATE POLICY analysts_see_all ON sales.customers
  FOR SELECT TO analyst, pipeline
  USING (true);
```

```
ana@lab:~/gov$ psql -f rls-analyst.sql
SET
CREATE POLICY
ana@lab:~/gov$ psql service=bruno -c "SELECT count(*) FROM sales.customers"
 count 
-------
  6012
(1 row)
```

The analysts' limit is the columns, not the rows, and the policy says so explicitly: `USING
(true)`. A policy that allows everything looks redundant. It is the line that will be read, a year
from now, by whoever wonders why analysts are not restricted by region — and it says somebody
decided.

**Before enabling row security on a table, list every role that reads it.** The matrix in
section 10 is one way, and the lesson's drill asks you to predict what each role would see.
