**Article 6** opens with good faith and lists ten principles that every processing has to respect.
They read like aspirations and work like tests: each one is a question a reviewer can ask of a table,
a pipeline or an export, and each one has an answer in this course.

| principle | the question it asks | where the course answers it |
|---|---|---|
| **purpose** (*finalidade*) | for which legitimate, specific, explicit purpose, told to the person? | the record of processing, lesson 6 |
| **adequacy** (*adequação*) | is the processing compatible with that purpose? | this lesson |
| **necessity** (*necessidade*) | is this the minimum the purpose needs? | minimisation, lesson 6 |
| **free access** (*livre acesso*) | can the person easily find out what is held and how? | sections 8 and 9 |
| **data quality** (*qualidade dos dados*) | is the data accurate, clear, relevant and up to date? | lesson 9 |
| **transparency** (*transparência*) | is the person told clearly, and who the processors are? | the privacy notice, section 8 |
| **security** (*segurança*) | are there technical and administrative measures against access and loss? | lessons 1 to 5 |
| **prevention** (*prevenção*) | is harm prevented before it happens? | the impact assessment, section 11 |
| **non-discrimination** (*não discriminação*) | could the processing be used to discriminate unlawfully or abusively? | lesson 8, on automated decisions |
| **accountability** (*responsabilização e prestação de contas*) | can the controller **demonstrate** it complied? | everything that leaves a record |

## The one that changes how a data team works

The last principle is the one engineers feel most. **Accountability means the controller has to be
able to show compliance**, not only to have achieved it. A grant scheme that is right but nobody can
list; a deletion that happened but left no record; a consent given but not stored with its wording —
each is compliance nobody can demonstrate, and to an inspector it is the same as none.

That is why so much of this course writes things down where a query can read them: the access matrix
of lesson 2, the classification of lesson 6, the consent events and the request log of this lesson,
the audit trail of lesson 10. **The record is the deliverable**, not a by-product.
