title: Os marcos que uma análise tem
version: 1
---

Um plano para uma análise não precisa de software. **Precisa de cinco ou seis marcos, cada um com uma data e
algo que você poderia mostrar a alguém naquela data.** Um marco sem nada para mostrar é uma esperança.

Repare que o primeiro recorte vem **antes** de o marco dos dados terminar: a Marina juntou uma versão grosseira
das tabelas na segunda semana e mostrou o resultado enquanto o Diego ainda conferia as definições. Marcos
podem se sobrepor; o que importa é que cada um produza algo visível.

## Alguém vigia as datas

Num projeto de uma pessoa, o analista também é o gerente do projeto, e o trabalho é simples: **em cada data de
marco, confira se a coisa existe, e se não, diga no mesmo dia** a quem está esperando. Um atraso relatado no
dia em que acontece é um problema de agenda. O mesmo atraso descoberto na semana da reunião é um problema de
credibilidade.

## O plano é uma ferramenta de comunicação

A tabela de marcos também é o esqueleto da atualização semanal da aula 13: o feito na semana é o marco que
acabou de passar, a próxima semana é o seguinte. **Um stakeholder que vê o plano não precisa perguntar como
está indo**, e um gestor que o vê consegue proteger as datas quando chega um pedido novo, como o registro de
pedidos da aula 13 faz pelas prioridades.
