@ interpolation quiz easy #ex-jd16aac4

?? `note` guarda a string `<b>bold?</b>`, e o template escreve `{{ note }}`. O que a página mostra?
- The word `bold?` in bold :: That would mean the string became markup, which interpolation never lets happen.
-- A palavra `bold?` em negrito :: Isso significaria que a string virou marcação, o que a interpolação nunca permite.
+ The characters `<b>bold?</b>`, as text :: Right. Interpolation always produces text.
++ Os caracteres `<b>bold?</b>`, como texto :: Isso. A interpolação sempre produz texto.
- Nothing, because Angular removes HTML from strings :: Nothing is removed; the characters are shown as they are.
-- Nada, porque o Angular remove HTML de strings :: Nada é removido; os caracteres aparecem como são.
- A build error, because the string looks like a tag :: The compiler does not inspect the contents of a string field.
-- Um erro de build, porque a string parece uma tag :: O compilador não inspeciona o conteúdo de um campo string.

@ interpolation quiz medium #ex-gmp9gm8j
? Which of these may a template expression inside `{{ }}` do?
?? O que destes uma expressão de template dentro de `{{ }}` pode fazer?
- `minutes = 0`, to reset a field before showing it :: Assignment is only allowed in an event binding.
-- `minutes = 0`, para zerar um campo antes de mostrá-lo :: Atribuição só é permitida num event binding.
- `console.log(minutes)`, to debug :: A template sees the component and nothing else, so no globals.
-- `console.log(minutes)`, para depurar :: Um template vê o componente e mais nada, então nenhum global.
+ `course.sessions * minutes` :: Right. Reading properties and doing arithmetic are allowed.
++ `course.sessions * minutes` :: Isso. Ler propriedades e fazer contas é permitido.
- `new Date()`, to show today :: `new` is not allowed in a template expression.
-- `new Date()`, para mostrar hoje :: O `new` não é permitido numa expressão de template.

@ property-binding quiz medium #ex-z5be2z4m
? `--html` showed no `value` attribute on the `<input>`, yet the field showed 45. Why?
?? O `--html` não mostrou atributo `value` no `<input>`, e mesmo assim o campo mostrava 45. Por quê?
- The binding failed, and the 45 is the browser's default :: A number field has no default of 45; the binding set it.
-- O binding falhou, e o 45 é o padrão do navegador :: Um campo numérico não tem 45 como padrão; o binding o definiu.
+ `[value]` set the property, which does not reflect into the attribute :: Right. The attribute is only the starting text; the property is what is in the box.
++ O `[value]` definiu a propriedade, que não reflete no atributo :: Isso. O atributo é só o texto inicial; a propriedade é o que está na caixa.
- `look --html` removes attributes Angular added :: It removes only `_ngcontent-` and `_nghost-`, and the min and max were shown.
-- O `look --html` remove os atributos que o Angular acrescentou :: Ele só remove `_ngcontent-` e `_nghost-`, e o min e o max apareceram.
- Angular stores the value in a hidden attribute :: Nothing is hidden; it sets the DOM property.
-- O Angular guarda o valor num atributo escondido :: Nada é escondido; ele define a propriedade do DOM.

@ property-binding quiz hard #ex-e9mw3cw2
? `<td [colspan]="2">` failed with `NG8002: Can't bind to 'colspan' since it isn't a known property of 'td'`. Which fix keeps the binding?
?? `<td [colspan]="2">` falhou com `NG8002: Can't bind to 'colspan' since it isn't a known property of 'td'`. Qual conserto mantém o binding?
- Import `CommonModule`, which teaches Angular table properties :: No module adds DOM properties; the property is called something else.
-- Importar o `CommonModule`, que ensina ao Angular as propriedades de tabela :: Nenhum módulo acrescenta propriedades do DOM; a propriedade tem outro nome.
- Write `colspan="{{ 2 }}"` :: Interpolation in an attribute is a property binding too, and fails the same way.
-- Escrever `colspan="{{ 2 }}"` :: Interpolação num atributo também é property binding, e falha do mesmo jeito.
+ `[attr.colspan]="2"` :: Right. It sets the attribute by its HTML name.
++ `[attr.colspan]="2"` :: Isso. Ele define o atributo pelo nome HTML.
- Add `CUSTOM_ELEMENTS_SCHEMA` to the component :: That silences checks for unknown elements; it would hide the mistake, not fix it.
-- Acrescentar `CUSTOM_ELEMENTS_SCHEMA` ao componente :: Isso cala as conferências de elementos desconhecidos; esconderia o erro, não o consertaria.

@ property-binding quiz medium #ex-403jqa6h

?? Por que `[disabled]="minutes >= 240"` em vez de escrever `disabled="false"` no HTML quando o botão deve ficar habilitado?

-- `disabled="false"` daria erro de build :: Compila; só não faz o que diz.
+ In HTML its mere presence switches the control off :: Right. The binding passes a real boolean to the property.
++ No HTML, a simples presença do atributo desliga o controle :: Isso. O binding passa um booleano de verdade para a propriedade.

-- O property binding desenha mais rápido :: A velocidade não é a diferença; o sentido é.
- Buttons ignore attributes and only read properties :: They read both; the attribute's presence is what disables.
-- Botões ignoram atributos e só leem propriedades :: Leem os dois; a presença do atributo é o que desabilita.
