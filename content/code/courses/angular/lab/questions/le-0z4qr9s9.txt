# Lesson 6: signals

@ signal quiz easy #ex-rtrbhk8f
? How does a template read the value of a signal called `minutes`?
?? Como um template lê o valor de um signal chamado `minutes`?
- `{{ minutes }}`, as with a plain field :: Without parentheses that is the signal itself, a function, and the template check refuses it.
-- `{{ minutes }}`, como um campo comum :: Sem parênteses isso é o próprio signal, uma função, e a conferência do template recusa.
+ `{{ minutes() }}` :: Right. A signal is read by calling it, in a template as in code.
++ `{{ minutes() }}` :: Isso. Um signal é lido chamando-o, no template como no código.
- `{{ minutes.value }}` :: That is how a resource exposes its value, as a signal you still call.
-- `{{ minutes.value }}` :: É assim que um resource expõe o valor, como um signal que ainda se chama.
- `{{ minutes.get() }}` :: There is no `get`; the call itself reads it.
-- `{{ minutes.get() }}` :: Não existe `get`; a própria chamada lê.

@ signal quiz medium #ex-r57xx0c3
? Why does the lesson prefer `minutes.update((m) => m + 15)` to `minutes.set(minutes() + 15)`?
?? Por que a aula prefere `minutes.update((m) => m + 15)` a `minutes.set(minutes() + 15)`?
- `set` cannot take an expression :: It takes any value; the difference is where the old value comes from.
-- O `set` não aceita uma expressão :: Ele aceita qualquer valor; a diferença está em de onde vem o valor antigo.
- `update` is faster :: Speed is not the reason given.
-- O `update` é mais rápido :: Velocidade não é o motivo dado.
+ Old and new in one call :: Right. The read and the write cannot drift apart.
++ Antigo e novo na mesma chamada :: Isso. A leitura e a escrita não têm como se separar.
- `set` does not notify readers :: Both notify readers of a change.
-- O `set` não avisa quem lê :: Os dois avisam quem lê sobre uma mudança.

@ signal quiz medium #ex-yq54arsq
? Why is a signal field in a component declared `readonly`?
?? Por que um campo signal num componente é declarado `readonly`?
- So its value cannot change :: The value changes through `set` and `update`; `readonly` is about the field.
-- Para o valor dele não mudar :: O valor muda pelo `set` e pelo `update`; o `readonly` é sobre o campo.
+ So nobody replaces the signal itself :: Right. The field always holds the same signal, whose value changes.
++ Para ninguém trocar o próprio signal :: Isso. O campo guarda sempre o mesmo signal, cujo valor muda.
- Templates can only read `readonly` fields :: They read `protected` and `public` fields alike.
-- Templates só leem campos `readonly` :: Eles leem campos `protected` e `public` igualmente.
- Angular requires it for signals to work :: Signals work in a mutable field too; it would just be a trap.
-- O Angular exige isso para os signals funcionarem :: Signals funcionam num campo mutável também; só seria uma armadilha.

++ Essa leitura não é rastreada como dependência :: Isso. Só os signals chamados enquanto a função roda são rastreados.

? Which of these marks a session done in a way a signal notices?
?? Qual destes marca uma sessão como feita de um jeito que um signal percebe?
- `sessions()[0].done = true` :: That changes an object in place; the signal holds the same array.
-- `sessions()[0].done = true` :: Isso muda um objeto no lugar; o signal guarda o mesmo array.
- `sessions.update((l) => { l[0].done = true; return l; })` :: It returns the same array, so `Object.is` finds no change.
-- `sessions.update((l) => { l[0].done = true; return l; })` :: Devolve o mesmo array, então o `Object.is` não vê mudança.
+ `sessions.update((l) => l.map((s, i) => (i === 0 ? { ...s, done: true } : s)))` :: Right. A new array, with a new object for the changed session.
++ `sessions.update((l) => l.map((s, i) => (i === 0 ? { ...s, done: true } : s)))` :: Isso. Um array novo, com um objeto novo para a sessão alterada.
- `sessions.set(sessions())` after changing the object :: Setting the same array is no change.
-- `sessions.set(sessions())` depois de mudar o objeto :: Definir o mesmo array não é mudança.
