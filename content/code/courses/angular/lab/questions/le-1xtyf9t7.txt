# Lesson 7: change detection

@ what-it-does quiz easy #ex-34zw7xjm
? What does Angular do during change detection?
?? O que o Angular faz durante a detecção de mudanças?
- It reloads the component's data from the server :: Loading is the resource's or the service's job; the walk only reads the classes.
-- Recarrega os dados do componente do servidor :: Carregar é trabalho do resource ou do serviço; a passada só lê as classes.
+ Re-reads every template, then fixes the DOM :: Right. It walks the tree and compares.
++ Relê os templates e corrige o DOM :: Isso. Ele percorre a árvore e compara.
- It recompiles the templates that changed on disk :: That is the dev server rebuilding, not change detection.
-- Recompila os templates que mudaram em disco :: Isso é o servidor de desenvolvimento reconstruindo, não detecção de mudanças.
- It destroys and recreates every component :: Components survive a walk; only the DOM values that differ are touched.
-- Destrói e recria todo componente :: Os componentes sobrevivem a uma passada; só os valores do DOM que diferem são tocados.

@ what-it-does quiz medium #ex-ttm6vx05
? `label()` was called again after a click on a button whose handler does nothing. Why?
?? O `label()` foi chamado de novo depois de um clique num botão cujo handler não faz nada. Por quê?
- The click changed `label`'s return value for this one time :: It returns the same text every time.
-- O clique mudou o valor que `label` devolve, só desta vez :: Ele devolve sempre o mesmo texto.
- `look` reloaded the page after it clicked the button :: The page loaded once; the extra calls came from walks.
-- O `look` recarregou a página depois de clicar no botão :: A página carregou uma vez; as chamadas a mais vieram de passadas.
+ Events schedule walks, and methods are asked again :: Right. Angular cannot know a method's answer without calling it.
++ Eventos agendam passadas, e métodos são consultados de novo :: Isso. O Angular não sabe a resposta de um método sem chamá-lo.
- Methods in templates are run on a timer by Angular :: There is no timer; walks happen when something schedules them.
-- Métodos em templates são rodados num timer pelo Angular :: Não há timer; as passadas acontecem quando algo as agenda.

@ what-it-does quiz medium #ex-keb86t4m
? In development mode, why does Angular walk the tree twice in a row?
?? Em modo de desenvolvimento, por que o Angular percorre a árvore duas vezes seguidas?
+ To check nothing changed between the walks :: Right. A difference is the `NG0100` error.
++ Para conferir que nada mudou entre as passadas :: Isso. Uma diferença é o erro `NG0100`.
- Because the first walk only reads and the second one writes the DOM :: Each walk does both; the second only compares.
-- Porque a primeira passada só lê e a segunda escreve o DOM :: Cada passada faz as duas coisas; a segunda só compara.
- To warm up the cache before production :: Development builds are not a warm-up for production ones.
-- Para aquecer o cache antes da produção :: Builds de desenvolvimento não aquecem os de produção.
- Because zone.js is loaded twice :: The planner has no zone.js, and the second walk happened anyway.
-- Porque o zone.js é carregado duas vezes :: O planner não tem zone.js, e a segunda passada aconteceu mesmo assim.

- `look`, which clicks the page while it waits :: `--wait` only waits.
-- O `look`, que clica na página enquanto espera :: O `--wait` só espera.

?? Com o zone.js, o campo comum do componente OnPush ficou 0 depois do timer. Por quê?

-- O zone.js não envolve timers de componentes OnPush :: O mesmo timer disparou uma passada; a passada pulou o componente.

- OnPush components are only checked once, at creation :: They are checked whenever marked; this one never was.

- The timer threw an error inside the OnPush component :: There was no error; the value simply was not read again.
-- O timer lançou um erro dentro do componente OnPush :: Não houve erro; o valor só não foi lido de novo.

- The parent must call `markForCheck()` on itself :: Marking the parent does not change the child's input.
-- O pai precisa chamar `markForCheck()` em si mesmo :: Marcar o pai não muda o input do filho.
