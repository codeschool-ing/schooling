@ constructor-or-init quiz medium #ex-58b5vh1c
? Why does a `computed` that reads an input work even when it is declared as a field?
?? Por que um `computed` que lê um input funciona mesmo declarado como campo?
+ It reads nothing until someone reads it :: Right. By then the input is set.
++ Ele não lê nada até alguém o ler :: Isso. Até lá o input já está definido.
- Fields are initialised after `ngOnInit` :: Fields are initialised during construction, before any hook.
-- Campos são inicializados depois do `ngOnInit` :: Campos são inicializados durante a construção, antes de qualquer hook.
- Angular delays every field until the inputs are set :: Only the computed's own work is delayed, because it is lazy.
-- O Angular adia todo campo até os inputs serem definidos :: Só o trabalho do próprio computed é adiado, porque ele é preguiçoso.
- A computed copies the input's default value :: It reads the input when asked; it copies nothing.
-- Um computed copia o valor padrão do input :: Ele lê o input quando é perguntado; não copia nada.

@ constructor-or-init quiz hard #ex-n947th3p
? Which of these is still a fair reason to write `ngOnInit` in new code?
?? Qual destes ainda é um motivo justo para escrever `ngOnInit` em código novo?

-- Para ler um input num campo uma vez, para o template :: Um `computed` faz isso e acompanha o input.

++ Um ato único que precisa dos inputs :: Isso. Um effect o repetiria sempre que o input mudasse.

-- Para limpar um timer :: Limpar é trabalho do `DestroyRef`.
