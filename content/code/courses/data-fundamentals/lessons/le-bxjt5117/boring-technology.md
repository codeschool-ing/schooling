---
title: Boring technology and innovation tokens
version: 1
---

**"Boring" in technology means that its failures are already known, and that is the most valuable
property a tool can have.** The word sounds like an insult, and the picture it calls up is old,
slow software that nobody chooses on purpose. That picture is wrong. A boring tool is one so many
people have run for so long that when it fails, the failure has a name, a search result and a fix.

The argument has a source. Dan McKinley's essay *Choose Boring Technology* (2015) puts it as a
budget: **every company gets about three innovation tokens**, and each new, unfamiliar technology
spends one. A token buys the chance to do something better than anybody else. It also buys every
problem that technology has which nobody has met yet, and those are the expensive ones: the
problems you know you have can be planned for, and the ones nobody has seen arrive at night.

## Where Roda Livre should spend its tokens

The question to ask is what the company competes on. Roda Livre competes on having a bicycle at the
station when somebody wants one. A forecast of which stations will run dry, which is Caio's work, is
close to that. A novel database for storing rides is not, and a token spent there buys no bicycle
anywhere.

So the data platform should be boring on purpose: a relational database, files in a well-known
format, Python, programs run on a schedule. If the company spends a token, it spends it on the
forecast, where being better than the ordinary is the point.

## Résumé-driven development

There is a reason boring choices lose arguments they should win. A new tool is interesting, it looks
good on a CV, and the person proposing it may not be there when it fails. **Choosing a technology for
what it does for the chooser's career rather than for the problem** has a name, résumé-driven
development, and it is common enough that the name is a joke everybody in the field understands.

The defence is the criteria from two sections back, asked out loud: which problem of ours does this
solve that the boring option does not, and who will be on call for it?

## When to leave the boring option

Boring is a default and not a rule. A boring tool that has stopped coping is an argument for changing
it, provided the evidence is measured rather than predicted: a query Marta needs that takes ten
minutes, a nightly load that no longer finishes before morning, a bill that doubled in a quarter.
**"It will not scale" is a forecast; "it took ten minutes this morning" is a fact**, and a token is
better spent on a fact.
