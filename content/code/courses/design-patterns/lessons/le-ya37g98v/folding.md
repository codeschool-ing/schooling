**To know the current state of an event-sourced thing, you start from an empty state and apply its
events one by one, in order; each step takes a state and an event and gives the next state.** That
operation is a *fold*, `functools.reduce` in Python, `reduce` on a JavaScript array, a loop with an
accumulator in Go or Java. The function that takes one step is usually called `apply` or `evolve`,
and it is the heart of an event-sourced model.

The belief to set aside is that the fold is a recovery procedure, something run after a crash. It is
run on every command. Before deciding whether Bia may borrow, the program folds her stream, and
the state it gets is the only state there is.

After four events Bia holds C1 and owes 150 cents, at version 4. Folding only the first two gives her
state at version 2, holding C3 and owing nothing, and **that is the whole of time travel in an
event-sourced system**: stop the fold early. The loan is refused while she owes money, she pays,
and the same loan goes through, leaving the stream at version 6.

## Two functions, two jobs

The program splits its logic in two, and the split is the pattern.

**`evolve` never refuses.** It receives events, which are facts. If `evolve` raised an exception
for a `CopyReturned` it did not like, the member's stream would become unreadable, because that
event is stored and will be folded on every command forever. The rules belong before the event
exists, in the command.

**`lend` decides and never changes state directly.** It folds, checks, and appends an event; the
state it computed is thrown away. The next command will fold again and see the new loan because the
event is now in the stream. This pairing is often called *decide* and *evolve*, and it keeps the
rules testable as a function: given these past events and this command, which new events, or which
refusal?

```python
assert reduce(evolve, [{"type": "MemberJoined", "name": "Bia"},
                       {"type": "CopyLent", "copy": "C3", "due": "2026-03-16"}],
              Member()) == Member("Bia", ("C3",), 0)
```

A test of an event-sourced model reads like the history it is about, with no database setup and no
mocks.

## What the fold costs

Every command reads and folds the whole stream. Bia's six events cost nothing. A member with ten
years of loans has thousands, and a stream per copy of a popular book grows without limit. The
fold's cost grows with the stream, which is the reason for snapshots, two sections on. Before that,
the same history feeds the other side of lesson 8's split.
