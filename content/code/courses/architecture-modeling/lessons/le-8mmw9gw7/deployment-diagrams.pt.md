**Um diagrama de implantação mostra o lado físico: as máquinas e os ambientes em que o software
roda, o que está instalado em cada um, e como eles se ligam.** Ele responde às perguntas que a
operação faz: *o que roda onde?*, *o que fala com o quê pela rede?*, *o que se perde se esta máquina
cair?*

## A notação

- Um **nó** é uma caixa tridimensional: algo que consegue rodar software. A UML separa dois tipos,
  marcados com palavras-chave: um **`«device»`**, uma peça física de hardware, como o celular de um
  motorista, e um **`«executionEnvironment»`**, um ambiente de software que hospeda outro software,
  como um runtime de containers, uma máquina virtual ou um serviço de banco de dados gerenciado.
- Nós **se aninham**: um ambiente de execução desenhado dentro de um dispositivo roda nele.
- Um **artefato** é um arquivo concreto que é implantado: `ticketing-api.jar`, uma imagem de
  container, um pacote de app. É um retângulo com a palavra-chave `«artifact»`, desenhado dentro do
  nó em que é implantado.
- Um **caminho de comunicação** é uma linha contínua entre nós, com o protocolo no rótulo: `HTTPS`,
  `PostgreSQL wire protocol`.

O diagrama diz, de um jeito que o diagrama de componentes não conseguia:

- A API de passagens roda em **três réplicas** num cluster de containers, numa região de nuvem. A
  multiplicidade no nó diz isso; o diagrama de componentes tinha uma *Ticketing* só.
- O banco de reservas é um **serviço gerenciado** na mesma região, um nó próprio, e cada réplica
  chega a ele pela rede.
- O **app de embarque roda nos celulares de 300 motoristas**, cada um com uma cópia local das
  passagens do dia para o seu ônibus. Esse armazenamento local é o que faz o embarque funcionar numa
  estrada sem sinal, e ele é invisível em todos os outros diagramas desta aula.
- O gateway de pagamento é **o nó de outra empresa**, alcançado pela internet, desenhado sem nada
  dentro, porque a Carcará não sabe nem controla o que roda lá.

## Erros

- **Partes lógicas desenhadas como nós.** *Pricing* desenhado como uma caixa 3D afirma que é uma
  máquina. Se é um módulo dentro do serviço de passagens, o lugar dele é dentro do artefato, ou então
  no diagrama de componentes.
- **Linhas sem protocolo.** Num diagrama de implantação, o protocolo é o essencial: é ele que decide
  as regras de firewall, a criptografia e o que quebra quando uma porta é fechada.
- **Uma caixa por servidor, em escala.** Quarenta nós idênticos desenhados quarenta vezes escondem o
  único fato de que o leitor precisa, que é *quarenta*. Desenhe um e escreva a quantidade.
- **O diagrama do ano passado.** A infraestrutura muda mais vezes do que o modelo de domínio. Um
  diagrama de implantação é o primeiro a ficar desatualizado, e é por isso que a aula 12 mostra como
  gerar um, e a aula 11 como saber quando um morreu.

**Desenhe você também.** Desenhe a implantação do back office das rodoviárias: os computadores de
mesa dos agentes em 26 rodoviárias, a impressora de comprovantes em cada guichê, e a mesma API de
passagens na nuvem. Decida do que os computadores dos agentes precisam localmente se a internet da
rodoviária cair.
