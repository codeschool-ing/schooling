---
title: Quatro jeitos de renderizar uma página
version: 1
---

**Uma página SvelteKit pode ser renderizada no servidor, no navegador ou nos dois, e a renderização do
servidor pode acontecer a cada requisição ou uma vez só, no build.** Toda página do planner até aqui teve
o padrão: o servidor renderiza o HTML para a primeira requisição, e o navegador o **hidrata**, roda os
mesmos componentes sobre o HTML que recebeu e assume dali em diante. A aula 13 viu a segunda metade
acontecer quando uma função load universal imprimiu a sua linha nos dois lugares.

Duas **opções de página**, `ssr` e `csr`, ligam e desligam as metades, e uma terceira, `prerender`, leva a
metade do servidor para o momento do build. Elas são exportadas de um `+page.js`, `+page.server.js`,
`+layout.js` ou `+layout.server.js`, e o valor de um layout vale para todas as páginas abaixo dele, a
menos que uma página diga outra coisa:

| `ssr` | `csr` | `prerender` | a primeira resposta | JavaScript no navegador |
|---|---|---|---|---|
| `true` | `true` | `false` | HTML renderizado para esta requisição | hidrata, depois cuida de cada clique |
| `true` | `false` | `false` | HTML renderizado para esta requisição | **nenhum** |
| `false` | `true` | `false` | uma página vazia | renderiza tudo |
| `true` | qualquer um | `true` | HTML renderizado **quando o site foi construído**, de um arquivo | o que o `csr` disser |

**O padrão é a resposta certa para as páginas do próprio planner**, e o resto desta aula mostra por quê
experimentando as outras. A página que se vira com menos é About: ela não tem dados, nem estado, nem
formulário, nem nada para clicar além de dois links, então não precisa de JavaScript nenhum e pode ser
escrita num arquivo uma vez, quando a aplicação é construída.

Para ver o que cada opção manda de verdade, as medidas desta aula vêm de um **build**, o código como ele
seria publicado, e não do servidor de desenvolvimento, que acrescenta scripts próprios em toda página para
poder atualizá-las enquanto você salva. Um build precisa de um adaptador que produza algo que rode, e o
planner ainda não tem um. A próxima seção resolve isso.
