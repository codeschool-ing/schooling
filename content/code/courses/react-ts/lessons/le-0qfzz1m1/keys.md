title: What a key is for
version: 1

**A key tells React which item is which between two renders.** Lesson 3 showed that React keeps a
component's state as long as the same type stays at the same position. In a list, "position" is the
order of the array, and the order is exactly what changes when an item is added, removed or sorted.
The key replaces position with identity: **the item with key `s2` is the same item it was last time,
wherever it now sits**, so React moves its DOM node and its state with it.

Three rules follow, and each is the opposite of a mistake people make:

- **Stable.** The same item has the same key on every render. `Math.random()` or a counter that runs
  during rendering gives every item a new key every time, so React throws away every element and
  builds the list again, losing focus, scroll positions and whatever was typed.
- **Unique among its siblings.** Two items with the same key are two items React cannot tell apart.
  Keys only need to be unique within one array; the course `statistics` and a session `statistics`
  in another list do not clash.
- **From the data.** The right key is the item's own id, the one the data already carries. The
  planner's courses have `id: 'statistics'` and its sessions `id: 's1'`, and lesson 1 put them there
  for this reason among others. When the app creates an item, it gives it an id at that moment; lesson
  10 does that with `crypto.randomUUID()`, once, when the session is made, which is stable from then on.

**The index is the key React uses when you give none**, and the warning exists because it is right
only when the list never changes order and never has an item inserted or removed anywhere but the
end. The planner's session list is sorted. The next section shows what that means.

A key is not a prop. `CourseCard` cannot read `props.key`, because React takes it out before the props
reach the component. If a component needs the id, pass it as well, under another name, as the planner
passes `course`.
