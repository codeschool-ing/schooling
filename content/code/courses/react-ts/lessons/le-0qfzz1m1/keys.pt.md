title: Para que serve uma key
version: 1

**Uma key diz ao React qual item é qual entre duas renderizações.** A aula 3 mostrou que o React
mantém o estado de um componente enquanto o mesmo tipo fica na mesma posição. Numa lista, "posição" é
a ordem do array, e a ordem é exatamente o que muda quando um item é acrescentado, removido ou
ordenado. A key troca a posição pela identidade: **o item com key `s2` é o mesmo item da vez
anterior, onde quer que esteja agora**, então o React move o nó do DOM e o estado dele junto.

Três regras decorrem disso, e cada uma é o contrário de um erro que as pessoas cometem:

- **Estável.** O mesmo item tem a mesma key em toda renderização. `Math.random()` ou um contador que
  roda durante a renderização dá a cada item uma key nova toda vez, então o React joga fora todo
  elemento e monta a lista de novo, perdendo o foco, a posição de rolagem e o que foi digitado.
- **Única entre os irmãos.** Dois itens com a mesma key são dois itens que o React não consegue
  distinguir. As keys só precisam ser únicas dentro de um array; o curso `statistics` e uma sessão
  `statistics` em outra lista não colidem.
- **Dos dados.** A key certa é o id do próprio item, o que os dados já trazem. Os cursos do
  planejador têm `id: 'statistics'` e as sessões `id: 's1'`, e a aula 1 os pôs lá por esse motivo,
  entre outros. Quando o app cria um item, dá a ele um id naquele momento; a aula 10 faz isso com
  `crypto.randomUUID()`, uma vez, quando a sessão é criada, e daí em diante ele é estável.

**O índice é a key que o React usa quando você não dá nenhuma**, e o aviso existe porque ela só está
certa quando a lista nunca muda de ordem e nunca tem um item inserido ou removido fora do fim. A lista
de sessões do planejador é ordenada. A próxima seção mostra o que isso quer dizer.

Uma key não é uma prop. O `CourseCard` não consegue ler `props.key`, porque o React a tira antes de as
props chegarem ao componente. Se um componente precisa do id, passe-o também, com outro nome, como o
planejador passa `course`.
