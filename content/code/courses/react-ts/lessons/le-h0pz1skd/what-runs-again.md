its state, and every other difference in this lesson comes out of it.

**React runs your code again and compares.** Its unit of change is the component: state changed, so the
component is called, and React works out what is different by comparing the old result with the new. It
knows nothing about which values the markup read, so it cannot do less than call the whole function.
That is why this course spent lesson 7 on `useMemo` and lesson 21 on `memo` and the React Compiler: a
model that re-runs everything needs a way to skip what did not change, and the compiler is React writing
those skips for you.

**The other three track what was read.** Vue's `ref`, Svelte's `$state` and Angular's `signal` are three
spellings of one idea, which the field calls **signals**: a value that knows who read it. When it
changes, only those readers are told. Your component's code ran once, to set the readers up, and never
needs to run again. How far down the update goes differs: Vue still re-renders the component's template
and compares, Angular checks the template's bindings, and Svelte's compiler wrote one small update per
place in the markup, so there is nothing to compare at all.

Three consequences you have already met from React's side:

- **Mutation.** Vue and Svelte let `toggle` write `session.done` straight into the array, because a proxy
  sees the write. React and Angular's signals decide whether something changed by asking whether it is
  the same object, so both need a new array. Lesson 4's "replace, don't mutate" is a rule of React's
  model, not of JavaScript.
- **Stale values.** A React component is a function called many times, and each call sees the state of
  its own render. That is where lesson 5's dependency arrays and lesson 6's rules of hooks came from. A
  Vue `<script setup>` or an Angular constructor runs once, so it has no renders to be stale between,
  and none of the other three asks for a dependency array: `computed` and `$derived` find their
  dependencies by watching what they read.
- **Templates or JavaScript.** React's markup is JavaScript, so a list is `map` and a condition is `&&`,
  with every JavaScript tool working on it unchanged. The other three have a template language,
  `v-for`, `{#each}`, `@for`, and each ships its own compiler and its own type checker to read it.
  JSX asks you to know JavaScript well; a template asks you to learn one more small language, and in
  exchange the framework can see what the markup reads.

None of this makes React slow. A comparison over a few hundred elements takes far less time than a person
takes to notice. What the model costs
is **the reasoning**: knowing when a value is recreated, why an effect ran, which component re-rendered.
Signals move that cost elsewhere, to knowing which value is reactive and which is a plain copy of one.
