**Os quatro imprimiram a mesma página e discordaram de um número.** O React registrou `Sessions ran` três
vezes, os outros três uma vez. Esse número é a diferença entre duas ideias de como uma interface acompanha
o seu estado, e toda outra diferença desta aula sai dela.

**O React roda o seu código de novo e compara.** A unidade de mudança dele é o componente: o estado mudou,
então o componente é chamado, e o React descobre o que está diferente comparando o resultado antigo com o
novo. Ele não sabe nada sobre que valores o markup leu, então não consegue fazer menos que chamar a função
inteira. É por isso que este curso gastou a aula 7 com o `useMemo` e a aula 21 com o `memo` e o React
Compiler: um modelo que roda tudo de novo precisa de um jeito de pular o que não mudou, e o compilador é o
React escrevendo esses atalhos por você.

**Os outros três acompanham o que foi lido.** O `ref` do Vue, o `$state` do Svelte e o `signal` do Angular
são três grafias de uma ideia, que a área chama de **signals**: um valor que sabe quem o leu. Quando ele
muda, só esses leitores são avisados. O código do seu componente rodou uma vez, para montar os leitores, e
nunca precisa rodar de novo. Até onde a atualização desce varia: o Vue ainda renderiza de novo o template
do componente e compara, o Angular confere os bindings do template, e o compilador do Svelte escreveu uma
atualização pequena para cada lugar do markup, então não há nada a comparar.

Três consequências que você já encontrou do lado do React:

- **Mutação.** O Vue e o Svelte deixam o `toggle` escrever `session.done` direto no array, porque um proxy
  vê a escrita. O React e os signals do Angular decidem se algo mudou perguntando se é o mesmo objeto,
  então os dois precisam de um array novo. O "substitua, não altere" da aula 4 é uma regra do modelo do
  React, não do JavaScript.
- **Valores velhos.** Um componente React é uma função chamada muitas vezes, e cada chamada vê o estado da
  sua própria renderização. Foi daí que vieram os arrays de dependências da aula 5 e as regras dos hooks da
  aula 6. Um `<script setup>` do Vue ou um constructor do Angular roda uma vez, então não tem
  renderizações entre as quais ficar velho, e nenhum dos outros três pede um array de dependências: o
  `computed` e o `$derived` acham suas dependências observando o que leem.
- **Templates ou JavaScript.** O markup do React é JavaScript, então uma lista é `map` e uma condição é
  `&&`, com toda ferramenta de JavaScript funcionando nele sem mudança. Os outros três têm uma linguagem
  de template, `v-for`, `{#each}`, `@for`, e cada um traz o próprio compilador e o próprio verificador de
  tipos para lê-la. O JSX pede que você conheça bem o JavaScript; um template pede que você aprenda mais
  uma linguagem pequena, e em troca o framework consegue ver o que o markup lê.

Nada disso deixa o React lento. Uma comparação sobre algumas centenas de elementos leva muito menos tempo
do que uma pessoa leva para notar. O que o modelo custa é **o raciocínio**: saber quando um valor é
recriado, por que um efeito rodou, que componente renderizou de novo. Os signals levam esse custo para
outro lugar, para saber que valor é reativo e qual é uma cópia comum de um.
