**Autenticação responde "quem está pedindo?"; autorização responde "essa pessoa pode fazer isso?"**
São duas perguntas, feitas nessa ordem, e uma API precisa das duas respostas antes de fazer
qualquer coisa. As aulas 7 a 10 foram a primeira pergunta: uma senha, um token, uma sessão, uma
afirmação assinada. Esta aula parte do princípio de que ela foi respondida e faz a segunda.

O erro comum é tomar a primeira resposta pela segunda. Um token válido prova que a requisição vem
da Ana. Não diz nada sobre se a Ana pode ler o pedido 3, estornar o pedido 2 ou listar todos os
clientes, e uma API que para de checar quando sabe quem chamou deixa qualquer conta fazer tudo o que
alguma conta pode.

O HTTP tem um código para cada falha: **401** quando a primeira pergunta não tem resposta, **403**
quando a segunda resposta é não. A seção "401, 403 ou 404" diz quando nenhum dos dois é o certo.

## Onde a checagem mora

Três regras decidem onde vai uma checagem de autorização, e cada uma corrige um erro que se comete
com frequência.

**No servidor.** Um botão que a interface esconde dos clientes é uma conveniência, não uma
checagem. A requisição que esse botão mandaria pode ser digitada com curl, como toda requisição
deste curso foi, então o que quer que o cliente mostre ou esconda, o servidor decide de novo.

**Em toda requisição.** Uma checagem feita uma vez no login e lembrada, ou feita na página que lista
os pedidos e não no endereço de um pedido, deixa todas as outras portas abertas. Cada requisição
leva o seu token e é julgada sozinha.

**Num lugar só.** Uma checagem copiada em quarenta handlers são quarenta chances de esquecer uma, e
a esquecida parece igualzinha às outras até alguém pedir a ela a coisa errada. No `orders.py`, três
seções adiante, toda requisição passa por uma função, `dispatch`, antes de qualquer handler rodar.
As checagens que precisam do próprio pedido moram em mais uma, `find`, que todo handler que recebe o
id de um pedido chama.

A figura é a aula em ordem, e cada pergunta tem uma seção só dela adiante. A ordem faz parte do
projeto. Uma API que buscasse o pedido antes de perguntar quem está chamando responderia a um
estranho de um jeito para um pedido que existe e de outro para um que não existe, e essa diferença
já é informação.
