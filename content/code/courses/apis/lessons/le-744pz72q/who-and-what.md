**Authentication answers "who is asking?"; authorisation answers "may they do this?"** They are two
questions, asked in that order, and an API needs both answers before it does anything. Lessons 7 to
10 were the first question: a password, a token, a session, a signed claim. This lesson assumes it
has been answered and asks the second.

The common mistake is to take the first answer for the second. A valid token proves the request
comes from Ana. It says nothing about whether Ana may read order 3, refund order 2 or list every
customer, and an API that stops checking once it knows the caller lets every account do everything
any account can.

HTTP has a code for each failure: **401** when the first question has no answer, **403** when the
second answer is no. The section "401, 403 or 404" says when neither is the right one.

## Where the check lives

Three rules decide where an authorisation check goes, and each one corrects a mistake that is made
often.

**On the server.** A button the interface hides from customers is a convenience, not a check. The
request that button would have sent can be typed with curl, as every request in this course has
been, so whatever the client shows or hides, the server decides again.

**On every request.** A check made once at sign-in and remembered, or made on the page that lists
the orders and not on the address of one order, leaves every other door open. Each request carries
its token and is judged on its own.

**In one place.** A check copied into forty handlers is forty chances to forget one, and the
forgotten one looks exactly like the others until somebody asks it for the wrong thing. In
`orders.py`, three sections on, every request passes through one function, `dispatch`, before any
handler runs. The checks that need the order itself live in one more, `find`, which every handler
that takes an order id calls.

The figure is the lesson in order, and each question has a section of its own below. The order is
part of the design. An API that looked the order up before asking who was calling would answer a
stranger one way for an order that exists and another for one that does not, and that difference
is already information.
