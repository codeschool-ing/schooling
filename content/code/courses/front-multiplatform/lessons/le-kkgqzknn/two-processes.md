---
title: Two processes, and the door between them
version: 1
---

**An Electron app is two kinds of program running at once.** The **main process** is Node.js: it starts
first, it can read and write any file the user can, run programs, open windows and menus, and it never
shows anything itself. Each window is a **renderer process**: a Chromium page, with your HTML, CSS and
JavaScript in it, exactly as in a browser tab, and with no more power than a browser tab has.

The picture most people start with is that Electron is a browser in which the page can use Node. It used
to be configurable that way, and it is the single most important thing to unlearn: **a page that can
`require("fs")` is a page from which any injected script can read and delete the user's files.** Modern
Electron keeps the renderer as powerless as a web page by default, and everything a page needs from the
computer goes through one door you write yourself.

- **The main process** is `electron/main.mjs`. It creates the window, decides what loads in it, and
  answers the requests the page is allowed to make.
- **The preload script**, `electron/preload.cjs`, runs in the renderer before the page does, with a
  small set of Electron's own functions. Its job is to put on `window` the few functions the page may
  call, and nothing else.
- **IPC**, inter-process communication, carries each call from the page to the main process and the
  answer back. `ipcRenderer.invoke` on one side and `ipcMain.handle` on the other turn it into an
  ordinary `Promise`, as Capacitor's bridge did in lesson 2.

**Electron brings its own copy of both Chromium and Node.js** into every app it builds. That is why the
app behaves the same on every computer, whatever browser the person has, and why the smallest Electron
app is bigger than the whole of the planner's web build; lesson 12 measures it against Tauri.
