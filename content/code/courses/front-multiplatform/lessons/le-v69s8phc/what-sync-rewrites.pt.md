---
title: O que o sync reescreve, e o que ele deixa em paz
version: 1
---

**A aula 2 disse que os projetos nativos são seus para editar, e isso vale para quase todo arquivo
deles.** Alguns são do Capacitor, reescritos a cada `cap sync` ou `cap update`, e uma edição num deles
some sem uma palavra. Eles dizem isso nas primeiras linhas:

```
ana@dev:~/planner$ head -n 4 ios/App/CapApp-SPM/Package.swift
// swift-tools-version: 5.9
import PackageDescription

// DO NOT MODIFY THIS FILE - managed by Capacitor CLI commands
ana@dev:~/planner$ head -n 1 android/app/capacitor.build.gradle
// DO NOT EDIT THIS FILE! IT IS GENERATED EACH TIME "capacitor update" IS RUN
```

A regra é fácil de testar. Mude o nome do app no `strings.xml`, que é seu, e acrescente uma linha ao
`capacitor.build.gradle`, que é do Capacitor. Depois sincronize:

```
ana@dev:~/planner$ sed -i 's/>Study planner</>Planner</' android/app/src/main/res/values/strings.xml
ana@dev:~/planner$ sed -i '1a // a line of mine' android/app/capacitor.build.gradle
ana@dev:~/planner$ git status --short
 M android/app/capacitor.build.gradle
 M android/app/src/main/res/values/strings.xml
ana@dev:~/planner$ npx cap sync android
✔ Copying web assets from dist to android/app/src/main/assets/public in 8.14ms
✔ Creating capacitor.config.json in android/app/src/main/assets in 944.33μs
✔ copy android in 17.57ms
✔ Updating Android plugins in 1.12ms
✔ update android in 19.50ms
[info] Sync finished in 0.044s
ana@dev:~/planner$ git status --short
 M android/app/src/main/res/values/strings.xml
ana@dev:~/planner$ grep app_name android/app/src/main/res/values/strings.xml
    <string name="app_name">Planner</string>
```

**Antes do sync os dois arquivos estavam mudados; depois dele, um.** O `capacitor.build.gradle` foi
escrito de novo a partir do que o Capacitor sabe, e a linha sumiu, sem nada na saída que o dissesse. O
nome no `strings.xml` ficou, porque o sync nunca toca nele. Aqui as duas edições foram desfeitas depois
com `git checkout android`.

| escrito pelo sync ou pelo update, toda vez | seu, nunca tocado |
|---|---|
| `android/app/src/main/assets/public/` e os dois JSON ao lado | `AndroidManifest.xml`, `strings.xml`, `styles.xml` |
| `android/app/capacitor.build.gradle`, `android/capacitor.settings.gradle` | `android/app/build.gradle`, `variables.gradle` |
| `android/capacitor-cordova-android-plugins/` | `MainActivity.java` e qualquer Java ou Kotlin que você acrescentar |
| `ios/App/App/public/`, `capacitor.config.json`, `config.xml` | `Info.plist`, `AppDelegate.swift`, `SceneDelegate.swift` |
| `ios/App/CapApp-SPM/Package.swift` | as configurações de build do projeto Xcode, os ícones e a assinatura |

**Uma configuração que você quer num arquivo do Capacitor vai no `capacitor.config.ts`**, onde o
Capacitor a lê e a escreve de novo toda vez. E o git é o que torna a regra segura de aprender: `git
status` depois de um sync mostra qualquer coisa que o Capacitor mudou, e `git diff` mostra o quê.
