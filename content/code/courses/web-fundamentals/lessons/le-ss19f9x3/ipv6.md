IPv6 is the answer to IPv4 running out, and the answer is simply **more bits**: 128 of them instead
of 32.

That sounds like four times as many addresses. It is not. Each bit doubles the count, so 128 bits
is 2⁹⁶ times as many — a number with thirty-nine digits, large enough that the question of running
out does not come back.

## Reading one without panic

An IPv6 address is eight groups of four hexadecimal digits, separated by colons:

`2001:0db8:0000:0000:0000:ff00:0042:8329`

That is unreadable, and two rules shorten it. **Leading zeros in a group are dropped**, and **one
run of all-zero groups is replaced by `::`**. Applying both:

`2001:db8::ff00:42:8329`

The `::` may appear only once in an address, because two of them would be ambiguous — nothing
could say how many zero groups belonged to each.

Hexadecimal is there because 128 bits in decimal would be even longer, and because four hex digits
are exactly sixteen bits, so each group is a clean slice rather than an arbitrary one.

## Three you will recognise

`::1` is loopback — the IPv6 `127.0.0.1`, and the shortening rule at its most extreme.

Anything starting `fe80:` is **link-local**: valid on this wire only, generated by the machine
itself without asking anybody, and never routed. Every IPv6 interface has one, always, and a great
deal of local machinery runs over them.

Anything starting `2` or `3` is generally a **global** address — a real, routable, unique
address. Which is the part worth pausing on.

## No private addresses, and what that changes

In IPv6 there are enough addresses that every device can have a globally unique one. A phone, a
laptop, a lightbulb — each with its own public address, no sharing.

That removes the reason NAT existed, and NAT is what the video at the end of this lesson is about.
It also removes something people had stopped noticing NAT was doing: **accidentally refusing every
connection from outside**. A device with a public address is a device the internet can address
directly, and what stops a connection then is a firewall somebody configured on purpose rather
than a table with no row in it.

That is better engineering and a different security posture, and it surprises people who had been
relying on an accident.

## What else it changed while nobody was looking

IPv6 is usually described as "IPv4 with more bits", and the address is the visible part. Three
other changes are worth knowing because they turn up in practice.

**A machine can address itself.** An IPv6 interface builds its own link-local address without
asking anybody — no server, no negotiation, no failure mode. Two machines plugged together talk
immediately. In IPv4 that case needs the `169.254` fallback you will meet two sections from now,
which exists precisely because the ordinary path failed.

**Routers do not fragment.** The MTU problem from lesson two is handled only at the ends: a router
that cannot pass a packet refuses it and says so, and never cuts it up. That makes the "too big"
message from lesson two load-bearing rather than optional — and makes the black hole failure, where
that message is discarded, correspondingly worse.

**The header is simpler.** Fewer fields, fixed length, no checksum — because the layers below and
above already check, and doing it three times was paying for the same assurance twice.

None of that is why IPv6 exists. All of it is why somebody who has learned IPv4 does not simply
know IPv6.

## Why the change has taken thirty years

IPv6 was finished in 1998. Adoption is somewhere around half of traffic now, which is remarkable
slowness for something with no serious competitor.

The reason is that **the two do not interoperate**. An IPv6-only machine cannot talk to an
IPv4-only server at all; the addresses do not fit in each other's headers and there is no
translation that is merely a matter of rewriting. So nobody can switch — everybody has to run both
for as long as anyone is still on the old one, which is called dual stack, and is where most of
the internet lives today.

Running both means every machine has at least two addresses, every name can resolve to either, and
every diagnosis has to ask which one was used. Which is the practical consequence for you: when
something works for one person and not another, **which protocol each of them got** is a question
worth asking early.

## Where this leaves you

IPv6 is 128 bits written as eight hexadecimal groups, shortened by dropping leading zeros and
collapsing one run of zero groups into `::`. There are enough addresses that nothing needs to be
private, which removes NAT and the accidental protection it provided. It does not interoperate
with IPv4, which is why both are running at once and will be for years.

the one that does not cross anything.
