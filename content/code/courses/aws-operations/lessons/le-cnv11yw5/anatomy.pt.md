O AWS WAF é um firewall para HTTP. Ele fica na frente de um balanceador de carga, de um estágio do API
Gateway, de uma distribuição do CloudFront ou de algumas outras portas de entrada, e lê cada requisição
antes da aplicação: o endereço, o caminho, os cabeçalhos, o corpo. É o que os alarmes de erros 5xx da
lição 10 não conseguem ser, um jeito de recusar uma requisição em vez de notar o estrago que ela fez.

O que o WAF executa é um **web ACL**, uma lista de regras em ordem de prioridade, e cada regra é uma
instrução (*statement*) com que uma requisição casa ou não, com uma ação para as que casam:

| ação | o que acontece com uma requisição que casa |
|---|---|
| `Block` | recusada, por padrão com um 403; nenhuma regra seguinte olha para ela |
| `Allow` | passa para a aplicação; nenhuma regra seguinte olha para ela |
| `Count` | contada, e rotulada se a regra adiciona rótulos; a avaliação **continua** na próxima regra |
| `CAPTCHA`, `Challenge` | o navegador precisa resolver um quebra-cabeça, ou rodar uma verificação silenciosa, antes de passar |

`Block` e `Allow` **terminam** a avaliação: a primeira regra que bloqueia ou permite uma requisição
decide, e as regras abaixo dela nunca a veem. `Count` não termina, e é isso que a torna o jeito seguro
de experimentar uma regra. Uma requisição que não casa com nenhuma regra terminal recebe a **ação
padrão** do web ACL, `Allow` para um site que o público usa.

## A ordem é o desenho

Como o primeiro casamento terminal vence, **prioridade é política**. O web ACL da loja, montado na
próxima seção, tem três regras, do número menor para o maior:

1. `blocked-addresses`: endereços que a equipe decidiu recusar, de um **conjunto de IPs**, conferidos
   primeiro porque é barato e certo;
2. `login-rate`: uma **regra por taxa** que bloqueia um endereço que manda requisições demais para
   `/login`;
3. `aws-common`: um **grupo de regras gerenciado** que a AWS escreve e mantém atualizado, com dezenas de
   regras próprias contra os ataques comuns a aplicações web.

Uma regra `Allow` posta acima delas, para os endereços do escritório por exemplo, deixaria essas
requisições passarem por tudo, regras gerenciadas inclusive. Às vezes é o que a equipe quer, e muitas
vezes é um erro que ninguém nota, porque uma requisição permitida não deixa rastro das regras que pulou.

## Capacidade

Cada regra custa **unidades de capacidade de web ACL**, WCU, conforme o trabalho que dá: cerca de 1 para
um conjunto de IPs, poucas para um casamento simples, mais para cada transformação de texto e cada
expressão regular, 700 para o conjunto comum de regras da AWS. Um web ACL comporta até 5.000 WCU, e
**as primeiras 1.500 estão incluídas no preço por requisição**; além delas cada requisição custa mais, o
que a seção sobre custo lê na lista de preços. A capacidade é contada quando o web ACL é salvo, então uma
regra que não cabe é recusada nessa hora, e não às três da manhã.
