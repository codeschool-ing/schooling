AWS WAF is a firewall for HTTP. It sits in front of a load balancer, an API Gateway stage, a CloudFront
distribution or a few other front doors, and reads each request before the application does: its
address, its path, its headers, its body. It is what lesson 10's alarms on 5xx errors cannot be, a way
to refuse a request rather than to notice the damage it did.

What WAF runs is a **web ACL**, a list of rules in priority order, and each rule is a statement
that a request matches or not, with an action for the requests that match:

| action | what happens to a matching request |
|---|---|
| `Block` | refused, by default with a 403; no later rule looks at it |
| `Allow` | let through to the application; no later rule looks at it |
| `Count` | counted, and labelled if the rule adds labels; evaluation **continues** with the next rule |
| `CAPTCHA`, `Challenge` | the browser must solve a puzzle, or run a silent check, before it is let through |

`Block` and `Allow` **terminate**: the first rule that blocks or allows a request decides it, and the
rules below it never see it. `Count` does not, which is what makes it the safe way to try a rule out.
A request that matches no terminating rule gets the web ACL's **default action**, `Allow` for a site the
public uses.

## Order is the design

Because the first terminating match wins, **priority is policy**. The shop's web ACL, built in the next
section, has three rules, lowest number first:

1. `blocked-addresses`: addresses the team has decided to refuse, from an **IP set**, checked first
   because it is cheap and certain;
2. `login-rate`: a **rate-based rule** that blocks an address sending too many requests to `/login`;
3. `aws-common`: a **managed rule group** that AWS writes and keeps up to date, with dozens of rules of
   its own against the common attacks on web applications.

An `Allow` rule placed above them, for the office's addresses say, would let those requests past
everything, managed rules included. That is sometimes what a team wants and often a mistake nobody
notices, because an allowed request leaves no trace of the rules it skipped.

## Capacity

Each rule costs **web ACL capacity units**, WCU, by how much work it is: about 1 for an IP set, a few for
a simple match, more for every text transformation and every regular expression, 700 for AWS's common
rule set. A web ACL holds up to 5,000 WCU, and **the first 1,500 are included in the request price**;
past them each request costs more, which the section on cost reads from the price list. Capacity is
counted when the web ACL is saved, so a rule that does not fit is refused then, not at three in the
morning.
