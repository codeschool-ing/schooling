---
title: What to hand in
version: 1
---

The reviewer of a take-home has perhaps ten minutes per submission. Hand in something that **works in those
ten minutes**:

- It runs from the instructions. A README that says how to run it on a clean machine, tested the way
  lesson 16 of the portfolio course tested one: by following it somewhere you had not set up.
- **It does what the brief asked**, first and completely, before anything extra. An extra feature on top of
  a missing requirement reads as not having read the brief.
- **It has a short note** with three things: **what you did**, **what you chose and why** (one or two
  decisions, each with its cost), and **what you would do with more time**. The last line is where the
  missing pieces go.
- **It has a test for the rule that matters**, if the brief has one. One test that fails when the rule is
  removed says more than coverage.

For support and infrastructure take-homes (*document how you would set up this office*, *fix this broken
virtual machine*), the same applies with a runbook in place of the README: **the steps, in order, that
somebody else could follow**, and what you checked at the end.

Send it as the brief asks (a repository link, a zip, a document), with the name the brief uses, and before
the deadline. A late, perfect submission is usually worse than an on-time, incomplete one.
