---
title: The result, not the stack
version: 1
---

A line that lists technologies answers a question nobody asked. The reader of a CV wants to know **what you
can do for them**, and a list of tools cannot say it, because the same list describes a project that works
and one that never ran.

Compare two lines about the same project:

> *Developed a web application using Python, SQLite, Podman and Caddy.*

> *Built and deployed a loan register for a school IT room, in which the database refuses a second loan of
> the same item; the rule has a test that fails when it is removed.*

The first could be anybody's. The second says **whose problem it was, what now happens that did not, and
how to check**, and it still mentions the database, because the database is where the rule lives.

The technology is not hidden: it goes in the skills section, and in one small line under the project if
you like. What changes is **which sentence the reader meets first**. A recruiter searching for *SQL* will
find it either way; a team lead reading the line will only be persuaded by the second.
