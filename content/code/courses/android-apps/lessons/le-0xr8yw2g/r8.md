title: R8: what the release build removes
version: 1
---

**R8 reads the whole app, libraries included, and keeps only what can be reached from the code that
runs.** It then shortens the names of what is left and optimises it. Lesson 1 section 08 found
27.82 MB of dex in a debug APK that showed one sentence, and `android analyze` complained about it.
Here are the same app's debug and release builds of the `play` flavour side by side:

```
ana@vm:~/planner$ ls -l app/build/outputs/apk/play/debug/app-play-debug.apk app/build/outputs/apk/play/release/app-play-release.apk
-rw-r--r-- 1 ana ana 11663286 Oct 30 17:41 app/build/outputs/apk/play/debug/app-play-debug.apk
-rw-r--r-- 1 ana ana   757882 Oct 30 17:42 app/build/outputs/apk/play/release/app-play-release.apk
ana@vm:~/planner$ android analyze app/build/outputs/apk/play/release/app-play-release.apk 2>&1 | sed -e "s/.*\r//" | grep -E "Dex|R8"
 - Uncompressed Dex Size: 1130676 bytes (1.08 MB)
 - Dex Marker Metadata: R8 Enabled=true, D8 Enabled=false, Full Mode=true
 - Dex Heuristic Obfuscation: 97.89%
ana@vm:~/planner$ wc -l app/build/outputs/mapping/playRelease/mapping.txt
116141 app/build/outputs/mapping/playRelease/mapping.txt
ana@vm:~/planner$ grep -E "^(com.example.planner.MainActivity|androidx.activity.ComponentActivity|androidx.compose.ui.platform.AndroidComposeView) " app/build/outputs/mapping/playRelease/mapping.txt
androidx.activity.ComponentActivity -> k9:
androidx.compose.ui.platform.AndroidComposeView -> h2:
com.example.planner.MainActivity -> com.example.planner.MainActivity:
```

**From 11.7 MB to 0.76 MB**, and from 27.82 MB of dex in lesson 1 to 1.08 MB here. Almost all of the
difference is library code the planner never calls: R8 follows every call from the app's entry
points, the activity in the manifest and what it composes, and drops every class and method it never
reaches. `isShrinkResources` then drops the resources nothing refers to any more. `R8 Enabled=true`
and `Full Mode=true` are what the analysis reports for a release build of AGP 9.5.

## The names it changes, and the file that undoes it

R8 also renames, and the last command above shows both outcomes. `ComponentActivity`, the AndroidX
class the planner's activity extends, is now `k9`, and the view Compose draws into is `h2`. A crash
report from a release build therefore names classes like `h2`, which nobody can read. **`MainActivity`
kept its name**, because the manifest names it as a string and R8 keeps whatever the manifest
refers to. **`mapping.txt` is the dictionary back**, written for every release build: 116,141 lines
here, each class on a line of its own with its fields and methods indented below it. Keep it with
each release, because a stack trace can only be translated with the mapping of the exact build that produced it. Google Play deobfuscates crash reports automatically
when the mapping is uploaded with the bundle; the `retrace` tool in the command-line tools does the
same on your computer.

## When R8 removes too much

R8 can only follow calls it can see in the code. Anything reached by **reflection**, by a class name
in a string, is invisible to it, and gets removed or renamed. The usual cases are JSON adapters that
find fields by name, which lesson 14 meets, and classes named in XML. Libraries that rely on
reflection ship their own rules in their AAR, which the plugin applies; for your own classes,
`proguard-rules.pro` takes a `-keep` line:

```properties
# A model read by reflection, if the planner ever had one
-keep class com.example.planner.data.** { *; }
```

**Not run**: the planner reaches nothing by reflection, so this rule is an example and is not in the
file section 02 built. The symptom of a missing rule is an app that works in `debug` and crashes in
`release`, which is the argument for testing the release build before it ships, not only the debug
one.
