**Um token é um valor com nome que representa uma decisão de design.** `#2f6f4e` é uma cor;
`color-green-600` é um token para ela; `accent` é um token para *aquilo para que essa cor é usada*. A
diferença entre os dois últimos é a ideia inteira, e é por isso que tokens vêm em camadas.

| camada | exemplo | diz |
|---|---|---|
| primitivo | `color-green-600: #2f6f4e` | aqui está uma cor que a marca tem |
| semântico | `accent: {color.green-600}` | esta é a cor das coisas em que se pode agir |
| componente | `button-background: {accent}` | o fundo de um botão é a cor de ação |

**O código se refere a tokens semânticos, nunca a primitivos.** Uma folha de estilo que diz
`color: var(--accent)` sobrevive a trocarem o verde da marca, a um tema escuro que precisa de um verde mais
claro para continuar legível, e a um produto parceiro que quer o próprio destaque. Uma que diz
`var(--color-green-600)` não sobrevive a nada disso, porque prendeu um significado a uma tinta em
particular.

## Primitivos são uma paleta, não um cardápio

Os primitivos são todo valor que o sistema permite, e nada mais: uma dúzia de cinzas, alguns verdes, uma
escala de tamanhos. Ninguém escolhe entre eles enquanto constrói uma tela. A camada semântica escolhe uma
vez, por tema, e uma tela escolhe na camada semântica. Quando alguém precisa de uma cor que a camada
semântica não tem, isso é uma conversa sobre o sistema, e não um código hex numa folha de estilo.

**Tokens de componente são opcionais**, e o planner vive sem eles. Eles se justificam quando um componente
precisa se afastar do significado que herdaria, e muitos sistemas nunca escrevem um. Uma terceira camada
de que ninguém precisa é uma camada que alguém tem de manter em dia à toa.

## O que um token não é

Um token não é uma variável CSS, embora os do planner virem variáveis CSS. Ele é uma decisão guardada como
dado, e o CSS é um dos lugares para onde ela é escrita. O mesmo arquivo pode gerar um arquivo de recursos
do Android, um catálogo de assets do iOS, ou as variáveis de uma ferramenta de design, e é assim que uma
designer e um desenvolvedor acabam usando o mesmo `accent` em vez de dois hex que se afastaram. A próxima
seção escreve os do planner como dado.
