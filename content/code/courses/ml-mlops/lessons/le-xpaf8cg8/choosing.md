The three kinds differ in **what they are given**, and that is how a question is sorted into one
of them. Asking "which algorithm?" first is the common mistake; the data you have, or can collect,
decides before any algorithm is chosen.

| the question at Ponto Final | what there is to learn from | the kind |
| --- | --- | --- |
| which members are about to stop coming? | members as they stood last year, and whether each came back | supervised: classification |
| how much will this member spend next month? | last year's members, and what each spent the month after | supervised: regression |
| what kinds of reader does the shop have? | members' purchases, and no label for "kind of reader" | unsupervised: clustering |
| which of three vouchers brings people back? | nothing yet; only what happens once vouchers are sent | reinforcement: a bandit |
| how many members bought crime novels last month? | the purchases table | **none: a query** |

**The last row is in the table on purpose.** A question whose answer is already in the data is a
query, and a model there is an expensive way to be slightly wrong. The same goes for a rule
everybody agrees on and nobody needs to tune, such as "a member who asks to leave the programme
has left". A model earns its place when the answer is not in the data yet (the future, the
member's taste) and a rule written by hand gets it wrong too often to be worth its simplicity.

## Two questions to ask before anybody trains anything

**Is there a label, and when does it arrive?** For lapsing it arrives 90 days after the day a
prediction is made, and lesson 3 shows that this delay decides how the data can be split. For a
fraud model it can arrive months later, when the chargeback does. For a recommendation it may never
arrive at all: nobody tells the shop which book a member would have liked and did not see.

**What will be done with the answer?** A probability of lapsing is worth computing only if somebody
will send a voucher because of it. If marketing can send a hundred vouchers a month, the model has
to rank the top hundred well and nothing else matters, and lesson 4 shows how that changes which
score you look at.

The modeller usually asks these. The data engineer is the person who can answer them, because the
answer is in where the data comes from and when it lands.
